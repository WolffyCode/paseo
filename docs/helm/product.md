## 0. 产品定位

Helm 是移动端、Web 与桌面端的 AI 编码代理控制台：连接本机或远程主机上的代理运行环境，让用户从一个界面监控、进入和控制工作。代码留在用户自己的机器上。

## 1. 全局信息架构（IA）

- 首次启动：一次性 onboarding，负责把用户连接到一个可用 host。
- 连接后：进入 host 主页与 workspace/agent 工作界面。
- 主页左侧：对话树按项目 → 根对话 → subagent 组织工作入口，并保留置顶与游离对话分组。
- 主页中区：承载左侧当前选中根对话的真实消息历史、运行态和输入区，或保持在主页内的新对话草稿。
- 主页右栏：以可关闭、可排序页签并行承载文件和对话；subagent 对话只读，根对话与新对话可输入。
- 对话视图周期：每条根对话或草稿独立记忆文件目录树、右侧工作区和页签现场；首次进入时两侧默认收起。
- 诊断与配置：通过 settings 进入；首次启动流程只在本地连接失败时暴露诊断入口。

## 2. 入口与导航

- `/welcome` 是首次启动 onboarding 路由。路由名保留为 welcome，但承载完整 onboarding 状态机。
- `/` 负责启动落点：**已看过欢迎且有可用 host 时进入主页；全新用户先进 onboarding 欢迎页（看过欢迎前不自动连接）；没有可落地 host 且需要连接时进入 onboarding**。
- `/pair-scan?source=onboarding` 是 onboarding 扫码连接入口。
- `/settings` 是本地 daemon 连接失败后的诊断入口。

### 首次启动 onboarding（连主机）

- 作用：让首次打开 Helm 的用户先看一次品牌欢迎，然后尽快连上本机 daemon（桌面与本机浏览器同样自动连），并保留连接远程主机的能力。
- 入口：全新安装/清空本地状态后启动；无 host 的启动路径；用户在欢迎页选择“连接远程主机”；本地连接失败后选择其它连接方式。
- 流程（延后连接 Q）：**看过欢迎前不发起任何连接**。首启显示欢迎页 →“开始使用”才触发连接本机 daemon（连接中显示当前主机标识+状态）→ 成功进主页；本机连不上：桌面进错误态、Web/手机落连接方式选择器。“连接远程主机”进连接方式选择器；错误态可重试 / 改用其它方式 / 查看诊断。**后续启动不再显示欢迎页，静默重试本机一次：连上进主页，仍连不上落选择器/错误态（重开自愈）。**
- 边界：不配置 provider、relay 协议或模型；直连、粘贴配对链接、扫码复用既有能力；**“自动连本机”对桌面与本机浏览器一视同仁（桌面经内建 daemon、浏览器经 localhost daemon）；只有真无本地可连 daemon（远程浏览器/未装未起/手机）才落选择器**，Web 选择器不显示扫码，手机扫码优先。
- UI：`ui.html#s1`、`ui.html#s2`、`ui.html#s3`、`ui.html#s4`、`ui.html#s5`

### 左侧对话树

- 作用：在主页左栏按项目和父子关系组织对话，让用户快速扫描工作状态并进入根对话或 subagent。
- 入口：连接 host 后进入主页，左栏常驻展示；顶部保留主机切换、新对话和搜索入口。
- 流程：项目展开根对话，根对话继续展开 subagent；点项目切换展开态，点根对话进入中区并选中，点 subagent 打开右栏对应对话并选中。项目、根对话与 subagent 均使用 36px 单行结构：项目行显示文件夹图标 + 标题，根对话和 subagent 都只显示标题，不显示图标、状态点或后代数量；分组标题与空提示同为 36px。三类行均有 hover 背景和右侧信息卡：项目卡显示标题、文件路径、Git 分支与 Git diff；根对话和 subagent 卡均显示各自的对话名称、操作目录、最后一次使用时间与提供方。subagent 没有独立工作区时，卡片的操作目录仅为展示而继承父级目录上下文；管理操作仍以 subagent 自己的实际工作区归属为准。所有树行均无行尾操作按钮；项目、根对话和 subagent 的管理操作统一从右键菜单进入，项目菜单含作用域内“新对话”。
- 边界：桌面左栏范围；层级递归不设产品上限，视觉缩进到第 8 层后停止增加；已归档对话不显示，closed 对话保留；移动紧凑态延后。
- UI：`ui.html#conversation-tree`

### 中区真实对话与新对话草稿

- 作用：让用户从左侧根对话直接进入真实历史、运行输出和输入区，也能在不离开主页工作壳的情况下开始新对话。
- 入口：连接 host 后首次进入主页即默认打开中区“新对话”；也可点击左侧任一根对话、左栏顶部“新对话”或项目右键菜单“新对话”切换目标。
- 流程：host 数据加载完成后，如果中区还没有用户选中的根对话或已打开的草稿，则自动进入未绑定项目的内嵌草稿；点击根对话 → 中区按 agent 身份加载真实消息流与 Composer；点击全局“新对话” → URL 与三栏布局保持不变，中区切换为未绑定草稿，Composer 顶部上下文条显示工作目录；点击项目菜单“新对话”则预选该项目。用户选择 host 真实目录后草稿绑定对应 workspace；发送第一条消息后，乐观消息与真实回复从 Composer 上方出现，创建成功后原位切换为真实 agent 并同步左树选中，不移动 Composer 的视觉锚点。切换根对话时整体切换内容；点击消息文件链接 → 右侧工作面板打开对应文件。点击 subagent 不替换中区当前根对话。
- 边界：复用既有 draft 创建流、消息流、timeline、Composer、归档与错误态，不新增协议、RPC、provider 或模型机制；预览假数据不能生成伪造消息；全局新对话不继承当前或默认 workspace，项目菜单新对话预选该项目 workspace；未选目录时草稿可编辑但不能启动 agent，取消或选择失败不清空输入；不回退到旧 `/new` 路由，不猜测目录，也不创建伪 workspace。
- UI：`ui.html#conversation-content`

### 右侧对话页签

- 作用：在不替换中区当前根对话的情况下，并行查看 subagent、继续其它根对话或从右栏开始新对话。
- 入口：点击左树 subagent；把左树根对话拖入中区；右侧 Workbench 空态“对话”入口；右侧页签栏“+”→“对话”。
- 流程：点击 subagent → 右栏自动展开并打开该 agent 的只读对话页签；拖入根对话 → 右栏自动展开并打开可编辑页签；当前中区已有真实 workspace 时，从右栏新建会沿用该 workspace 并直接打开右侧 draft Composer → 首次发送创建真实 agent → 页签原位接管并由 daemon 推送把对话归入左树对应项目。重复打开同一真实 agent 聚焦已有页签；不同 draft 可并列；页签可聚焦、关闭和拖动排序。
- 边界：subagent 页签不显示可输入 Composer，也不接受文件拖入；根对话页签不改变中区选择；工作目录缺失、host 离线时不能创建；不新增协议、RPC、provider 或模型机制。桌面 Web/Electron 支持根对话拖拽，原生端保留点击与新建入口。
- UI：`ui.html#right-conversation-tabs`

### 对话视图状态记忆

- 作用：切换中区对话时隔离并恢复各自的右侧工具现场，避免上一条对话的目录树和页签串入下一条。
- 入口：点击左树根对话、左栏或项目菜单“新对话”；草稿首次发送后由真实 agent 原位接管。
- 流程：离开当前对话时保存文件目录树、右侧工作区和最大化状态以及 Workbench 页签现场 → 首次进入目标对话时两侧默认收起且 Workbench 为空 → 返回已访问对话时恢复开关、页签集合、顺序与焦点。草稿创建成真实对话时迁移同一份现场，不重置。
- 边界：左侧全局对话树和工具宽度规则不按对话复制；视图记忆只保证当前客户端会话内切换，页面重载恢复延后；不修改消息、文件、协议、RPC、provider 或模型机制。
- UI：`ui.html#conversation-view-memory`

### 对话 Composer 与运行配置（已实现，待 Gate 3 验收）

- 作用：把新对话和进行中对话统一成一套稳定输入表面，让工作目录、提供方、中转站、模型、推理强度、运行模式、当前上下文和账号额度具有清晰且固定的位置。
- 入口：中区新对话草稿；任一可编辑根对话；右栏可编辑对话页签沿用同一 Composer 结构。
- 流程：新对话先选择工作目录与运行配置 → 在同一 Composer 输入并发送 → agent 创建后 Composer 保持原位，工作目录和提供方锁定 → 中转站、模型、推理强度、运行模式与 provider feature 可为下一条消息改选。底栏左侧只保留统一“+”入口，右侧以三个同规格且间隔 6px 的标签承载模型、强度和模式，再放上下文与发送；附件、`@`、语音和低频配置收进“+”。模型入口在触发器上方打开有最大高度且内部滚动的单列锚定下拉，提供方与中转站位于下拉顶部；运行时继续发送进入队列，每条待发消息右侧可删除或强制发送，发送按钮保持独立停止动作。真实对话底栏显示当前 context window 占用，hover/点击后同时显示当前官方/中转站运行路由返回的 5h、7 天或其它账号额度窗口。
- 边界：中转站是挂在提供方下的 API 供应商配置，不是 host Relay；Plan、Build、Default Permissions、Full Access 等是提供方运行模式，不是模型或客户端自造的三级文件权限；推理强度保留 provider/model 返回的英文标签；所有模型、模式、provider feature、额度窗口和工具均由 host 能力驱动，不硬编码、不伪造禁用项；中转站密钥与模型暴露列表仍在设置中管理。底栏点击槽位统一 32px 高、6px 圆角和 16px 图标，只有发送/停止使用实色；780px 桌面和 320px 紧凑宽度均不横向滚动或裁切，紧凑态只常驻“+”、模型、上下文和发送，其余能力从“+”完整可达。本机 Electron 使用系统目录选择器，其它环境使用 host 目录面板；本需求不修改协议。
- UI：`ui.html#conversation-composer`

## 4. 核心流程

### 首次连接 host

1. 首装首跑显示一次欢迎页，包含 Helm 标识、slogan、开始使用、连接远程主机和版本号。**看过欢迎前不发起任何连接。**
2. 点“开始使用”后进入连接中过场，**这时才**检测并连接本机 daemon——**桌面（内建 daemon）与本机浏览器（localhost daemon）一致**；过场显示当前主机标识+状态（不显端口）。
3. 本机连接成功后由启动路由进入主页，不停留在欢迎或过场，全程不手输 host。
4. 本机连接失败：**桌面**显示错误态（重试 / 改用其它连接方式 / 查看诊断）；**Web/手机**落连接方式选择器兜底（含“重试本地”，显示当前主机失败上下文）。
5. 用户选择远程连接（欢迎页“连接远程主机”或失败后“改用其它连接方式”）进入连接方式选择器，使用直连 host、粘贴配对链接或扫码完成连接。

### 后续启动与重开自愈

1. 已看过欢迎后，启动不再显示欢迎页。
2. 启动静默重试本机一次：daemon 已起 → 直接进主页；仍连不上 → 落连接方式选择器（桌面落错误态），显示当前主机标识+状态。
3. “连接远程”是会话级意图，不跨重启记忆——重开仍先静默重试本机。

### 从左侧对话树进入工作

1. 进入主页后，从置顶、项目或游离对话分组定位目标。
2. 展开项目查看根对话；展开根对话或 subagent 查看更深层级。
3. 点击根对话时中区切换到该对话；点击 subagent 时右栏打开或聚焦对应对话。
4. 项目展开后没有对话时显示缩进的“暂无对话”，不留下无法判断的空白。
5. hover 三类行查看指针反馈与各自的补充信息卡。右键目标行执行新建、置顶、重命名、复制或移除等可用操作。

### 在中区继续根对话

1. 点击左树根对话，中区根据该 agent 的 workspace 加载真实 timeline。
2. 消息流、工具调用、附件、subagent 轨道与 Composer 使用既有对话能力。
3. 切换根对话时按 agent 身份重建内容边界，不显示上一条对话的残留内容。
4. 从消息点击文件链接时，以当前 workspace 解析相对路径并在右侧工作面板打开。
5. 显式选择的目标后来丢失、加载失败、离线或已归档时均显示对应状态，并保留选择其它根对话或重连的出口；首次进入不走该恢复空态。
6. 首次进入一条根对话时文件目录树与右侧工作区默认收起；切走再返回时恢复该根对话离开前的两侧状态和右侧页签现场。

### 在中区开始新对话

1. 首次进入主页或点击左栏顶部“新对话”时，中区进入未绑定项目的草稿；从项目右键菜单进入时预选该项目 workspace。
2. 草稿首帧即使用真实 Composer 的底部锚点，Composer 顶部上下文条固定显示工作目录；画布上方保持可承载消息的空白，不显示旧新建页。
3. 用户可通过本机系统目录选择器或 host 目录面板选择真实目录；成功后绑定返回的 workspace。取消和失败保留草稿及输入。
4. 未选目录时输入可编辑，但发送不启动 agent 并提示先选择工作目录；选择目录后发送第一条消息，乐观用户消息从 Composer 上方出现。
5. daemon 返回真实 agent 后，中区原位切换到该 agent，左树在所选目录对应项目下新增并选中根对话；后续回复继续向上方消息区生长。
6. 离线时目录选择和发送禁用；用户可等待重连、切换根对话或重新新建草稿退出。
7. 每个新草稿都是新的视图周期，两侧默认收起；创建成功后的真实 agent 沿用草稿现场。

### 在右侧并行处理对话

1. 点击任一 subagent，右栏展开并打开只读对话页签；历史、运行输出和文件链接可用，输入区替换为只读提示。
2. 在桌面把任一有工作区的根对话拖入中区，drop 高亮确认可放置；释放后中区保持不变，右栏打开该根对话的可编辑页签。
3. 当前中区已有真实 workspace 时，点击右栏空态“对话”或页签栏“+”→“对话”，沿用当前 workspace 直接打开右侧 draft；中区未选目录时该入口禁用。
4. 首次发送沿用真实创建流；成功后 draft 页签原位变为 agent 页签，左树在 daemon 更新到达后把它放入当前 workspace 对应项目；失败时保留 draft 和重试入口。
5. 再次打开已存在的 agent 时聚焦原页签；关闭当前页签后聚焦相邻页签，关闭全部后回到 Workbench 空态。

## 5. 全局状态与规则

- “已看过欢迎”是本地一次性持久状态；看过后后续启动不再展示欢迎页。
- **看过欢迎前不发起任何主机连接（延后连接 Q）**：连接由“开始使用”触发，或在已看过欢迎的后续启动时静默发起（重试本机一次）。
- **“自动连本机 daemon”对桌面与本机浏览器一视同仁**：桌面经 Electron 内建 daemon 的 directPipe/socket，浏览器经 localhost daemon 的 WebSocket；区别只在 transport 与连不上时的兜底（桌面→错误态、浏览器/手机→连接方式选择器）。只有真无本地可连 daemon 才落选择器。
- 连接中 / 错误态 / 选择器**通过各屏主文案**体现当前主机标识（本机 daemon / 远程主机名）+ 状态，不显具体端口；不另设与主文案重复的状态元素。
- 新 host 连上后的主页落点由启动路由统一决定，onboarding 只渲染阶段并派发动作；onboarding 屏自身不做“跳主页”。
- 对话树所有项目、根对话、subagent、分组标题与空提示统一为 36px 单行节奏；层级通过缩进、chevron 和行背景表达，不用额外分隔线。项目保留文件夹图标，根对话与 subagent 均不加图标、状态点或数量；根对话的审核中、报错、进行中等状态判断与视觉另行设计，本轮不在行内展示。hover 与点击选中使用可区分的行背景；任何项目或对话行都不显示尾部三点、快捷新建或其它行尾按钮，操作统一进入右键菜单。
- 中区目标由左树根对话身份或内嵌新对话草稿驱动，左栏折叠不清空；subagent 激活与根对话中区 focus 相互独立。首次加载成功且没有任何显式中区目标时自动进入未绑定项目的草稿；该初始化不覆盖用户已选中的根对话、手动草稿或创建后的 pending agent。进入全局草稿会清除旧根对话选中且不继承其 workspace，创建成功后选中新根对话；切换 host 时按新 host 重建并进入该 host 的未绑定草稿。
- 中区必须展示 daemon 的真实 agent/timeline；树预览 fixture 只影响左栏，不写入 session store 或生成消息。
- 右侧对话页签以 agentId/draftId 为身份：真实 agent 去重聚焦，draft 独立；每个页签携带自己的 workspace，不要求中区切换到同一目录。同一 workspace 可包含多条根对话，左树标题优先使用各 agent 自己的标题，不能由共享 workspace 标题互相覆盖。
- 中区根对话与草稿各自拥有客户端会话内的视图周期。切换前保存当前文件目录树、右侧工作区、最大化与 Workbench 页签现场；首次目标安装两侧关闭的默认态，已访问目标恢复；draft→agent 迁移不创建新周期。同一 workspace 下的不同根对话也不能共享这份视图状态。
- 左栏全局“新对话”创建未绑定项目的中区草稿；项目菜单“新对话”预选目标项目。右栏新对话暂沿用当前中区 workspace，右栏目录改选不在本轮范围。
- Composer 是单一连续输入表面：顶部上下文条放工作目录，正文承载输入与附件；底栏左侧只有统一“+”，右侧用三个同规格、间隔 6px 的文字标签承载模型、推理强度和运行模式，再放上下文与发送。点击槽位统一 32px 高、6px 圆角和 16px 图标，只有发送/停止使用实色；文字标签和方形图标按钮各自成组，不混用圆形、胶囊或无间距分段条。新对话中工作目录、提供方、中转站、模型、强度与模式可选；真实会话建立后工作目录与提供方锁定，中转站、模型、强度、模式和 provider feature 按下一条消息生效。待发消息行右侧提供同高的删除与强制发送。模型下拉不使用居中弹框且列表内部滚动；能力不存在时对应控件不显示。780px 桌面底栏不换行；320px 紧凑态只常驻“+”、模型、上下文和发送，附件、`@`、语音、强度、模式与低频 feature 收进“+”菜单，功能不丢失。
- subagent 从左树进入右栏时强制只读，即使 provider 快照没有 `observed` 标记也不能出现 Composer；根对话拖入和右栏新建保持可编辑。
- 已实现的主页与 Composer 需求不修改协议、RPC 或 `server_info.features.*`；Composer 复用既有 capability、usage、workspace 与 agent 创建接口。

## 6. 术语表

- Host：Helm 连接的本机或远程 daemon 环境。
- Daemon：本机或远程运行的 Paseo/Helm 后端进程。
- Onboarding：首次启动连接 host 的一次性引导流程。
- 连接方式选择器：直连主机、粘贴配对链接、扫码连接的选择界面。
- 项目：按代码仓库聚合根对话的一级目录节点。
- 根对话：没有父对话的 agent 会话，点击后由中区承载。
- Subagent：挂在根对话或其它 subagent 下的子会话，点击后由右栏承载。
- 中区对话：主页中央承载当前根对话真实消息流，或新对话草稿及其固定 Composer 的工作区域。
- 右侧对话页签：Workbench 中独立承载 agent 或 draft 的并行对话表面，每个页签自带工作目录上下文。
- 中转站：挂在提供方下、由 `base_url + key + API 格式` 定义的 API 供应商；与连接主机使用的 Relay 是两个概念。
