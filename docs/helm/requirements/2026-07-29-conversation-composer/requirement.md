# 需求 · 对话 Composer 与运行配置

> 日期：2026-07-29 · 状态：已实现，待 Gate 3 验收 · 配套 UI：[ui.html](./ui.html)

## 1. 目标

把新对话与对话进行中的输入区统一成一套稳定、克制的 Composer。用户能在同一位置明确工作目录、提供方、中转站、模型、推理强度和运行模式，并能查看当前对话上下文与账号额度，不再把目录选择器、模型选择器和输入框画成彼此割裂的控件。

## 2. 核心对象

- **提供方**：运行编码代理的客户端，例如 Codex、Claude Code、Copilot、OpenCode、Pi。决定会话运行时与能力边界。
- **中转站**：挂在提供方下的 API 供应商配置，由 `base_url + key + API 格式` 组成。中转站不是主机连接使用的 Relay。
- **模型**：由当前提供方与中转站共同暴露的可用模型。
- **推理强度**：当前模型实际支持的 thinking/reasoning 档位；选项由能力数据驱动。
- **运行模式**：当前提供方实际返回的 agent mode，例如 OpenCode 的 `Build / Plan`、Codex 的 `Default Permissions / Auto-review / Full Access`。模式同时表达规划/执行方式与真实权限边界，不伪造成通用的三级“文件权限”。
- **提供方能力**：不属于 model 或 mode 的独立开关/选项，例如 Codex 的 Plan mode feature；仅在当前提供方真实返回时出现。
- **上下文用量**：当前对话的 `used tokens / context window max tokens`，与账号套餐额度是两类数据。
- **账号额度**：当前官方或中转站运行路由返回的通用 usage windows / balances；可包含 5h、7 天等窗口，但不在客户端硬编码固定周期。

## 3. 新对话

1. Composer 固定在中区底部，整体是一块连续输入表面，不再把工作目录画成外置的第二个大输入框。
2. 顶部上下文条显示工作目录。未选择时是“选择工作目录”，选择后显示项目名与缩略路径。
3. 主输入区承载文本、`/` 命令、`@` 文件引用和附件。
4. 底栏只保留少量稳定槽位：左侧一个统一“+”入口，右侧为运行配置标签组、上下文用量和发送。附件、`@` 文件引用、语音及其它低频动作进入“+”菜单，不再各占一个形状不同的按钮。
5. 模型、推理强度和运行模式各自使用独立的 32px 高、6px 圆角轻量标签，三者保持同一描边、背景、文字基线和 hover 规则，标签之间固定留 6px 间隔；不再混用圆形、胶囊、图标底板或无间距分段条。
6. 模型入口打开贴着触发器向上的锚定下拉，不使用居中弹框。下拉顶部承载提供方与中转站选择，主体为有最大高度、可内部滚动和搜索的单列模型列表。
7. 首条消息发送前，工作目录、提供方、中转站、模型、推理强度与运行模式均可调整。
8. 缺少工作目录、可用提供方或模型时不启动 agent；对应入口显示错误或配置出口，输入内容不丢失。

## 4. 对话进行中

1. 消息从 Composer 上方生长，Composer 的宽度、底部位置和控件槽位不移动。
2. 工作目录和提供方在创建成功后锁定，避免会话身份与运行目录分叉；模型下拉中提供方以带锁摘要展示，不能更改。
3. 中转站、模型、推理强度、运行模式与提供方能力允许改选；空闲时立即保存为下一条消息配置，运行中改选则排队到下一回合。
4. 配置发生改选时，底栏只显示新的摘要状态，不向消息流插入伪消息；失败时恢复上一组有效配置并显示轻量错误。
5. agent 运行时发送按钮变为停止按钮；用户继续输入并发送时进入待发队列，停止与队列互不覆盖。
6. 每条待发消息右侧固定提供“删除”和“强制发送”。删除只移除该条；强制发送使用现有 send-now 语义立即提交该条，不要求先停止当前回合。
7. 真实对话底栏显示当前上下文占用；点击或 hover 后在同一信息面板中先显示对话上下文，再显示当前官方/中转站运行路由的账号额度窗口与重置时间。

## 5. 能力差异

1. 选择器只展示当前 host、提供方、中转站和模型实际可用的选项。
2. 模型没有推理强度档位时，强度控件直接隐藏；只有一个档位时显示只读摘要，不打开空菜单。
3. 运行模式使用提供方返回的 mode 集合，保留 provider 原始英文标签；Plan、Build、Full Access 等不是模型。不支持的 mode 不伪造、不置灰占位。
4. Codex Plan mode 等独立 provider feature 不塞进模型或运行模式列表，而以能力控件单独呈现；未返回就不显示。
5. 模型不支持的联网、图片、语音或其它 Composer 工具直接隐藏，底栏自动回收空间。
6. 中转站不可用时显示健康状态和原因；不可用项不能成为新选择，但保留“管理中转站”出口。
7. 上下文与账号额度只展示 host 真实返回的数据：缺少 context window 时隐藏上下文入口，缺少 usage capability 或当前提供方额度时只展示已有部分，不制造 5h/7 天占位。

## 6. 视觉与响应式

- Composer 使用单一边界、8px 以内圆角和清晰的聚焦边框；不嵌套卡片。
- 顶部上下文条、正文、底栏由留白和细分隔线建立层级，不重复描边。
- 提供方、中转站、模型不拆成三个常驻胶囊；模型是主触发器，提供方与中转站收进摘要及锚定下拉顶部。
- 底栏所有点击槽位统一为 32px 高、6px 圆角和 16px 图标。模型、强度、模式是彼此间隔 6px 的同规格文字标签；“+”、上下文和发送是 32px 方形图标按钮。只有发送/停止使用实色，颜色只表达状态，不再用圆形、胶囊和不同图标底板混合制造层级。
- 桌面模型选择使用单列锚定下拉；紧凑态使用同一信息顺序的底部 sheet，不复制三列桌面弹框。
- 桌面 780px Composer 必须在单行底栏内放下“+”、三个有间隔的运行配置标签、上下文和发送；宽度不足时先隐藏提供方/中转站摘要，再将强度、模式和低频 provider feature 收入“+”菜单，模型入口切换为紧凑态底部 sheet。
- 紧凑态最小按 320px 验收：底栏只常驻“+”、模型、上下文和发送四个槽位；模型名允许省略，但任何控件不得横向滚动、换行顶高或被裁切。长工作目录必须在“已锁定”等尾部状态前正确省略。
- 队列中的“删除”和“强制发送”保持同高、同圆角并固定在右侧；窄宽度先省略消息摘要，两个动作仍保留。
- 文字过长时模型名优先保留，提供方/中转站摘要省略；控件不随内容改变高度。

## 7. 状态

- 默认、hover、聚焦、输入、附件、发送可用、发送中、运行中、队列、停止中。
- 工作目录未选、提供方不可用、中转站不可用、模型加载、模型空、切换失败。
- 推理强度单档/多档/不支持，标签保留 provider 返回的英文 `Low / Medium / High / XHigh / Max`；运行模式按 provider 返回值展示，危险模式使用风险色。
- 上下文用量等待/正常/70% 警告/90% 危险；账号额度加载、可用、部分窗口缺失、不可用、错误与 host 不支持。
- 待发消息单条/多条、删除、强制发送中、强制发送失败。
- host 离线时保留输入与队列，发送和配置改选禁用，恢复连接后继续。
- 紧凑态“+”菜单和模型底部 sheet；菜单按能力包含附件、引用、语音、推理强度、运行模式与 provider feature，不支持项不出现。

## 8. 边界

- 本需求不修改协议，也不新建 provider、vendor 或 agent 创建机制；Composer 只消费 host 已有能力与真实数据。
- 本机 Electron 使用操作系统目录选择器；普通浏览器、原生端与远程 host 使用 host 目录面板，不能访问运行客户端之外的本地文件系统。
- 中转站是 API 供应商配置，不复用或混淆主机 Relay 的术语与状态。
- 不在 UI 中硬编码某个提供方必然具有的模型、强度、模式、provider feature 或额度窗口；最终以 host 能力快照和 usage 响应为准。
- 深度配置中转站、密钥、API 格式和模型暴露列表仍在“设置 → 主机 → 提供方与中转站”。Composer 只选择和跳转管理入口。

## 9. 验收

1. 设计稿同时覆盖新对话、进行中对话、锚定模型下拉、强度/运行模式菜单、上下文/额度和能力差异。
2. 六项运行上下文均有明确位置：工作目录、提供方、中转站、模型、推理强度、运行模式；provider feature 按能力出现。
3. 首条消息前与开始对话后的可改/锁定规则清楚。
4. 运行、队列删除/强制发送、离线、加载、空和错误状态都有入口与出口。
5. 780px 桌面 Composer 与 320px 紧凑 Composer 均无文本溢出、控件重叠、横向滚动或高度跳变；长路径、长模型名和多模型列表均可收缩或内部滚动。
6. 当前对话上下文和账号额度在信息层级上明确分离，5h/7 天等窗口只按真实数据展示。
7. 模型、强度和模式三个标签之间有固定 6px 间隔，且与“+”、上下文、发送保持统一的 32px 高度和 6px 圆角；所有图标统一 16px，低频功能从“+”菜单完整可达。
