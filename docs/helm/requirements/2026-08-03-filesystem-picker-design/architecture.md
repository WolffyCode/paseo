# 本机工作目录选择器架构边界

> Gate 1 设计已确认；接手方进入 Gate 2 前必须补齐最终接口、能力门与测试清单，再开始生产实现。

## 责任划分

- 统一入口模型管理项目查询、最近项目、当前选择和浏览器开关。
- 本机浏览模型管理常用位置、目录树、当前路径、目录列表、搜索、选中项、路径历史和异步状态。
- UI 只渲染模型并派发动作，不自行拼接或猜测文件系统结果。
- workspace 创建只接收本机 daemon 可解析的规范化绝对目录路径。

## 平台路径

- Electron 与连接本机 daemon 的桌面 Web 使用同一个 Helm 双栏浏览器。
- 文件系统数据只从当前电脑的 daemon 目录服务读取；浏览器页面不直接把 File System Access API 句柄作为工作目录。
- 本期不建立远程 Host 目录浏览分支，也不在选择器内部提供设备切换。

## 浏览数据流

1. 打开浏览器时读取本机主目录、桌面、下载和项目位置。
2. 左侧位置或树节点改变当前根与路径；右侧使用现有目录列表能力读取当前层。
3. 返回 / 前进由模型维护路径历史；搜索只派生过滤当前已加载目录，不改变真实路径。
4. 单击只更新选中项；双击或 Enter 进入目录并刷新右侧；确认时将 daemon 返回的规范化绝对路径交给 workspace 创建边界。
5. 两栏滚动位置属于临时 UI 状态；切换路径时右栏回到顶部，展开树不重置右栏当前选择。

## 协议与安全边界

- 文件浏览复用现有 daemon 目录读取能力，不新增第二套文件协议。
- 若现有能力不足，Gate 2 使用 `server_info.features.*` 单点门控，并采用 dotted namespace 的 `.request` / `.response` 配对。
- 新字段保持可选；缺少能力时提示更新本机 Host，不降级为浏览器文件句柄或猜测路径。
- daemon 必须把目录读取请求绑定到已认证会话，并在确认前执行现有 workspace 路径校验。
