## 1. 目标 & 用户价值

**一句话目标**：把对话页右侧的**右侧侧边栏空容器**先立成一个**多页签工作面板的骨架**——展开后默认落**启动器列表**，具备 **Codex 式 tab 头**（图标+文字 · 活跃胶囊高亮 · 末尾 + · 右上 ⤢）的完整页签管理（新建 / 关闭 / 调序 / 右键 / 放大缩小 / 关全部回启动器）；并**落地「终端」这一个页签、做到全态全深度**——**忠实还原现有成熟终端**（等宽流式输出 / 聚焦键入 / 复制粘贴 / 加载·运行·错误·退出·离线各态 / 尺寸自适应 / 本地路径可点 / 拖文件插路径 / 平台差异）。**对话 / 浏览器 / 代码审核 / 文件四类本轮只在框架层声明类型与实例规则、以「后续」置灰呈现**，不设计内部。

**用户为什么需要它**：

- **为什么要工作面板？** 用户在对话里指挥 agent 干活，干完需要一个**固定的操作台**动手看东西——跑终端看输出、审 agent 改了什么、开浏览器看页面效果、翻文件看/改内容、在侧边另起一条子对话。空容器毫无用处；工作面板是「对话之外，动手看东西的地方」。
- **为什么先立五类框架、却只填终端一个？** 框架（所有页签挂靠的骨架）是**稳定外壳**，必须先立牢、一次声明清楚「右边总共能干什么」；内容则**分批填**。董事长给出三点收缩理由，逐条成立——① **文件、浏览器这两类「大」**：文件要接读/写/脏态/冲突/编辑器，浏览器要接内嵌渲染/截图/标注/进 composer，都是**可分离的重内容**，摸不清真实用法前铺开易返工；② **终端「最简单」、可先落地**：终端是一条自足的操作台（开会话→看流式输出→键入→复制粘贴→关闭），闭环短、边界清；③ **终端是「迁移现有成熟能力」而非从零发明**——现有终端已是打磨成熟的子系统，本轮把它**迁到新目录、按最新代码规则与模型 / UI 分离等价从新实现、忠实还原原行为**（此为实现层要求，HOW 归架构），产品面几乎零新概念、风险最低。**先立框架、先落最简单的终端，把工作区的架子搭起来，后边再补文件 / 浏览器 / 代码审核 / 对话**——这正是「先立形、再填细节」的分阶段铁律。
- **为什么终端要「忠实还原」而非重新设计？** 现有终端的交互（等宽流式、Ctrl+C 复制/中断、拖文件插路径、本地路径可点……）用户已有肌肉记忆，且经过打磨。本轮的价值是**把这套成熟能力搬进右侧工作面板、成为面板承载的第一个真实页签**，而**不是**改它的用法。迁到新目录、分离模型与 UI 是**代码层的等价重写**，用户**不应察觉行为变化**——因此产品面要求「忠实还原」，一切既有态照实兑现。
- **为什么要 Codex 式 tab 头（胶囊高亮）？** 董事长指明 tab 头观感对齐 Codex：图标+文字页签、活跃页签**胶囊式高亮**、页签间细分隔、末尾 +、右上 ⤢。骨架一次立好，后续补别的页签类型时**不必重构 tab 头**。
- **为什么要放大缩小？** 终端输出有时需要**更大视野**看清一长段日志：整面板放大占满对话区、单页签放大聚焦这一个终端——都是真实的「看得更清」诉求；放大后终端只需按新尺寸重新自适应，不改行为。
- **为什么其余四类现在不做、只声明框架？** 它们的**可见价值**（侧边聊、审 diff、看页面、看/改文件）确有需求，但**内部都是可分离的重基建**。本轮先在框架里给它们**留位 + 诚实标「后续」**，让用户对「右边将来能干什么」一眼有全貌，也不在没摸清真实用法前一次铺开。**v2 已为文件 / 浏览器做过全态设计（旧 sRS4–sRS10），这些设计意图与屏内容本轮不丢弃、待后续独立需求补充兑现**（指针见 §2·D）。

## 2. 范围

> 董事长允许「页签框架全做 + 部分页签内容全做、其余页签只声明框架标后续」的分阶段切法（参照 codepilot-layout / v1·v2 分阶段先例）。下方**做 / 不做逐条写死**，并对**深度切分**显式论证。**本轮唯一落地的页签内容 = 终端。**

### 做

#### A. 页签框架能力（全做 —— 这是五类页签挂靠的骨架，不能半建）

- **① 打开默认 = 启动器列表**：右侧侧边栏展开且**无任何已打开页签**时，落地态为**竖排启动器**；顶部**仅有 ⤢ 放大 + 收起**（**没有 tab 条、也没有「新选项卡 +」**）。**启动器呈现项 = 全部五类**（对话 / 浏览器 / 代码审核 / 终端 / 文件），其中**仅「终端」为可用项**，**对话 / 浏览器 / 代码审核 / 文件四行呈禁用 + 「后续」标**（相较 v2「文件 / 浏览器可用」，v3 **翻转为仅终端可用**）。点终端行 → 开终端页签、tab 条随之出现。
- **② 五类页签类型体系（框架层声明）**：面板可承载五类页签——**终端**（本轮**全做**，忠实还原现有终端）、**对话**（右栏侧边会话/子对话，deferred）、**浏览器**（内嵌网页 · 截图标注进 composer，deferred）、**代码审核**（工作区 diff · Stage/Revert/行评论，deferred）、**文件**（类 VSCode 查看+编辑，deferred）。五类均在框架层声明并给出实例规则；**除终端外四类本轮不设计内部**。
- **③ 实例规则（产品写死）**：
  - **代码审核 = 单实例**：面板内只能存在一个代码审核页签；再次「打开代码审核」= **聚焦既有页签**、不新建第二个（deferred，规则仅框架声明）。
  - **终端 / 对话 / 浏览器 / 文件 = 多实例**：可同时存在多个同类页签。**本轮仅「终端」可被真正打开、可同时开多个终端页签**；其余三类的多实例本轮为框架声明。
  - 无常驻页签、无固定首位、无不可关页签。
- **④ 多实例的去重与命名区分（产品写死）**：
  - **去重**：**终端各实例相互独立、不去重**（每个终端页签 = 一个独立会话，可多开）；文件按同一文件去重、代码审核受单实例约束（均 deferred，规则仅框架声明）。
  - **命名区分**：同类多个页签用各自内容区分标识——**终端 = 会话序号或工作目录**；文件 = 文件名、浏览器 = 页面标题（无标题用 URL）、对话 = 会话标题、代码审核 = 固定标识（后四者 deferred）；标识过长时**截断省略**（完整标识可经悬浮提示获得）。
- **⑤ tab 头（Codex 观感对齐）**：tab 条上每个页签 = **图标 + 文字**；**活跃页签 = 胶囊式高亮**（非蓝下划线）；页签之间有**细分隔**；tab 条**末尾有「新选项卡 +」**；tab 条**右上有 ⤢ 放大 + 收起**。tab 上可显**活动状态点**（运行 / 待输入 / 需关注），由页签内容驱动——**本轮唯一驱动源为终端**（见 B）。
- **⑥ 新选项卡 +（下拉）**：点 tab 条末尾「新选项卡 +」→ 弹**下拉**，呈现**全部五类**（**仅终端可用**；对话 / 浏览器 / 代码审核 / 文件禁用 + 「后续」标），各带快捷键提示；选终端即在 tab 条追加终端页签并聚焦；**快捷键等价触发**（无需先点 +）。
- **⑦ 悬浮关闭 ✕**：页签**悬浮时**行尾浮出 ✕，点它关闭该页签。**所有已打开页签均可关**（关闭 = 仅布局层移除、可重开）。**终端页签无「脏」概念——关闭 = 直接关，不弹任何「未保存」确认**（区别于 v2 文件页签的三择一确认，见 §3.1）。
- **⑧ 拖拽调序**：页签可**左右拖拽调序**，拖动时显**放置指示线**；无固定首位约束，任意页签可拖到任意位置。
- **⑨ 页签右键菜单（3 项）**：在页签上右键 → **关闭页签 / 关闭其它 / 关闭全部**。
- **⑩ 放大缩小 ⤢**：
  - **整面板放大**：tab 条右侧 ⤢ → 右侧侧边栏**扩展占满对话区的空间**、**左栏保留**、**目录树按其自身显隐保留**；**还原 ⤡** 回到停靠态。
  - **单页签放大**：页签内容右上角有 ⤢ → **单独放大该页签内容**；本轮以**终端**演示——放大后终端**按新尺寸重新自适应**（更多行列可见），再 ⤡ 还原（语义细节见 §8·v3-F）。
- **⑪ 关掉全部页签 → 回启动器默认态**：所有页签关闭后回到 ① 的启动器列表。**新框架无常驻页签，「关全部」可真正回到裸启动器。**

#### B. 终端页签（全态全做 · 迁移现有终端 · 忠实还原）

> **WHAT 定义与边界（写进本节 · HOW 留架构）**：终端页签 = **把现有终端能力接入右侧工作面板，作为面板承载的第一个真实页签，全态忠实还原现有终端的用户可见行为**。**「迁移到新目录 + 按最新代码规则做模型 / UI 分离 + 在新目录等价从新实现」是实现层边界要求**（对应 standards §1 模型与 UI 分离、§2 重构而非打补丁）——本需求**只声明这条边界存在**，**HOW（复用既有仿真内核 vs 重写集成层、模型归属、协议能力如何映射）一概归 P2 架构，本 WHAT 层不点名**。

**B.1 忠实还原清单（A · 现状真有，照实兑现）**

- **输出**：**等宽字体**流式输出 + **闪烁光标** + 输出**流式追加**（带背压 / 合并，长时间高速输出不卡）。
- **输入**：内容区**聚焦后可键入**；**Ctrl+C**：有选区时**复制选区**、无选区时**向当前进程发中断**（相当于中断正在跑的命令）；**Ctrl+V**：粘贴。
- **右键菜单（桌面 web / desktop · 3 项）**：**复制**（**有选区才启用**）/ **粘贴** / **全选**——就这 3 项（是否新增「清屏」第 4 项见 §8·v3-C）。
- **加载态**：连接中，居中**加载指示**遮罩。
- **运行态**：流式输出。
- **错误态**：底部一行**错误提示**（连接 / 订阅失败）；出口 = 自动 / 手动重连。
- **退出态**：进程结束 → 显**「进程已结束」提示** + 清屏；出口 = 关闭该页签 / 新开一个终端（是否附带**非 0 退出码**见 §8·v3-B）。
- **离线态**：主机断连 → 见 §8·v3-D（倾向服从面板级冻结 + 横幅 + 自动重连；现状为整屏切「主机未连接」居中消息 + 自动重连）。
- **本地链接**：输出里的**文件路径可高亮**（下划线 + 手型光标），可**带行 / 列定位**；**「点击路径 → 打开为文件」的落点是文件页签，本轮文件页签 deferred → 该点击的「打开」顺延后续**（见 §8·v3-G），本轮忠实保留**路径识别与高亮**。
- **文件拖拽（桌面 web / desktop）**：拖文件到终端 → 显**放置遮罩** → 松开即**插入经 shell 转义后的路径**（**不自动执行**）。
- **尺寸自适应**：终端**自适应父容器尺寸**，尺寸变化时**向主机汇报行数 / 列数**（无专门 UI；改宽 / 放大后自动重排，注解说明行为即可）。
- **活动状态点**：终端向 tab 头**汇报活动状态**（运行 / 待输入 / 需关注），tab 上显对应状态点。
- **平台差异**：**web / desktop** = 内嵌等宽输出 + **自绘滚动条** + **文件拖拽** + **右键菜单（3 项）**；**native** = 内嵌等宽输出（**无滚动条 / 无文件拖拽 / 无右键菜单**）+ **移动虚拟键盘条**（Esc / Tab / 方向 / Enter / 退格 / 空格 + Ctrl / Shift / Alt 粘滞修饰键）。**本轮平台 = 桌面 only；native 虚拟键盘条 deferred**（见 H），不作为桌面态设计。

**B.2 董事长点名补充项（B · 现状没有 · 标「补充 · 待董事长闸 1」· 每条进 §8 开放问题）**

- **空态「无历史停提示符」**：**现状无专门空态占位**（新终端只显 shell 提示符或回放历史快照）。董事长点名要空态 → 记为「新终端仅显示提示符、无历史」的空态；**是否新增专门空占位** vs **忠实显示裸提示符** → §8·v3-A。
- **非 0 退出码显式展示**：**现状只显「进程已结束」、不带退出码**。董事长点名「非 0 退出码」→ **是否在退出态展示退出码** vs **忠实不展示** → §8·v3-B。
- **右键「清屏」**：**现状右键仅 复制 / 粘贴 / 全选 3 项、没有清屏**（内核具备清屏能力但未接入菜单）。董事长点名清屏 → **右键是否新增「清屏」第 4 项** vs **保持忠实 3 项** → §8·v3-C。
- **离线「冻结」与面板级调和**：董事长说「冻结 + 重连」；**现状是整屏切「主机未连接」居中消息 + 自动重连（非冻结留存旧内容）**；而**面板级离线（sRS6）是整面板所有页签统一冻结 + 顶部重连横幅**。两者需调和 → §8·v3-D。

**B.3 终端 WHAT 层能力依赖（用 WHAT 描述 · 不点名 RPC）**——见 §5 能力门。

#### D. 对话 / 浏览器 / 代码审核 / 文件页签（仅框架层声明 · 内部标后续 · deferred）

- **本轮只做**：在框架层**声明这四类的类型 + 实例规则**（代码审核单实例；对话 / 浏览器 / 文件多实例），并在**启动器 / 新选项卡下拉**中以**禁用 + 「后续」标**呈现（诚实展示路线图、不产生死胡同）。
- **本轮不做（deferred · 不静默丢弃）**：四类的**内部**均标后续、不设计不实现，但框架**预留其位**——
  - **对话**：右栏侧边会话 / 子对话。
  - **浏览器**：内嵌网页 · 地址栏导航 · 设备工具条 · 隔离沙箱 · 截图 + 标注 · 标注截图进对话 composer。**v2 曾为浏览器做过全态设计（旧 sRS8 / sRS9 / sRS10）**——其设计意图与屏内容**本轮降 deferred、不丢弃，待后续独立需求补充兑现**。
  - **代码审核**：工作区 diff · Stage / Revert · 行评论 · 对话「改动·diff → 代码审核」映射。
  - **文件**：类 VSCode 查看 + 语法高亮 + 编辑 · Markdown 编辑/预览双态 · 图片只读 · 脏标记 / 保存 / 关闭确认 / 外部变更冲突 · 消费目录树选中 · 承接对话文档地址 · 页签↔树双向联动。**v2 曾为文件做过全态设计（旧 sRS4 / sRS5 / sRS6 / sRS7）**——其设计意图与屏内容**本轮降 deferred、不丢弃，待后续独立需求补充兑现**。

#### E. 承接对话跳转 & 消费目录树（随文件页签 deferred 顺延 · 不静默丢弃）

- **「文档地址 → 文件页签」承接**、**消费目录树输出的「选中文件」**、**页签↔树双向联动（reveal / 重根 / 选中）**——三者的**落点都是文件页签**；文件页签本轮 deferred，故**一并顺延后续**（deferred），**待文件页签落地时兑现**，本轮**不静默丢弃**。
- **「改动 / diff → 代码审核」映射**同理随代码审核 deferred 顺延后续。

#### F. 面板级聚合态

- **面板级空 / 加载 / 错误 / 能力门（更新主机·不降级）/ 离线** 五态，与终端页签内容态**区分**（详见 §3.5 / sRS6）。

#### G. 主题

- 走 **codePilot** 主题（GitHub 浅色默认 + 深色一并适配），与外壳**同一套主题来源**，不自带冲突配色（主题取值 / 切换机制归 codepilot-layout，本需求不定义）。选中 / 激活态 = 很淡的灰高亮（浅底深字，绝非黑底白字）；蓝仅点缀。

#### H. 平台

- **桌面 only**；**native 移动虚拟键盘条 deferred**、移动 / 浏览器紧凑态 deferred。

### 深度切分 · 显式论证

> 为什么**框架全做 + 终端全做**、**对话 / 浏览器 / 代码审核 / 文件只声明框架标 deferred**？用董事长三点收缩理由论证。

**① 「文件 + 浏览器这两个大」——先避重**：文件页签要接读 / 写 / 脏态 / 保存 / 外部变更冲突 / 类 VSCode 编辑器；浏览器页签要接内嵌渲染 / 截图 / 标注 / 粒度样式 / 进 composer。二者都是**可分离的重内容**，在没摸清真实用法前铺开，很可能**建错、返工**。v2 已为它们做了全态设计（12 屏中的旧 sRS4–sRS10），**设计不作废、只顺延**，作为后续独立需求的起点。

**② 「终端最简单、可先落地」——先落最短闭环**：终端是一条**自足且短的操作台**（开会话 → 流式输出 → 键入 → 复制粘贴 → 关闭），态清晰、边界干净，做全**不会返工**。它是把工作面板「跑起来、见到真实内容」的**最低成本的第一个页签**。

**③ 「迁移现有成熟终端、模型 / UI 分离等价重写」——先搬成熟件、零新概念**：终端不是从零发明，而是把**打磨成熟的既有能力**搬进面板；产品面几乎无新概念，风险最低。迁到新目录、分离模型与 UI 是**代码层等价重写**（HOW 归架构），用户**不应察觉行为变化**——故要求「忠实还原」。**先立框架、先搭架子、先落终端，后补其余四类**，正是「先立形、再填细节」的分阶段铁律。

### 不做（逐条写死 · 防范围蔓延 · 每条后续项不得静默丢弃）

- **不重定义壳行为**：右栏 toggle（顶栏、默认收起）、宽度（默认 480 / min 320 / max 800）、相邻手柄拖拽改宽、按工作区记忆宽度、需 active workspace 才可用、「展开右侧边栏」公共壳行为——**全部沿用壳子 `2026-06-28-shell` 与 `2026-06-27-codepilot-layout`，本需求一概不改、不重写**。
- **不做目录树**：定位 / 选中 / 搜索 / 切目录 / 文件图标 / 树内右键 / 内联新建重命名删除 / 拖拽——**属 file-tree 模块**（独立第 4 区）。
- **不写终端实现路子**：终端如何迁移、如何做模型 / UI 分离、如何复用既有仿真内核、尺寸 / IO / 快照能力如何映射为协议——**一概归架构 P2**，本 WHAT 层只声明「忠实还原现有终端行为」这一边界。
- **不做对话页签内部**（**deferred · 后续**）：右栏侧边会话 / 子对话。
- **不做浏览器页签内部**（**deferred · 后续**，v2 曾全态设计旧 sRS8–sRS10）：内嵌渲染 / 导航 / 设备工具条 / 隔离沙箱 / 截图标注 / 进 composer——**设计不丢、待后续兑现**。
- **不做代码审核页签内部**（**deferred · 后续**）：工作区 diff / Stage / Revert / 行评论 / 对话「改动·diff → 代码审核」映射。
- **不做文件页签内部**（**deferred · 后续**，v2 曾全态设计旧 sRS4–sRS7）：查看 / 语法高亮 / 编辑 / md 双态 / 图片只读 / 脏标记 / 保存 / 关闭确认 / 外部变更冲突 / 消费目录树选中 / 承接对话文档地址 / 页签↔树双向联动——**设计不丢、待后续兑现**。
- **不做承接对话跳转 / 消费目录树 / 树双向联动**（**deferred · 随文件页签顺延**，不静默丢弃）。
- **不做对话侧「发起跳转」的交互**（属 `2026-06-28-conversation-page`）。
- **不做 composer 对附件的渲染**（属 `2026-06-28-conversation-page`）。
- **不定义主题取值 / 切换机制 / 入口**（归 codepilot-layout）。
- **不做移动 / 浏览器紧凑态、native 虚拟键盘条**（**deferred**）。
- **不涉及协议 / RPC / 能力标志**：纯前端设计需求；能力门是架构师 P2 的事，本 WHAT 层只说「依赖某能力」不点名。

## 3. 流程（端到端）

> 每态有入口、有出口，无死胡同。覆盖框架 / 终端全流程（含连接·输入·复制粘贴·错误·退出·离线·尺寸自适应·本地链接·拖文件）/ 放大 / 对话承接（deferred 顺延）/ 面板级聚合。

### 3.1 页签框架

- **展开右侧侧边栏 → 落启动器默认态**：用户点顶栏右栏 toggle 展开右侧侧边栏（壳行为）→ 若**无任何已打开页签**，落**启动器列表**（五类竖排：**仅终端可用**；对话 / 浏览器 / 代码审核 / 文件禁用+「后续」，各带快捷键提示）；顶部仅 ⤢ + 收起，无 tab 条、无「新选项卡 +」。出口 = 点终端行开页签 / ⤢ 放大 / 收起交还壳。
- **从启动器开页签**：点**终端**行（或按其快捷键，建议 ⌃`，见 §8·v3-E）→ 打开终端页签、tab 条出现（含「新选项卡 +」）。点四个禁用项（对话 / 浏览器 / 代码审核 / 文件）→ 无反应（保持禁用态，标「后续」）。出口 = 切页签 / 新建 / 关闭 / 调序 / 放大。
- **新选项卡 +**：点 tab 条「新选项卡 +」→ 弹下拉【**仅终端可用**；对话 / 浏览器 / 代码审核 / 文件禁用+后续】→ 选终端即追加终端页签并聚焦；快捷键等价触发。点下拉外 / Esc → 关下拉、不新增。
- **切页签**：点某页签 → 切到其内容；当前页签呈**胶囊高亮**。
- **悬浮关闭 ✕**：页签悬浮 → 行尾浮出 ✕ → 点它关该页签（所有页签可关，关 = 仅布局、可重开）。**终端页签无脏态 → 直接关闭，不弹任何确认**（关闭即结束该终端会话）。
- **拖拽调序**：拖某页签左右移动 → 显放置指示线 → 松开即在指示位落位；无固定首位约束。
- **页签右键（3 项）**：右键某页签 → **关闭页签**（关该页签）/ **关闭其它**（关除它外全部）/ **关闭全部**（关掉全部）。点项即执行并关菜单；点菜单外 / Esc → 关菜单不执行。**（终端无脏态，各关闭动作直接执行、无逐一确认。）**
- **关掉全部页签 → 回启动器**：当**所有页签都被关闭**时 → 回启动器默认态（sRS1）。新框架无常驻页签，**此出口完整可达**。

### 3.2 终端页签（忠实还原现有终端）

- **打开终端**：从启动器 / 新选项卡开终端 / 快捷键（建议 ⌃`）→ 进**连接中**（居中加载指示遮罩）。出口 = 连上转运行 / 连接失败转错误。
- **连上 → 运行态**：终端**流式输出**（等宽字体 + 闪烁光标 + 追加）。出口 = 键入 / 复制粘贴 / 进程结束转退出 / 断连转离线 / 切页签 / 放大 / 关闭。
- **输入**：内容区**聚焦后键入**，字符送往会话。**Ctrl+C**：有选区 → 复制选区；无选区 → 向进程发中断。**Ctrl+V** → 粘贴。
- **右键（桌面 · 3 项）**：**复制**（有选区才启用）/ **粘贴** / **全选**。（是否加「清屏」第 4 项 → §8·v3-C。）
- **进程结束 → 退出态**：显「进程已结束」提示 + 清屏（是否带退出码 → §8·v3-B）。出口 = 关闭该页签 / 新开一个终端。**无死胡同。**
- **连接 / 订阅错误（分叉）**：底部一行错误提示。出口 = 自动重连 / 手动重连 → 成功回运行、仍失败保持错误可再试。
- **主机断连 → 离线（分叉）**：见 §3.5 面板级离线（**倾向服从面板级：冻结旧输出 + 顶部重连横幅 + 自动重连**；现状取舍见 §8·v3-D）。主机恢复 → 回运行。出口 = 重连。
- **尺寸自适应（分叉）**：父容器尺寸变化（改宽 / 放大 / 收起再展开）→ 终端**自动重排 + 向主机汇报行列数**（无专门 UI）。出口 = 重排后照常运行。
- **本地链接（分叉）**：输出里的文件路径**高亮**（下划线 + 手型），带行 / 列定位。**点击「打开为文件」的落点是文件页签、本轮 deferred → 顺延后续**（本轮忠实保留高亮识别；点击的过渡处置见 §8·v3-G）。
- **拖文件插路径（分叉 · 桌面）**：拖文件到终端 → 显放置遮罩 → 松开即**插入经 shell 转义后的路径**（**不自动执行**，光标停在插入处等用户决定）。出口 = 用户继续编辑 / 回车执行由用户决定。
- **空态（分叉）**：新终端**仅显示提示符、无历史**（现状无专门空占位，取舍见 §8·v3-A）。出口 = 键入即进入运行。

### 3.3 放大缩小

- **整面板放大 / 还原**：停靠态点 tab 条 ⤢ → 右侧侧边栏**扩展占满对话区的空间**（左栏保留、目录树按其自身显隐保留）；图标变 ⤡ → 点 ⤡ 还原回停靠列（恢复对话区）。旁边的**收起**仍可把整列收起、右栏 toggle 交还壳。
- **单页签放大 / 还原（终端演示）**：点终端页签内容右上角 ⤢ → 单独放大该终端；放大后终端**按新尺寸重新自适应**（更多行列可见），输出**照常实时流式**；再 ⤡ 还原（语义细节见 §8·v3-F）。

### 3.4 对话承接（deferred · 随文件页签顺延）

- **文档地址 → 文件页签**：对话页发起跳转、右侧侧边栏承接并打开文件页签——因**文件页签本轮 deferred，此承接顺延后续**（不静默丢弃，待文件页签落地兑现）。
- **改动 / diff → 代码审核**：同理随代码审核 deferred 顺延后续。

### 3.5 面板级聚合态

- **面板级离线（聚合）**：主机断连 → **整面板所有页签**统一冻结当前内容 + 顶部一条重连横幅；主机恢复后各页签按各自能力恢复。**终端离线态倾向服从此聚合行为**（见 §8·v3-D）。出口 = 重连。
- **面板级加载（聚合）**：面板打开 / 页签恢复 / 首次建立工作面板中 → 面板级加载指示；完成落内容，失败转面板级错误。
- **面板级错误（聚合）**：无法建立工作面板（罕见的面板级失败）→ 提示 + **重试**。
- **面板级能力门（聚合 · 更新主机·不降级）**：主机版本过低 / 缺工作面板或终端能力 → 显「更新主机以使用工作面板」+「查看如何更新」引导升级；**不提供降级 / 模拟路径**。出口 = 升级主机后能力就绪即可用。
- **面板级空（聚合）** = **启动器默认态**（无任何已打开页签）= sRS1；出口 = 点启动器可用项（终端）开页签。
- **与终端内容态区分**：面板级空（无页签）≠ 终端空（新终端仅提示符）；面板级离线（整面板冻结+横幅）与终端离线态需调和（§8·v3-D）；某页签态异常不代表面板级异常。

  - 右键菜单：无独立右键。入口：面板恢复 / 断连 / 能力探测失败 / 关光页签。出口：各态如上，均可达确定态。

**全态交互聚焦**：每屏覆盖 默认 / hover / 活跃（胶囊高亮）/ 运行（终端流式）/ 禁用（启动器四类 + 下拉四类）/ 空（面板空 / 终端空）/ 加载 / 错误 / 退出（终端）/ 离线 / 浅深主题，以及各屏右键菜单（sRS3 页签右键 3 项 / sRS4 终端 3 项 / sRS1·2·5·6 无独立右键或随内容区）与每个可点元素的点击效果。

## 5. 边界与依赖

### 与既有设计的关系（分工边界）

- **建立在壳子之上（壳行为一概不重定义）**：本需求填的是壳子 `2026-06-28-shell` §7.d 第 22–25 条标注的右侧侧边栏空容器。右栏 toggle（顶栏 · 默认收起）、宽度（默认 480 / min 320 / max 800）、相邻手柄拖拽改宽、按工作区记忆宽度、需 active workspace、**「展开右侧边栏」公共壳行为**——**全部是壳行为**（壳子 + `2026-06-27-codepilot-layout`），**本需求沿用不改**。本需求只关心「容器里装什么、怎么用」。
- **终端页签的 WHAT 边界（迁移 / 模型-UI 分离声明 · HOW 归架构）**：终端页签 = **把现有终端能力接入右侧工作面板、作为第一个真实页签、忠实还原其用户可见行为**。**「迁到新目录 + 模型与 UI 分离 + 等价从新实现」是实现层边界声明**（standards §1 / §2）——本需求只声明这条边界，**HOW（复用既有仿真内核 vs 重写集成层、模型归属、协议能力映射）一概归架构 P2**，本 WHAT 层不点名任何实现符号。
- **与目录树（file-tree 模块）边界（随文件页签 deferred 顺延）**：目录树只做「定位 + 选中 + 搜索 + 切目录 + 图标 + 树内右键 + 内联新建重命名删除」，是独立第 4 区。**「消费目录树选中 / 命令 reveal·重根 / 页签↔树双向联动」的落点是文件页签，文件页签本轮 deferred → 一并顺延后续**（不静默丢弃）。**终端本地链接「点击打开文件」的落点亦是文件页签 → 同随文件页签顺延**（本轮忠实保留路径高亮识别，见 §8·v3-G）。
- **与对话页（conversation-page）联动（随文件页签 / 浏览器 deferred 顺延）**：「文档地址 → 文件页签」承接、「改动 / diff → 代码审核」映射、浏览器「标注截图加入对话 composer」——三者的落点（文件页签 / 代码审核 / 浏览器）本轮均 deferred，**故对话侧联动本轮一并顺延后续**（不静默丢弃）。本需求**不画对话侧交互、不画 composer 渲染**。
- **与 codepilot-layout（主题）**：走 **codePilot** 主题（GitHub 浅色默认 + 深色），与外壳同一套主题来源；**主题取值 / 浅深切换机制 / 入口归 codepilot-layout**，本需求不定义、不自带冲突配色。

### 平台与能力门（用 WHAT 描述 · 不点名 RPC / 接口）

- **桌面 only**；**native 虚拟键盘条 / 移动 / 浏览器紧凑态 deferred**。
- **能力门 · 终端会话双向 IO（必需）**：依赖「主机能开一个终端会话并双向流式收发 IO」的能力。不可用 → 终端页签走错误 / 离线态（可重连）；能力整体缺失 → 面板级能力门「更新主机」。
- **能力门 · 终端尺寸变更（必需）**：依赖「主机能接收终端尺寸（行数 / 列数）变更」的能力。不可用 → 尺寸自适应不生效（输出仍可显示但不随容器重排）。
- **能力门 · 会话快照 / 恢复（可选）**：依赖「主机能提供会话历史快照供恢复」的能力。不可用 → 重开 / 恢复时终端从空提示符起（无历史回放）——对应终端空态。
- **能力门 · 本地路径解析（可选）**：依赖「主机能把输出里的本地路径解析为可打开的文件」的能力。不可用 → 路径不高亮 / 不可点（退化为普通文本）。**注**：即便可解析，「点击打开」的落点是文件页签、本轮 deferred，故点击行为随文件页签顺延（§8·v3-G）。
- **随后续页签顺延的能力门（deferred）**：读 / 写文件内容、外部变更感知（文件页签）、内嵌网页渲染 / 网页截图与元素上下文（浏览器）、加入对话 composer（浏览器·文件）、目录树定位联动（文件页签）——**均随对应 deferred 页签顺延，本轮不定义**。
- 以上均为**能力门**：能力在则功能可用，能力缺则相应路径给出可恢复的提示态，**不写降级版另一套实现**。能力门的具体形态（协议 / RPC / 能力标志）属架构师 P2，本需求不点名。
- **无老用户 / 迁移**（fork 未上线）：不写存量兼容。

## 6. 验收标准（逐条可判定 · 能 / 否）

**页签框架 · 启动器 · 呈现项（sRS1）**

1. 右侧侧边栏展开且**无任何已打开页签**时，**能**落**启动器列表**（竖排五类），且顶部**仅有 ⤢ 放大 + 收起**、**无 tab 条、无「新选项卡 +」**。
2. 启动器**恰呈现五类**（对话 / 浏览器 / 代码审核 / 终端 / 文件），其中**仅「终端」为可用项**，**对话 / 浏览器 / 代码审核 / 文件四行为禁用 + 「后续」标**、不可点。
3. 点启动器**终端**（或按其快捷键）**能**打开终端页签，此后 tab 条**能**出现（含「新选项卡 +」）；点四个禁用项**无**打开效果。

**页签框架 · 五类体系 + 实例规则（sRS2）**

4. 文档**明确声明五类页签**（对话 / 浏览器 / 代码审核 / 终端 / 文件）及其实例规则：**代码审核 = 单实例**，**终端 / 对话 / 浏览器 / 文件 = 多实例**；**本轮仅终端可被真正打开、可同时开多个终端页签**。
5. 同类多个终端页签**能**用各自标识区分（**终端 = 会话序号或工作目录**）；标识过长**能**截断省略。
6. tab 头**能**呈现 Codex 观感：**图标 + 文字页签**、**活跃页签 = 胶囊式高亮**（**非**蓝下划线）、**页签间有细分隔**、**tab 条末尾有「新选项卡 +」**、**右上有 ⤢ 放大 + 收起**；tab 上**能**显活动状态点（运行 / 待输入 / 需关注，本轮由终端驱动）。
7. 新框架下**无固定首位、无不可关页签**——**所有已打开页签均可关**；**关闭终端页签直接执行、不弹任何「未保存」确认**。

**页签框架 · 管理交互（sRS3）**

8. 「新选项卡 +」点开的下拉**恰为五类**（**仅终端可用**；对话 / 浏览器 / 代码审核 / 文件禁用+后续），各带快捷键提示；选终端**能**追加终端页签；快捷键**能**等价触发。
9. 页签**悬浮时能**浮出 ✕ 关闭该页签（关 = 仅布局、可重开）；**终端页签关闭无确认弹窗**。
10. 页签**能**左右拖拽调序，拖动时**有**放置指示线；**无**固定首位约束。
11. 页签右键**能**弹出菜单，且**恰为 3 项**：关闭页签 / 关闭其它页签 / 关闭全部页签，各项点击效果如 §3.1。
12. **所有页签关闭后能**回到启动器默认态（sRS1）——新框架下此出口**完整可达**。

**终端页签 · 忠实还原（sRS4 · 本轮核心）**

13. 终端页签**能**连上并**流式等宽输出**；内容区聚焦后**能**键入；**Ctrl+C**（有选区复制 / 无选区中断）、**Ctrl+V**（粘贴）**能**如常工作。
14. 终端**能**覆盖各态且每态**有**出口：加载（居中指示）/ 运行（流式）/ 错误（底部错误行 + 重连）/ 退出（「进程已结束」+ 清屏，出口 = 关页签 / 新开）/ 离线（重连）。
15. 终端右键**恰为 3 项**（复制〔有选区才启用〕/ 粘贴 / 全选）；**native 无右键菜单**（平台差异 · deferred）。
16. 终端**能**自适应父容器尺寸（改宽 / 放大后重排），并向主机**汇报行 / 列数**变化。
17. 终端**能**向 tab 头汇报活动状态（运行 / 待输入 / 需关注）并显对应状态点。
18. 终端输出里的本地路径**能**高亮（下划线 + 手型 · 带行列定位）；文档**明确**「点击打开文件」落点随文件页签 deferred、本轮顺延（§8·v3-G），本轮忠实保留高亮识别。
19. 拖文件到终端**能**插入**经 shell 转义后的路径**且**不自动执行**。
20. 文档**明确区分**忠实还原（A）与董事长点名补充（B）：空态占位 / 非 0 退出码展示 / 右键清屏 / 离线冻结与面板级调和**四项**均标「现状如何 + 待闸 1 决策」，并逐条列入 §8。

**终端页签 · 迁移边界（WHAT 声明 · 可判定）**

21. 文档**明确声明**终端页签落新目录、按模型 / UI 分离等价重写、**忠实还原现有终端行为**；且**明确**其 HOW（复用内核 / 协议能力映射）归架构、本需求不点名任何实现符号。

**放大缩小（sRS5）**

22. tab 条 ⤢ **能**把整面板**放大占满对话区**（左栏保留、目录树按其显隐保留），⤡ **能**还原回停靠列；其旁「收起」仍**能**把整列收起、交还壳。
23. 终端页签内容右上角 ⤢ **能**单独放大该终端，放大后**能**重新自适应（更多行列可见），⤡ **能**还原；放大态下终端**能**照常实时流式。

**面板级聚合态（sRS6）**

24. 主机**离线**时**整面板所有页签统一冻结** + 顶部一条重连横幅，主机恢复后各页签按各自能力恢复；面板级**空/加载/错误**分别对应启动器默认态 / 面板恢复中 / 无法建立工作面板（+重试）；主机**版本过低 / 缺工作面板或终端能力**时**能**显「更新主机以使用工作面板」+ 查看如何更新、**不提供降级路径**；以上面板级态相互**并列且与终端内容态可区分**。

**deferred 声明（不静默丢弃）**

25. 文档**明确**：对话 / 浏览器 / 代码审核 / 文件**四类页签内部本轮 deferred**、仅框架层声明；且**明确文件 / 浏览器在 v2 曾做全态设计（旧 sRS4–sRS10）**，本轮降 deferred、**设计不丢、待后续独立需求补充兑现**（给出指针）。

## 7. 发散思考建议项（单列 · 每条「建议项 · 待董事长闸 1 采纳」+ 论证 · 与必做范围明确隔离）

> 以下**均为建议项、不在 §2/§4/§6 的必做范围内**，探索终端类工作面板的真实使用痛点，供董事长在闸 1 决定是否纳入。**未获采纳前不进入必做范围**；采纳的才增补进相应屏与验收。
> **说明**：董事长已点名的**空态占位 / 非 0 退出码展示 / 右键清屏 / 离线语义**属「忠实现状 vs 采纳补充」的取舍，已单列 §8 开放问题待闸 1 决策，**此处不重复**。

1. **建议项 · 待董事长闸 1 采纳 — 终端缓冲区（scrollback）内查找**（观感参照 VSCode 终端搜索）。**痛点**：一长段流式输出里定位某条日志 / 某个报错，靠滚动 + 眼扫极慢。**价值**：终端页签内一个查找框，命中高亮 + 上/下跳转，把「找到那一行输出」收进终端内。**隔离**：仅终端页签内、不影响目录树全局搜索（那归 file-tree）。
2. **建议项 · 待董事长闸 1 采纳 — 多终端会话切换 / 会话列表**。**痛点**：开多个终端页签后，想在会话间快速跳需逐个点 tab；tab 多时还会溢出。**价值**：一个终端会话下拉 / 列表（按会话序号或工作目录命名），一点即达；与命名区分（④）协同。**隔离**：框架层 + 终端命名，不改终端内核行为。
3. **建议项 · 待董事长闸 1 采纳 — 页签溢出下拉**。**痛点**：终端（及后续其它类型）页签开多了会超出 tab 条宽度，被挤出可视区的页签**无法触达**。**价值**：tab 条末尾加「溢出下拉」列出被隐藏页签，一点即达。**隔离**：纯框架层交互，不涉及任何页签内部。

## 8. 开放问题（终端 B 组 6 项 · 每项两候选 + 倾向 + 现状标注 · 待董事长闸 1 拍板）

> 以下 6 项为董事长点名但**现状没有**（或与现状 / 面板级设计冲突）的取舍点，须闸 1 二选一；每项给现状标注、两个候选与 **PM 倾向**。末尾保留 v2 已结论的处置。

- **v3-A · 终端空态占位**：**现状——无专门空态占位**（新终端只显 shell 提示符或回放历史快照）。候选：**(a) 新增专门空占位**（如「新终端 · 输入命令开始」引导层）/ **(b) 忠实——裸提示符即空态、不加占位**。**PM 倾向 (b)**：终端用户对提示符天然理解；假占位反而遮住真实提示符、令人怀疑是否已连上；YAGNI。
- **v3-B · 非 0 退出码展示**：**现状——退出只显「进程已结束」、不带退出码**。候选：**(a) 采纳**——退出态显退出码（非 0 时高亮，0 时仍显「进程已结束」）/ **(b) 忠实**——一律「进程已结束」、不带码。**PM 倾向 (a)**：退出码低成本高信号，直接服务董事长点名的「非 0 退出码」，用户一眼知成败。
- **v3-C · 右键「清屏」第 4 项**：**现状——右键仅 复制 / 粘贴 / 全选 3 项**（内核具备清屏能力但未接入菜单）。候选：**(a) 采纳**——右键增「清屏」第 4 项（能力已在、成本低、可发现的清屏帮不知道 `clear` 的用户）/ **(b) 忠实**——保持 3 项（用户可自行输入 `clear`）。**PM 倾向 (a)**：能力已具备、成本低、可发现性有价值；代价是从忠实 3 项变 4 项，需董事长确认是否愿意偏离「忠实」。
- **v3-D · 终端离线与面板级调和**：**现状——终端离线为整屏切「主机未连接」居中消息 + 自动重连（清空可见旧内容）**；而**面板级离线（sRS6）为整面板统一冻结 + 顶部横幅**。候选：**(a) 服从面板级**——冻结旧输出 + 顶部重连横幅 + 自动重连（保留 scrollback、与 sRS6 一致）/ **(b) 忠实**——整屏切居中消息 + 自动重连。**PM 倾向 (a)**：冻结保留上下文优于清屏；多页签时不与面板级横幅自相矛盾。此项**改现状**，须董事长确认。
- **v3-E · 终端启动器 / 新选项卡快捷键取值**：**建议 ⌃`（control + backtick，VSCode 终端惯例）**。候选：**(a) 采纳 ⌃`** / **(b) 另定**。**PM 倾向 (a)**：VSCode 肌肉记忆标准；v2 的 ⌘P（文件）/ ⌘T（浏览器）随二者 deferred 让位，本轮唯一可用项即终端，用 ⌃` 最自然。全局键位与其它模块的最终裁决可归快捷键设置模块；本轮唯一可用项无内部撞车。
- **v3-F · 终端单页签放大语义**：**现状——无 per-terminal 放大**（终端只填满父容器并自适应；放大是框架层能力）。候选：**(a) 终端参与单页签放大**——放大区域后**重新自适应尺寸**（更多行列可见）、无额外终端逻辑 / **(b) 本轮终端不设独立 ⤢**——放大仅整面板。**PM 倾向 (a)**：框架层已提供单页签放大（v2 sRS11），终端只需按新尺寸重新 fit（现状本就自适应），成本低且与框架一致。

**PM 额外发现的依赖冲突（非 B 组 · 一并请闸 1 明确）**

- **v3-G · 终端本地链接点击落点**：本地链接「点击 → 打开为文件」的落点是**文件页签**，而**文件页签本轮 deferred**——落点缺失。候选：**(a) 本轮保留路径高亮识别、点击暂不响应**（「打开」随文件页签顺延后续）/ **(b) 本轮点击降级为「复制路径到剪贴板」**。**PM 倾向 (a)**：保持忠实识别、避免引入一次性过渡交互（YAGNI）；待文件页签落地时兑现完整「点击打开」。无论哪个候选，**路径高亮识别本轮保留、点击闭环不静默丢**。
