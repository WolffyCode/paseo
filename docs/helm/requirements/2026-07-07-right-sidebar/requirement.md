## 1. 目标 & 用户价值

**一句话目标**：把对话页右侧的**右侧侧边栏空容器**先立成一个**多页签工作面板的骨架**——展开后默认落**启动器列表**，具备 **Codex 式 tab 头**（图标+文字 · 活跃胶囊高亮 · 末尾 + · 右上 ⤢ · **活跃 tab 常显 ✕**）的完整页签管理（新建 / 去重 / 关闭 / 调序 / 右键 / 放大缩小 / 关全部回启动器）；并**落地「文件」这一个页签、做到与 VSCode 文件页功能对等**——**类 VSCode 的查看 + 编辑面**（代码语法高亮编辑 + **编辑器背景随主题 + 代码高亮默认 ODPF**、Markdown **默认预览 / 可切编辑**双态、图片只读、**脏标记（编辑中未落盘的临时指示）/ 失焦自动保存 / 关闭即自动保存无确认 / 外部变更冲突 / 文件内查找替换浮层 / 常用快捷键对等**），**承接对话页「文档地址 → 文件页签」的跳转打开**、**消费目录树输出的「选中文件」并与目录树双向联动**、**作为任何输出里「点本地路径 → 打开文件」的统一落点**。**对话 / 浏览器 / 代码审核 / 终端四类本轮只在框架层声明类型与实例规则、以「后续」置灰呈现**，不设计内部。

**用户为什么需要它**：

- **为什么要工作面板？** 用户在对话里指挥 agent 干活，干完需要一个**固定的操作台**动手看东西——翻文件看/改内容、审 agent 改了什么、跑终端看输出、开浏览器看页面效果、在侧边另起一条子对话。空容器毫无用处；工作面板是「对话之外，动手看东西的地方」。
- **为什么先立五类框架、却只填文件一个？** 框架（所有页签挂靠的骨架）是**稳定外壳**，必须先立牢、一次声明清楚「右边总共能干什么」；内容则**分批填**。**为什么这一批先填文件**——文件是被依赖最多的落点：目录树只做「定位 + 选中」、对话只做「发起跳转」、终端输出里的本地路径只做「识别 + 高亮」，**三者的下文都落在文件页签**，且树与文件页签还是**双向**的（切文件页签要反向定位树）。**不做文件页签，这三条就都是断链**——点了树 / 点了对话文档地址 / 点了输出里的路径都**没有反应**，切页签时也**丢失「我在哪」**。终端 / 浏览器 / 代码审核 / 对话的**内部则是可分离的重基建**（会话流 / 内嵌渲染 + 截图标注 / diff 引擎 + Stage·Revert / 侧边会话模型），本轮先立框架、标「后续」，避免在没摸清真实用法前一次铺开、建错返工——这正是「先立形、再填细节」的分阶段铁律。
- **为什么文件页签要可编辑（不再是只读）？** 董事长否决了 v1「只读预览」。用户在审改代码的工作流里，**常要就地改一两处**——修个错别字、调一行配置、补段注释、写点 Markdown——为这点小改动跳出去开别的编辑器太慢、丢现场。**类 VSCode 的「查看 + 语法高亮 + 编辑」把「看文件」和「改文件」收在同一个落点**。**Markdown 做「预览 / 编辑」双态**因为 md 既是「读文档」也是「写文档」两种真实诉求（**默认落预览 / 查看**——多数打开 md 是为了读、读是更高频的诉求，要写再切编辑）。**图片只读**因为图片没有就地编辑诉求（编辑图片是另一个产品，YAGNI）。
- **为什么文件页签要与 VSCode 文件页功能对等（v5 新基线）？** 董事长看过 v4 文件设计后定基线：**文件页签的日常编辑体验要向 VSCode 文件页看齐**，让熟悉 VSCode 的用户零学习成本就地改文件。具体到用户价值——① **失焦自动保存**（去手动保存按钮 / ⌘S 手动保存 / 保存四态）：改完点去别处（切页签 / 切窗口 / 关页签）就自动落盘，用户**不用记得按保存、也不会因忘保存丢改动**；脏 ● 退化为「编辑中还没落盘」的临时提示、失焦即清；连锁地，**关页签也就不再需要「保存 / 放弃 / 取消」三择一弹窗打断**——关即自动保存、直接关。② **文件内查找 / 替换**（浮层）：编辑长文件时「定位一处 + 批量替换」是刚需，没有它用户只能靠眼扫滚动、改多处极慢；浮层不占整行、随手 ⌘F 唤起、命中高亮 + 上下条 + 逐个 / 全部替换，把「找到 + 改到」在文件页签内闭环。③ **常用快捷键对等**（撤销 / 重做 / 剪切复制粘贴 / 全选 / 查找 / 替换）：键盘流用户的肌肉记忆直接可用、不摸鼠标就能改；右键项作为补充通道并存。④ **编辑器背景随 app 主题 + 代码高亮默认 One Dark Pro Flat**（浅色主题配一套浅色默认高亮）：护眼且与 VSCode 一致的阅读手感。这些不是新增花活，而是「就地改文件」这件事**要好用到用户愿意在这里改、而不是跳出去**的必要门槛。
- **为什么文件页签是「目录树 + 对话跳转 + 输出本地链接」的共同落点？** file-tree §2「不做」明写「文件内容富预览属右侧边栏文件页签」、conversation-page「文档地址跳右栏的目标内容不在本需求」、终端「本地链接点击打开文件的落点是文件页签」——**三个兄弟模块都把「文件富预览 / 编辑的账」记到这个页签**。不做就**多向断链**，最该先兑现。文件先落地，正是把这三笔账一次性接上（详见 §2·E / §3.4 三条断链）。
- **为什么要承接对话跳转 + 消费目录树 + 与树双向联动？** 用户在对话里点了某文档地址、在目录树里选中某文件、在输出里点了某路径，期望**立刻在右边打开**；反过来，切到某个文件页签时，也期望目录树**自动定位到该文件所在处**，让「我在改哪个文件」在树里一眼可见。右侧侧边栏是这些跳转的**统一落点**，并与目录树**双向联动**——不承接、不联动，跳转就无处可去、目录树的「选中」就没有下文、「我在哪」就丢失。
- **为什么要 Codex 式 tab 头（胶囊高亮）？** 董事长指明 tab 头观感对齐 Codex：图标+文字页签、活跃页签**胶囊式高亮**（非蓝下划线）、页签间细分隔、末尾 +、右上 ⤢。骨架一次立好，后续补别的页签类型时**不必重构 tab 头**。
- **为什么要放大缩小？** 文件编辑有时需要**更大视野**细看细改：整面板放大占满对话区——真实的「看得更清、改得更稳」诉求；放大后内容照常实时生效（编辑 / 保存不受影响）。
- **为什么其余四类现在不做、只声明框架？** 它们的**可见价值**（侧边聊、看页面、审 diff、跑输出）确有需求，但**内部都是可分离的重基建**。本轮先在框架里给它们**留位 + 诚实标「后续」**，让用户对「右边将来能干什么」一眼有全貌，也不在没摸清真实用法前一次铺开。**v2 已为浏览器做过全态设计（旧 sRS8–sRS10）、v3 已为终端做过全态设计（v3 sRS4），这些设计意图与屏内容本轮不丢弃、待后续独立需求补充兑现**（指针见 §2·D）。

## 2. 范围

> 董事长允许「页签框架全做 + 部分页签内容全做、其余页签只声明框架标后续」的分阶段切法（参照 codepilot-layout / v1·v2·v3 分阶段先例）。下方**做 / 不做逐条写死**，并对**深度切分**显式论证。**本轮唯一落地的页签内容 = 文件。**

### 做

#### A. 页签框架能力（全做 —— 这是五类页签挂靠的骨架，不能半建）

- **① 打开默认 = 启动器列表**：右侧侧边栏展开且**无任何已打开页签**时，落地态为**竖排启动器**；顶部**仅有 ⤢ 放大 + 收起**（**没有 tab 条、也没有「新选项卡 +」**）。**启动器呈现项 = 全部五类**（对话 / 浏览器 / 代码审核 / 终端 / 文件），其中**仅「文件」为可用项**，**对话 / 浏览器 / 代码审核 / 终端四行呈禁用 + 「后续」标**（相较 v2「文件 / 浏览器可用」、v3「仅终端可用」，v4 **翻转为仅文件可用**）。点文件行 → 开文件页签（无选中则落空态「选择一个文件」）、tab 条随之出现。
- **② 五类页签类型体系（框架层声明）**：面板可承载五类页签——**文件**（本轮**全做**，类 VSCode 查看 + 编辑）、**对话**（右栏侧边会话 / 子对话，deferred）、**浏览器**（内嵌网页 · 截图标注进 composer，deferred）、**代码审核**（工作区 diff · Stage / Revert / 行评论，deferred）、**终端**（等宽流式输出 · 迁移现有终端，deferred）。五类均在框架层声明并给出实例规则；**除文件外四类本轮不设计内部**。
- **③ 实例规则（产品写死）**：
  - **代码审核 = 单实例**：面板内只能存在一个代码审核页签；再次「打开代码审核」= **聚焦既有页签**、不新建第二个（deferred，规则仅框架声明）。
  - **文件 / 对话 / 浏览器 / 终端 = 多实例**：可同时存在多个同类页签。**本轮仅「文件」可被真正打开、可同时开多个文件页签（按同一文件去重，见 ④）**；其余三类的多实例本轮为框架声明。
  - 无常驻页签、无固定首位、无不可关页签。
- **④ 多实例的去重与命名区分（产品写死）**：
  - **去重**：**文件页签按「同一文件只开一个」去重**——对同一文件重复打开 = 聚焦既有页签、不新开（详见 B）；浏览器 / 对话 / 终端各实例相互独立、不去重，代码审核受单实例约束（均 deferred，规则仅框架声明）。
  - **命名区分**：同类多个页签用各自内容区分标识——**文件 = 文件名**；浏览器 = 页面标题（无标题用 URL）、终端 = 会话序号或工作目录、对话 = 会话标题、代码审核 = 固定标识（后四者 deferred）；标识过长时**截断省略**（完整标识可经悬浮提示获得）。
- **⑤ tab 头（Codex 观感对齐）**：tab 条上每个页签 = **图标 + 文字**；**活跃页签 = 胶囊式高亮**（非蓝下划线）；页签之间有**细分隔**；tab 条**末尾有「新选项卡 +」**；tab 条**右上有 ⤢ 放大 + 收起**。tab 上可显**活动状态点**（由页签内容驱动，本轮唯一驱动源为文件——如未保存脏态在页签标题旁显脏点）。
- **⑥ 新选项卡 +（下拉）**：点 tab 条末尾「新选项卡 +」→ 弹**下拉**，呈现**全部五类**（**仅文件可用**；对话 / 浏览器 / 代码审核 / 终端禁用 + 「后续」标），各带快捷键提示；选文件即在 tab 条追加文件页签并聚焦；**快捷键等价触发**（无需先点 +）。
- **⑦ 可见关闭 ✕（VSCode 式）**：**活跃页签行尾常显 ✕**、**非活跃页签 hover 时行尾显 ✕**，点它关闭该页签；**脏页签在未失焦（尚未自动保存）时 ✕ 位可显脏 ●、hover 转 ✕**（脏 ● 与 ✕ 复用同一位置）。**所有已打开页签均可关**（关闭 = 仅布局层移除、可重开）。**关有脏改动的文件页签 = 触发失焦 = 静默自动保存后关闭、无确认弹窗**（v4 的「关闭未保存三择一确认」本轮整个取消，见 §3.2 / B）——区别于 v3 终端页签「无脏概念、直接关」，本轮文件页签是「关即自动保存、直接关」。
- **⑧ 拖拽调序**：页签可**左右拖拽调序**，拖动时显**放置指示线**；无固定首位约束，任意页签可拖到任意位置。
- **⑨ 页签右键菜单（3 项）**：在页签上右键 → **关闭页签 / 关闭其它 / 关闭全部**。（关含脏改动的文件页签时，对每个脏页签**静默自动保存后关闭、无确认弹窗**——关闭 = 失焦 = 自动保存。）
- **⑩ 放大缩小 ⤢（整面板）**：tab 条右侧 ⤢ → 右侧侧边栏**扩展占满对话区的空间**、**左栏保留**、**目录树按其自身显隐保留**；**还原 ⤡** 回到停靠态。**放大统一走整面板——文件内容区不另设放大 / 全屏按钮**（右侧工作区已有整面板全屏方法，文件内部不再重复放方法）。
- **⑪ 关掉全部页签 → 回启动器默认态**：所有页签关闭后回到 ① 的启动器列表。**新框架无常驻页签，「关全部」可真正回到裸启动器。**

#### B. 文件页签（全态全做 · 恢复 v2 已审设计 · 类 VSCode 可编辑）

> **恢复声明**：文件页签的态 / 右键项数 / 三分支联动 / 编辑必备态**照 v2（commit `000f1517`）恢复**——v2 已是董事长逐条审过的设计，本轮不重新发明，只做「文件先行」重构 + 接断链。**「类 VSCode 查看 + 编辑」是形态级观感参照，非实现符号**；文件如何读写、语法高亮 / 编辑器如何实现归架构 P2。

- **形态（按文件类型）**：
  - **代码 / 文本**（js / ts / java / txt 等）= 查看 + **语法高亮** + **编辑**。
  - **Markdown** = **编辑 / 查看（预览）双形态**可切换（页签内有「编辑 ⇄ 预览」切换）。
  - **图片** = **查看（不可编辑）**。
  - **未识别 / 二进制** = **只读兜底**（说明无法编辑）。
- **打开来源（三种 + 输出本地链接落点）**：① **目录树点击文件**（消费 file-tree 输出的「选中文件」）；② **对话点文档地址**（承接 conversation-page 发起的跳转）；③ **启动器 / 新选项卡开文件**（无选中 → 空态「选择一个文件」）；此外**作为任何输出里「点本地路径 → 打开文件」的统一落点**（如终端输出里的路径——触发侧随终端 deferred、落点本轮就位，见 §2·E / §3.4 断链②）。**目录树点文件 / 对话点地址 / 点输出路径时若右侧侧边栏收起 → 顺带展开右栏**（沿用壳「展开右侧边栏」公共壳行为，本需求不新增布局原语）。
- **同一文件去重**：对**同一文件**重复打开 = **聚焦既有页签**、不新开；不同文件各一个页签、可多开。
- **切树根不删页签**：目录树切换树根（换目录）**不删除**已打开的文件页签。
- **页签 ↔ 树双向联动（钉死语义，见 §3.2 联动）**：切到 / 聚焦某文件页签 → **命令目录树定位到该文件**（reveal 或重根），语义按该文件与当前树根的关系三分支确定；反向，目录树选中文件 → 打开 / 聚焦对应文件页签。此联动是**命令 file-tree 公共能力执行定位**，本模块**不重画树**、不越界。
- **编辑必备态**（**v5 · VSCode 对等**）：
  - **脏标记（编辑中未落盘的临时指示）**：文件被改动但尚未落盘时，页签标题旁 / 面包屑显**脏 ●**（可见脏点），**仅表示「编辑中还没写回磁盘」这一临时态**；**一旦失焦自动保存成功即清**。脏 ● 不再是「需要用户手动去保存」的提示。
  - **失焦自动保存（去手动保存）**：**无手动保存按钮、无 ⌘S 手动保存、无保存四态**——**编辑区 / 文件窗口失焦即自动写回**（观感参照 VSCode 的「失焦即自动保存」行为）。触发失焦的场景包括：切到别的页签、切到别的窗口 / 应用、点到文件内容区之外、关闭该页签。**自动保存成功**：脏 ● 清除、内容落盘。**自动保存失败**（如权限被拒 / 写能力不可用）：以**非阻塞指示**（状态条 / 轻提示）呈现「自动保存失败」，**不弹阻塞对话框、不给手动重试按钮**；用户继续编辑、下次失焦再次尝试自动保存；写能力整体缺失则文件页签退化为只读并说明（见能力门）。
  - **关闭 = 失焦 = 自动保存、无确认弹窗**：关闭有脏改动的文件页签**不再弹任何确认**（v4 的「保存并关闭 / 放弃更改并关闭 / 取消」三择一**整个取消**）——关闭动作本身即触发失焦、静默自动保存后关闭。
  - **外部文件变更冲突**：页签打开期间该文件在主机侧被**外部改动** → 弹**冲突提示**，给出口：**重载（放弃本地未落盘改动、载入主机最新）/ 保留本地（忽略外部变更、以本地为准）/ 对比（并排看本地与主机最新）**。（此为唯一保留的阻塞式确认——因涉及「本地改动 vs 外部改动」的真实数据取舍，不能静默。）
  - **文件内查找 / 替换（浮层 · v5 必做 · VSCode 式）**：代码 / 文本 / md 编辑形态下，**⌘F / Ctrl+F 唤起查找、⌘⌥F / Ctrl+H 唤起替换、Esc 关闭**；形态 = **悬浮在文件内容区右上角的浮层**（**不占一整行**），含**查找框 + 替换框（替换行可展开 / 收起）**、**命中计数**（第几 / 共几处）、**上一条 / 下一条**、**逐个替换 / 全部替换**、**区分大小写 / 全词匹配 / 正则**三个开关（VSCode 同款）；**命中在编辑区高亮、当前命中额外强调**。仅作用于**当前文件页签内**，**不影响目录树的全局搜索**（那归 file-tree）。
  - **快捷键对等（v5 新增 · VSCode 对等）**：编辑区支持——**撤销 ⌘Z / 重做 ⌘⇧Z（回退操作 = 重做）/ 剪切 ⌘X / 复制 ⌘C / 粘贴 ⌘V / 全选 ⌘A / 查找 ⌘F（Ctrl+F）/ 替换 ⌘⌥F（Ctrl+H）**；这些键位是**交互契约**。右键项与快捷键**并存**（右键是补充通道，见下「右键菜单」）。
- **右键菜单（三套，按内容区）**：
  - **代码 / 文本编辑区（9 项）**：剪切 / 复制 / 粘贴 / 全选 / 查找 / 替换 / 复制文件路径 / 在目录树中定位 / 在 Finder 中显示。（**v5 变更**：手动保存已改为失焦自动保存、无手动保存动作，故右键去掉「保存 / 还原此文件」两项、换入「查找 / 替换」两项——查找 / 替换即右键唤起 §上「文件内查找 / 替换」浮层，与 ⌘F / ⌘⌥F 快捷键并存互补；仍 9 项。此右键组成请董事长确认，见 §8·v5-Y。）
  - **Markdown 预览区（5 项）**：复制选中文本 / 复制文件路径 / 在目录树中定位 / 在 Finder 中显示 / 切到编辑。
  - **图片查看区（4 项）**：复制图片 / 复制文件路径 / 在目录树中定位 / 在 Finder 中显示。
  - **说明**：Markdown 编辑形态下右键 = 代码 / 文本编辑区 9 项（md 编辑即文本编辑；切到预览经页签内「编辑 ⇄ 预览」切换）。**目录树相关文件写操作（新建 / 重命名 / 删除 / 剪切复制粘贴文件等）归 file-tree 模块、不在本页签的任何右键里**（保持「不重画树」边界）。
- **全态**：默认（渲染内容 · 代码高亮默认 ODPF · 背景随主题）/ 编辑中 / 脏（编辑中未落盘的临时 ●）/ 失焦自动保存中·已自动保存·自动保存失败（非阻塞指示）/ 查找替换浮层（查找态 / 展开替换态 / 命中高亮）/ 空（未选文件）/ 加载（读取）/ 错误（无法读取该文件 + 重试）/ 冲突（外部变更）/ 只读兜底（图片 / 二进制 / 未识别）/ 离线（见面板级）/ 浅深 chrome 主题（编辑器背景随主题，见 G）。
- **边界**：文件页签**不含目录树**（只消费选中 + 命令 reveal / 重根）。

#### D. 对话 / 浏览器 / 代码审核 / 终端页签（仅框架层声明 · 内部标后续 · deferred）

- **本轮只做**：在框架层**声明这四类的类型 + 实例规则**（代码审核单实例；对话 / 浏览器 / 终端多实例），并在**启动器 / 新选项卡下拉**中以**禁用 + 「后续」标**呈现（诚实展示路线图、不产生死胡同）。
- **本轮不做（deferred · 不静默丢弃）**：四类的**内部**均标后续、不设计不实现，但框架**预留其位**——
  - **对话**：右栏侧边会话 / 子对话。
  - **浏览器**：内嵌网页 · 地址栏导航 · 设备工具条 · 隔离沙箱 · 截图 + 标注 · 标注截图进对话 composer。**v2（commit `000f1517`）曾为浏览器做过全态设计（旧 sRS8 / sRS9 / sRS10）**——其设计意图与屏内容**本轮降 deferred、不丢弃，待后续独立需求补充兑现**（指针：git 历史 v2 sRS8–sRS10）。
  - **代码审核**：工作区 diff · Stage / Revert · 行评论 · 对话「改动·diff → 代码审核」映射。
  - **终端**：等宽流式输出 · 聚焦键入 · 复制粘贴 · 加载 / 运行 / 错误 / 退出 / 离线各态 · 尺寸自适应 · 本地路径可点 · 拖文件插路径 · 平台差异。**v3（commit `60ea6bca`）曾为终端做过全态设计（v3 sRS4 · 忠实还原现有终端）**——其设计意图与屏内容**本轮降 deferred、不丢弃，待后续独立需求补充兑现**（指针：git 历史 v3 sRS4 + v3-A~v3-G 开放问题）。

#### E. 承接对话跳转 & 消费目录树 & 输出本地链接落点（本轮兑现 · 三条断链接通）

### 深度切分 · 显式论证

> 为什么**框架全做 + 文件全做**、**对话 / 浏览器 / 代码审核 / 终端只声明框架标 deferred**？

**① 「文件被依赖最多」—— 先接断链**：文件是目录树 reveal、终端本地链接、对话文档地址三条断链的**共同落点**，且与目录树**双向**。不做文件页签，这三条兄弟模块的「账」都悬空、点了没反应。先落文件，一次性把三条接上（断链① 端到端全通，断链②③ 承接侧就位）——这是「被依赖最多者优先」的收敛，也正是董事长「很多都依赖文件、先做文件」的意图。

**② 「文件契约稳定」—— 做全不返工**：文件页签的契约稳定（读一个文件 → 渲染 / 编辑 / 失焦自动保存 / 冲突 / 三分支联动），做全**不会返工**。它是把工作面板「见到真实内容、并与树 / 对话打通」的**最有价值的第一个页签**。

**③ 「其余四类是可分离重基建」—— 先立框架标后续**：对话 / 浏览器 / 代码审核 / 终端的**内部**是可分离的重基建（侧边会话模型 / 内嵌渲染 + 截图标注 / diff 引擎 + Stage·Revert / 会话流 + scrollback）。**五类框架 + 实例规则是稳定外壳**——现在立框架、以后补四类内部，**不推翻框架**。v2 已为浏览器做全态、v3 已为终端做全态，**设计不作废、只顺延**，作为后续独立需求的起点。这正是「先立形、再填细节」的分阶段铁律。

### 不做（逐条写死 · 防范围蔓延 · 每条后续项不得静默丢弃）

- **不重定义壳行为**：右栏 toggle（顶栏、默认收起）、宽度（默认 480 / min 320 / max 800）、相邻手柄拖拽改宽、按工作区记忆宽度、需 active workspace 才可用、「展开右侧边栏」公共壳行为——**全部沿用壳子 `2026-06-28-shell` 与 `2026-06-27-codepilot-layout`，本需求一概不改、不重写**。
- **不做目录树**：定位 / 选中 / 搜索 / 切目录 / 文件图标 / 树内右键 / 内联新建重命名删除 / 拖拽——**属 file-tree 模块**（独立第 4 区）；**文件页签只消费其「选中文件」并命令其 reveal / 重根，不重画树**。文件写操作（新建 / 重命名 / 删除 / 剪切复制粘贴）归 file-tree，不在本页签任何右键里。
- **不做对话页签内部**（**deferred · 后续**）：右栏侧边会话 / 子对话。
- **不做浏览器页签内部**（**deferred · 后续**，v2 曾全态设计旧 sRS8–sRS10）：内嵌渲染 / 导航 / 设备工具条 / 隔离沙箱 / 截图标注 / 进 composer——**设计不丢、待后续兑现**。
- **不做代码审核页签内部**（**deferred · 后续**）：工作区 diff / Stage / Revert / 行评论 / 对话「改动·diff → 代码审核」映射。
- **不做终端页签内部**（**deferred · 后续**，v3 曾全态设计 v3 sRS4）：等宽输出 / 会话流 / 复制粘贴 / 尺寸自适应 / 本地路径点击 / 拖文件插路径 / scrollback / 活动指示——**设计不丢、待后续兑现**。注：终端里「点本地路径 → 打开文件」的**落点（文件页签）本轮已就位**，只是**触发侧随终端 deferred**（断链②）。
- **不做对话侧「发起跳转」的交互**（属 `2026-06-28-conversation-page`）：在对话里哪里点、怎么触发由对话页负责；本需求**只承接「文档地址 → 文件页签」被跳转打开这一态**。
- **不做 composer 对附件的渲染**（属 `2026-06-28-conversation-page`）。
- **不定义主题取值 / 切换机制 / 入口**（归 codepilot-layout）。
- **不做移动 / 浏览器紧凑态**（**deferred**）。
- **不涉及协议 / RPC / 能力标志**：纯前端设计需求；能力门是架构师 P2 的事，本 WHAT 层只说「依赖某能力」不点名。

## 3. 流程（端到端）

> 每态有入口、有出口，无死胡同。覆盖框架 / 文件全流程（含编辑 / 失焦自动保存 / 冲突 / 查找替换 / 快捷键 / 三分支联动 / 三来源打开）/ 放大 / 对话承接与断链兑现 / 面板级聚合。

### 3.1 页签框架

- **展开右侧侧边栏 → 落启动器默认态**：用户点顶栏右栏 toggle 展开右侧侧边栏（壳行为）→ 若**无任何已打开页签**，落**启动器列表**（五类竖排：**仅文件可用**；对话 / 浏览器 / 代码审核 / 终端禁用 + 「后续」，各带快捷键提示）；顶部仅 ⤢ + 收起，无 tab 条、无「新选项卡 +」。出口 = 点文件行开页签 / ⤢ 放大 / 收起交还壳。
- **从启动器开页签**：点**文件**行（或按其快捷键，建议 ⌘P，见 §8·v4-D）→ 打开文件页签（无选中则落空态「选择一个文件」）、tab 条出现（含「新选项卡 +」）。点四个禁用项（对话 / 浏览器 / 代码审核 / 终端）→ 无反应（保持禁用态，标「后续」）。出口 = 切页签 / 新建 / 关闭 / 调序 / 放大。
- **新选项卡 +**：点 tab 条「新选项卡 +」→ 弹下拉【**仅文件可用**；对话 / 浏览器 / 代码审核 / 终端禁用 + 后续】→ 选文件即追加文件页签并聚焦；快捷键等价触发。点下拉外 / Esc → 关下拉、不新增。
- **切页签**：点某页签 → 切到其内容；当前页签呈**胶囊高亮**。**切到文件页签时触发页签 ↔ 树联动**（见 §3.2 联动）。
- **可见关闭 ✕（VSCode 式）**：**活跃页签常显 ✕**、**非活跃页签 hover 显 ✕**（脏页签未失焦时 ✕ 位可显脏 ●、hover 转 ✕）→ 点它关该页签（所有页签可关，关 = 仅布局、可重开）。**关有脏改动的文件页签** → **关闭即触发失焦 = 静默自动保存后关闭、无确认弹窗**（v4 三择一确认已取消，见 §3.2）。
- **拖拽调序**：拖某页签左右移动 → 显放置指示线 → 松开即在指示位落位；无固定首位约束。
- **页签右键（3 项）**：右键某页签 → **关闭页签**（关该页签）/ **关闭其它**（关除它外全部）/ **关闭全部**（关掉全部）。点项即执行并关菜单；关含脏改动的文件页签时对每个脏页签**静默自动保存后关闭、无确认弹窗**；点菜单外 / Esc → 关菜单不执行。
- **关掉全部页签 → 回启动器**：当**所有页签都被关闭**时 → 回启动器默认态（sRS1）。新框架无常驻页签，**此出口完整可达**。

### 3.2 文件页签（可编辑 · 恢复 v2）

- **打开文件 · 消费目录树选中**：目录树选中某文件（file-tree 输出「选中文件」）→ **若右栏收起则先展开右栏**（壳行为）→ 打开文件页签显示该文件内容（代码 / 文本编辑 / md 预览或编辑 / 图片查看 / 只读兜底之一）。**同一文件已开则聚焦既有页签、不新开**。
- **打开文件 · 承接对话文档地址**：对话里点某文档地址（对话页发起跳转）→ 同上打开 / 聚焦文件页签显示该文件；右栏收起则顺带展开。
- **打开文件 · 承接输出本地链接（断链②）**：任何输出里「点本地路径」→ 同上打开 / 聚焦文件页签（落点本轮就位）；终端等触发侧随终端 deferred，落点已在此等候、无需新增承接工作。
- **从启动器 / 新选项卡开文件而无选中**：显**空态「选择一个文件」**占位。出口 = 去目录树选一个 / 对话点一个 → 回填内容。
- **查看**：代码 / 文本 → 语法高亮内容（**编辑器背景随 chrome 主题：浅 chrome 浅底、深 chrome 深底；代码高亮默认 One Dark Pro Flat**）；md → **默认落预览 / 查看态**（渲染阅读，可切编辑，见下）；图片 → 图片查看；未识别 / 二进制 → 只读兜底（说明无法编辑）。
- **编辑（代码 / 文本 / md 编辑形态）**：在内容区修改 → 进入**编辑中**；一旦有未落盘改动 → 页签标题旁 / 面包屑显**脏 ●**（编辑中未落盘的临时指示）；**失焦即自动保存、脏 ● 随之清除**（见下「失焦自动保存」）。
- **Markdown 预览 ⇄ 编辑（默认落预览）**：md **打开默认落预览 / 查看态**（渲染阅读）；页签内有「预览 ⇄ 编辑」切换 → 切到编辑形态可改内容、切回预览渲染阅读；两形态间切换不丢未落盘改动；md 编辑形态下同样**失焦自动保存**、支持**查找 / 替换浮层**与**常用快捷键**。
- **失焦自动保存（去手动保存）**：**无手动保存按钮 / ⌘S 手动保存 / 保存四态**——**编辑区 / 文件窗口失焦即自动写回**（切页签 / 切窗口 / 点内容区外 / 关页签均触发失焦）→ **自动保存中 → 已自动保存**（脏 ● 清除）/ **自动保存失败**（如权限被拒 → **非阻塞指示**「自动保存失败」、**不弹阻塞框、不给手动重试按钮**，用户续编、下次失焦再试；写能力整体缺失 → 退化只读并说明）。
- **文件内查找 / 替换（浮层 · v5 必做）**：**⌘F / Ctrl+F**（或右键「查找」）→ 内容区右上角浮出**查找浮层**（不占整行）→ 输入查找词 → **命中在编辑区高亮、当前命中额外强调 + 命中计数（第几 / 共几处）** → **上一条 / 下一条**跳转 → **⌘⌥F / Ctrl+H**（或右键「替换」）展开**替换行** → 输入替换词 → **逐个替换 / 全部替换** → 可切**区分大小写 / 全词 / 正则** → **Esc 关闭**浮层。仅作用当前文件页签、不动目录树全局搜索。
- **常用快捷键（VSCode 对等 · v5 必做）**：编辑区支持 撤销 **⌘Z** / 重做 **⌘⇧Z**（回退 = 重做）/ 剪切 **⌘X** / 复制 **⌘C** / 粘贴 **⌘V** / 全选 **⌘A** / 查找 **⌘F** / 替换 **⌘⌥F**；右键项与快捷键并存（右键为补充通道）。
- **关闭即自动保存（无确认弹窗 · v5）**：关闭有脏改动的文件页签 → **关闭动作即触发失焦 = 静默自动保存后关闭**，**不弹任何确认**（v4 的「保存并关闭 / 放弃更改并关闭 / 取消」三择一**整个取消**）；若自动保存失败则以**非阻塞指示**呈现、页签照常关闭（不阻断关闭）。
- **外部文件变更冲突（分叉 · 唯一保留的阻塞确认）**：页签打开期间该文件被主机侧外部改动 → 弹冲突提示：**重载**（放弃本地未落盘改动、载入主机最新）/ **保留本地**（忽略外部变更、以本地为准，后续失焦自动保存以本地覆盖）/ **对比**（并排看本地与主机最新，看完仍回到冲突三选项：重载 / 保留本地 / 对比）。每个出口都回到可编辑或已重载的确定态。（此为唯一保留的阻塞式确认——涉及「本地改动 vs 外部改动」的真实数据取舍、不能静默；失焦自动保存不消解此冲突。注：此「冲突三选项」与已删除的「关闭未保存三择一」是不同概念。）
- **只读兜底（分叉）**：图片 / 二进制 / 未识别 → 只读呈现，无编辑 / 保存 / 脏态；说明该类型无法编辑。
- **换选中 → 聚焦或新开**：目录树换选中另一文件 → 若该文件已开则聚焦其页签、否则新开一个文件页签（同一文件去重）。
- **切树根不删页签（分叉）**：目录树切换树根（换目录）→ **已打开的文件页签全部保留**、内容不变；仅目录树的展示根变了。
- **联动 · 页签 ↔ 树（钉死语义）**：**切到 / 聚焦某文件页签**时，本模块**命令目录树定位到该文件**，按该文件与当前树根的关系分三种确定行为——
  1. **该文件属于当前树根范围、且其所在目录不等于当前树根**（是树根的更深层后代）→ 目录树**保持当前树根不变**，在当前树内把该文件 **reveal** 出来：逐层展开其所有祖先目录 + 滚动使其可见 + 选中该文件行。
  2. **该文件所在目录恰为当前树根**（文件是树根的直接子项、已在首层可见）→ 目录树**不改树根、不改展开结构**（无祖先可展开），仅**选中**该文件行——此即「树根不动」。
  3. **该文件不属于当前树根范围**（不是当前树根的后代）→ 目录树借「file-tree 公共能力（接受外部目录输入）」**以该文件所在目录为新树根重展示**，并选中该文件行。
  - **反向联动**：目录树选中文件 → 打开 / 聚焦对应文件页签（见「打开文件·消费目录树选中」）。
  - **边界**：以上「reveal / 重根 / 选中」的呈现由 **file-tree 负责**，本模块只**发起命令**，**不重画树**。
- **分叉 · 加载**：读取文件中 → 加载指示。**分叉 · 错误**：无法读取该文件（无权限 / 已删除等）→ 提示 + **重试**。**分叉 · 离线**：主机断连 → 见 §3.5 / sRS9。
- **右键**：见 §4 sRS4 / sRS5 / sRS7（三套按内容区）。**边界**：文件页签**不含目录树、不做目录树写操作**（归 file-tree）。

### 3.3 放大缩小

- **整面板放大 / 还原**：停靠态点 tab 条 ⤢ → 右侧侧边栏**扩展占满对话区的空间**（左栏保留、目录树按其自身显隐保留）；图标变 ⤡ → 点 ⤡ 还原回停靠列（恢复对话区）。旁边的**收起**仍可把整列收起、右栏 toggle 交还壳。**放大统一走整面板——文件内容区不另设放大 / 全屏按钮**；放大态下文件**照常实时编辑 / 失焦自动保存 / 查找替换 / 快捷键**。

### 3.4 对话承接 & 断链兑现

- **文档地址 → 文件页签（断链③）**：对话页发起跳转（本需求不画对话侧）→ 右侧侧边栏**承接**：打开 / 聚焦**文件页签**并显示该文件；若右栏收起则跳转**顺带展开**右栏（沿用壳「展开右侧边栏」公共壳行为）。承接侧本轮就位；发起侧交互属 conversation-page。
- **目录树选中 → 文件页签（断链①）**：目录树选中某文件 → 打开 / 聚焦对应文件页签（见 §3.2）；两端齐活、端到端全通。
- **输出本地链接 → 文件页签（断链②）**：任何输出里点本地路径 → 落点即文件页签（本轮就位）；触发侧（终端可点路径）随终端 deferred，落地即接通、承接侧无需新增。
- **改动 / diff → 代码审核（顺延后续）**：因代码审核内部本轮不做，对话点「改动 / diff」跳到代码审核的映射**本轮顺延后续**（不静默丢弃，待代码审核落地兑现）。

### 3.5 面板级聚合态

- **面板级离线（聚合）**：主机断连 → **整面板所有页签**统一冻结当前内容 + 顶部一条重连横幅；主机恢复后各页签按各自能力恢复。出口 = 重连。
- **面板级加载（聚合）**：面板打开 / 页签恢复 / 首次建立工作面板中 → 面板级加载指示；完成落内容，失败转面板级错误。
- **面板级错误（聚合）**：无法建立工作面板（罕见的面板级失败）→ 提示 + **重试**。
- **面板级能力门（聚合 · 更新主机·不降级）**：主机版本过低 / 缺工作面板或文件读写能力 → 显「更新主机以使用工作面板」+「查看如何更新」引导升级；**不提供降级 / 模拟路径**。出口 = 升级主机后能力就绪即可用。
- **面板级空（聚合）** = **启动器默认态**（无任何已打开页签）= sRS1；出口 = 点启动器可用项（文件）开页签。
- **与文件内容态区分**：面板级空（无页签）≠ 文件空（未选文件「选择一个文件」）；面板级离线（整面板冻结 + 横幅）与文件页签自身的加载 / 错误须区分；某页签态异常不代表面板级异常。

## 4. 屏与全状态

> 逐屏对应 [ui.html](./ui.html) 锚点 `sRS*`（与 UI 设计师约定：**sRS 前缀，从 sRS1 起，共 9 屏**，requirement 每状态 ↔ 屏 1:1）。每屏完整交互态以 ui.html 逐屏「交互注解块」（布局 / 状态 / 右键菜单 / 点击效果）为准。布局维度统一：**桌面 only；移动 / 浏览器紧凑态 deferred**；每屏浅 / 深主题均适配。

- **sRS1 启动器默认态 · 竖排五类入口** `ui.html#sRS1`：右侧侧边栏展开且无已打开页签的落地态——**竖排五项**（**仅文件可用**；对话 / 浏览器 / 代码审核 / 终端禁用 + 「后续」标，各带快捷键提示）；顶部**仅 ⤢ 放大 + 收起**（无 tab 条、无「新选项卡 +」）。
  - 状态：默认（五项竖排、一项可用四项禁用）/ hover（文件行底色变浅）/ 禁用（四行灰化 + 「后续」标、不可点）/ 加载（面板恢复中，见 sRS9）/ 离线（见 sRS9）/ 浅深主题。
  - 可点元素：**文件行**（点 / ⌘P → 开文件页签；无选中则落空态「选择一个文件」，见 sRS4 / sRS7 空；tab 条出现）；**⤢**（整面板放大占满对话区，见 sRS8）；**收起**（收起整列、交还壳）；对话 / 浏览器 / 代码审核 / 终端四行禁用不可点。

## 5. 边界与依赖

### 与既有设计的关系（分工边界）

- **建立在壳子之上（壳行为一概不重定义）**：本需求填的是壳子 `2026-06-28-shell` §7.d 第 22–25 条标注的右侧侧边栏空容器。右栏 toggle（顶栏 · 默认收起）、宽度（默认 480 / min 320 / max 800）、相邻手柄拖拽改宽、按工作区记忆宽度、需 active workspace、**「展开右侧边栏」公共壳行为**——**全部是壳行为**（壳子 + `2026-06-27-codepilot-layout`），**本需求沿用不改**。本需求只关心「容器里装什么、怎么用」。
- **与目录树（file-tree 模块）边界（断链① 端到端全通）**：目录树只做「定位 + 选中 + 搜索 + 切目录 + 图标 + 树内右键 + 内联新建重命名删除」，是**独立的第 4 区**；**文件内容富预览与编辑属本需求的文件页签**。文件页签**不重画树**——它**消费** file-tree 输出的「选中文件」，并**命令** file-tree 公共能力执行 **reveal / 重根 / 选中**（file-tree §2⑧：目录树能力对外开放为公共能力、接受「外部指定的目录」作为输入）。**file-tree 模块已落地发货**，其「选中文件供后续在右侧边栏文件页签打开复用」的账，本轮由文件页签承接兑现——两端齐活。文件的写操作（新建 / 重命名 / 删除 / 剪切复制粘贴）归 file-tree，不在本页签。
- **与对话页（conversation-page）联动（断链③ 承接侧就位）**：对话页点击文档地址会**发起跳转到右栏**——**对话页只负责「发起跳转这一步」**（conversation-page §2「点击代码 / 文件 / 改动等跳到右栏的目标内容不在本需求，只负责发起跳转」）；**右侧侧边栏负责「被跳转后打开 / 聚焦文件页签并显示该文件」这一态**。本需求**不画对话侧交互、不画 composer 渲染**。（「改动 / diff → 代码审核」映射因代码审核内部本轮不做而顺延后续。）
- **与终端（terminal · deferred）边界（断链② 承接侧就位）**：终端输出里的本地路径「点击 → 打开为文件」的**落点是文件页签**——本轮**落点就位**；**触发侧（终端里可点的高亮路径）随终端 deferred**。终端后续落地时点其路径即在此打开 / 聚焦文件页签、承接侧无需新增（见 §2·E / §3.4 断链②）。
- **与 codepilot-layout（主题）**：走 **codePilot** 主题（GitHub 浅色默认 + 深色），与外壳同一套主题来源；**主题取值 / 浅深切换机制 / 入口归 codepilot-layout**，本需求不定义、不自带冲突配色。

### 平台与能力门（用 WHAT 描述 · 不点名 RPC / 接口）

- **桌面 only**；移动 / 浏览器紧凑态 deferred。
- **能力门 · 读取文件内容（必需）**：依赖「主机能读出某文件内容供查看」的能力。不可用 → 文件页签走加载 / 错误 / 离线态；能力整体缺失 → 面板级能力门「更新主机」。
- **能力门 · 写入文件内容（必需）**：依赖「主机能把编辑后的文件内容写回」的能力。不可用 → **失焦自动保存走失败态（非阻塞指示、无手动重试按钮，下次失焦再试）**；写能力整体缺失 → 文件页签退化为只读并说明。
- **能力门 · 外部变更感知（可选）**：依赖「主机能感知某文件在打开期间被外部改动」的能力。不可用 → 不弹冲突提示（不影响查看 / 编辑 / 失焦自动保存主路径）。
- **能力门 · 目录树定位联动（可选）**：依赖 file-tree 公共能力「接受外部目录输入 / 定位到指定文件（reveal 或重根）」。不可用 → 文件页签仍可查看 / 编辑，仅树联动不生效。
- **随后续页签顺延的能力门（deferred）**：终端会话双向 IO / 尺寸变更（终端）、内嵌网页渲染 / 网页截图与元素上下文（浏览器）、加入对话 composer（浏览器）、工作区 diff / Stage·Revert（代码审核）、侧边会话（对话）——**均随对应 deferred 页签顺延，本轮不定义**。
- 以上均为**能力门**：能力在则功能可用，能力缺则相应路径给出可恢复的提示态，**不写降级版另一套实现**。能力门的具体形态（协议 / RPC / 能力标志）属架构师 P2，本需求不点名。
- **无老用户 / 迁移**（fork 未上线）：不写存量兼容。

## 6. 验收标准（逐条可判定 · 能 / 否）

**页签框架 · 启动器 · 呈现项（sRS1）**

1. 右侧侧边栏展开且**无任何已打开页签**时，**能**落**启动器列表**（竖排五类），且顶部**仅有 ⤢ 放大 + 收起**、**无 tab 条、无「新选项卡 +」**。
2. 启动器**恰呈现五类**（对话 / 浏览器 / 代码审核 / 终端 / 文件），其中**仅「文件」为可用项**，**对话 / 浏览器 / 代码审核 / 终端四行为禁用 + 「后续」标**、不可点。
3. 点启动器**文件**（或按其快捷键 ⌘P）**能**打开文件页签（无选中则落空态「选择一个文件」），此后 tab 条**能**出现（含「新选项卡 +」）；点四个禁用项**无**打开效果。

**页签框架 · 五类体系 + 实例规则（sRS2）**

4. 文档**明确声明五类页签**（对话 / 浏览器 / 代码审核 / 终端 / 文件）及其实例规则：**代码审核 = 单实例**，**文件 / 对话 / 浏览器 / 终端 = 多实例**；**本轮仅文件可被真正打开、可同时开多个文件页签**。
5. **文件页签按「同一文件只开一个」去重**（重复打开同一文件 = 聚焦既有页签、不新开）；同类多个文件页签**能**用**文件名**区分，标识过长**能**截断省略。
6. tab 头**能**呈现 Codex 观感：**图标 + 文字页签**、**活跃页签 = 胶囊式高亮**（**非**蓝下划线）、**页签间有细分隔**、**tab 条末尾有「新选项卡 +」**、**右上有 ⤢ 放大 + 收起**；tab 上**能**显活动状态点（本轮由文件驱动，如脏点）。
7. 新框架下**无固定首位、无不可关页签**——**所有已打开页签均可关**；**活跃页签常显 ✕、非活跃页签 hover 显 ✕**（VSCode 式）；**关有脏改动的文件页签 = 失焦自动保存后关闭、无任何确认弹窗**（v4 的关闭三择一确认已删）。

**页签框架 · 管理交互（sRS3）**

8. 「新选项卡 +」点开的下拉**恰为五类**（**仅文件可用**；对话 / 浏览器 / 代码审核 / 终端禁用 + 后续），各带快捷键提示；选文件**能**追加文件页签；快捷键**能**等价触发。
9. 页签 ✕ **能**按 VSCode 式呈现（**活跃常显、非活跃 hover 显**；脏页签未失焦时 ✕ 位可显脏 ●、hover 转 ✕），点它关该页签（关 = 仅布局、可重开）；关**有脏改动的文件页签** = **静默失焦自动保存后关、无确认弹窗**。
10. 页签**能**左右拖拽调序，拖动时**有**放置指示线；**无**固定首位约束。
11. 页签右键**能**弹出菜单，且**恰为 3 项**：关闭页签 / 关闭其它页签 / 关闭全部页签，各项点击效果如 §3.1；关含脏改动的文件页签时**逐一静默自动保存后关、无确认弹窗**。
12. **所有页签关闭后能**回到启动器默认态（sRS1）——新框架下此出口**完整可达**。

**放大缩小（sRS8）**

13. tab 条 ⤢ **能**把整面板**放大占满对话区**（左栏保留、目录树按其显隐保留），⤡ **能**还原回停靠列；其旁「收起」仍**能**把整列收起、交还壳。
14. 文件内容区**不设**放大 / 全屏按钮——**放大统一走整面板**（tab 条 ⤢，见 item 13）；「单页签放大 / per-tab ⤢」概念全文**已删除、无残留**；整面板放大态下文件**能**照常实时编辑 / 失焦自动保存 / 查找替换 / 快捷键。

**文件页签 · 类 VSCode 可编辑（本轮核心 · sRS4/5/6/7）**

15. 文件页签**能**按类型呈现：代码 / 文本 = 查看 + 语法高亮 + **编辑**；Markdown = **编辑 / 预览双态**可切换；图片 = **查看（不可编辑）**；未识别 / 二进制 = **只读兜底**（说明无法编辑）。
16. 文件页签**能**消费目录树输出的「选中文件」并显示；**能**承接对话「文档地址」跳转打开并显示该文件；**能**作为输出本地链接「点路径 → 打开文件」的落点；**从启动器 / 新选项卡开文件而无选中时能**显「选择一个文件」空态。
17. **同一文件重复打开 = 聚焦既有页签**、不新开；不同文件各一个页签、可多开。
18. 目录树**切换树根（换目录）不删除**已打开的文件页签。
19. 文件被改动尚未落盘时**能**显**脏 ●**（编辑中未落盘的临时指示）；**失焦即自动保存**（切页签 / 切窗口 / 点内容区外 / 关页签均触发），保存成功后脏 ● 清；**无手动保存按钮 / ⌘S 手动保存 / 保存四态**；**自动保存失败**（如权限被拒）以**非阻塞指示**呈现、**不弹阻塞框、不给手动重试按钮**（续编下次失焦再试）。
20. 关闭有脏改动的文件页签时**无任何确认弹窗**——关闭 = 失焦 = **静默自动保存后关闭**（v4 的「保存并关闭 / 放弃更改并关闭 / 取消」三择一确认**已整个取消**）；若自动保存失败则以非阻塞指示呈现、页签照常关闭。
21. 文件在打开期间被外部改动时**能**弹冲突提示，给出口：重载 / 保留本地 / 对比，每个出口都回到确定态。
22. 文件页签**能**覆盖全态：默认 / 编辑中 / 脏（编辑中未落盘临时 ●）/ 失焦自动保存中·已自动保存·自动保存失败（非阻塞）/ 查找替换浮层 / 空 / 加载 / 错误（+重试）/ 冲突 / 只读兜底 / 离线，每个非常规态**有**定义出口。

**文件页签 · 页签 ↔ 树 reveal 语义（钉死·可判定 · sRS6）**

23. 切到 / 聚焦某文件页签时，目录树**能**按三分支确定行为定位该文件：① 文件是当前树根的**更深层后代** → 当前树内 reveal（展开祖先 + 滚动 + 选中），**不改树根**；② 文件所在目录**恰为当前树根**（直接子项）→ **树根不动、不改展开结构**，仅选中该文件行；③ 文件**不属于当前树根范围** → 以其所在目录为**新树根重展示** + 选中。
24. 反向：目录树选中文件**能**打开 / 聚焦对应文件页签；文档**明确**此联动是**命令 file-tree 公共能力执行定位**，本模块**不重画树**。

**文件页签 · 右键（三套·可判定 · sRS4/5）**

25. 文件页签**能**按内容区弹三套右键，项数严格：**代码 / 文本编辑区 9 项**（剪切 / 复制 / 粘贴 / 全选 / **查找 / 替换** / 复制文件路径 / 在目录树中定位 / 在 Finder 中显示——**v5 已将「保存 / 还原此文件」换为「查找 / 替换」**，仍 9 项，见 §8·v5-Y）；**Markdown 预览区 5 项**（复制选中 / 复制文件路径 / 在目录树中定位 / 在 Finder 中显示 / 切到编辑）；**图片查看区 4 项**（复制图片 / 复制文件路径 / 在目录树中定位 / 在 Finder 中显示）；**目录树写操作（新建 / 重命名 / 删除等）不在本页签任何右键里**。

**三条断链兑现（可判定）**

26. 文档**明确**断链① 目录树点文件 → 文件页签：**触发侧 file-tree 已发货 + 承接侧文件页签本轮真实 = 端到端全通**，sRS6 有演示。
27. 文档**明确**断链② 输出本地链接（终端等）点路径 → 文件页签：**承接侧（落点）本轮就位、触发侧随终端 deferred**；v3 的 v3-G「落点缺失」在本轮因文件页签落地而翻转为「落点就位」。

**面板级聚合态（sRS9）**

**deferred 声明（不静默丢弃）**

**主题 · 平台 · 快捷键 · 边界**

## 7. 发散思考建议项（单列 · 每条「建议项 · 待董事长闸 1 采纳」+ 论证 · 与必做范围明确隔离）

> 以下**均为建议项、不在 §2/§4/§6 的必做范围内**，探索文件类工作面板的真实使用痛点，供董事长在闸 1 决定是否纳入。**未获采纳前不进入必做范围**；采纳的才增补进相应屏与验收。（v2 的两条浏览器建议项——浏览器控制台·网络速览 / 一键复制元素上下文——**随浏览器 deferred，本轮不列**。）

> **注（v5）**：v4 的建议项①「文件内查找 / 替换」**已被董事长闸 1 采纳、升为必做**（见 §2·B / §3.2 / §4 sRS4 / §6 item 37），**从本建议项清单移除**；以下为其余保留建议项，重新编号。

1. **建议项 · 待董事长闸 1 采纳 — 跳转到行**（点行号 / 快捷键跳到第 N 行）。**痛点**：对话 / 输出常引用「第 N 行」，用户手动滚动找行既慢又易错。**价值**：与「文档地址 / 本地链接可带行锚点」协同——对话点带行号的文档地址、点终端里带行号的路径可**直达该行**，把「打开文件」升级为「打开并定位到那一行」。**隔离**：仅文件页签内定位，不改对话 / 终端侧发起交互。
2. **建议项 · 待董事长闸 1 采纳 — 页签溢出下拉**。**痛点**：文件页签开多了会超出 tab 条宽度，被挤出可视区的页签**无法触达**（可达性黑洞）。**价值**：tab 条末尾加一个「溢出下拉」列出被隐藏页签，一点即达，保证任意多页签都可切换。**隔离**：纯框架层交互，不涉及任何页签内部。
3. **建议项 · 待董事长闸 1 采纳 — 最近关闭重开**（观感参照 ⌘⇧T）。**痛点**：误关页签（尤其正在看 / 改的文件）是高频事故，重新从目录树 / 对话找回很烦。**价值**：一键重开最近关闭的页签，是廉价、高频受益的兜底；文件页签重开还能恢复到关闭前的滚动 / 编辑现场。**隔离**：框架层，不新增页签类型。
4. **建议项 · 待董事长闸 1 采纳 — 键盘循环切换页签**（观感参照 ⌃Tab / ⌘⇧[ ]）。**痛点**：页签多时用鼠标逐个点切换慢；键盘流用户想不摸鼠标切页签。**价值**：键盘正 / 反向循环切换 + 触发树联动，提升重度多页签用户的流畅度。**隔离**：纯键位，落值与全局键位裁决可归快捷键设置模块。
5. **建议项 · 待董事长闸 1 采纳 — 会话级持久化已开页签**。**痛点**：重开面板 / 刷新客户端后，之前开的一组文件页签全没了，用户要重建整个工作区现场。**价值**：按工作区记住「上次开了哪些文件页签、哪个活跃」，重开即恢复现场，与壳「按工作区记忆宽度」一脉相承。**隔离**：状态记忆策略较重，故列建议而非必做；采纳后需定义「记住什么、恢复到何种程度（是否恢复未保存草稿）」。
6. **建议项 · 待董事长闸 1 采纳 — 右侧代码小地图 minimap**（观感参照 VSCode）。**痛点**：长文件里滚动定位缺乏全貌感，用户不知道「自己在文件哪一段、改动 / 命中散在何处」。**价值**：文件页签右侧一条缩略全貌，改动行 / 查找命中在小地图上标记，点即快速跳转。**隔离**：仅文件页签内视觉附件，与必做的高亮 / 编辑分离，虚线隔离不混入本轮。
