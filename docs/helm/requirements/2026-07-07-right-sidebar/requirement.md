## 1. 目标 & 用户价值

**一句话目标**：把对话页右侧的**右侧边栏空容器**填成一个**多页签工作面板**——展开后默认落在**启动器列表**（竖排：审查 / 终端 / 浏览器 / 文件），可打开这四类页签，具备**新建 + / 悬浮关闭 ✕ / 拖拽调序 / 放大缩小 ⤢** 的完整页签管理；其中**审查 diff（Stage / Revert / 行评论）与文件预览做到全态**，**终端与浏览器做到「可见 surface」全态**（深层内部标后续）；并**承接对话页「点改动→审查、点文件→文件」的跳转打开**、**消费目录树输出的「选中文件」**。

**用户为什么需要它**：

- **为什么要工作面板？** 用户在对话里让 agent 干活，干完需要一个**固定的操作台**看结果——审查 agent 改了什么、跑终端看输出、开浏览器看页面效果、翻文件看内容。空容器没有任何用处；工作面板是「对话之外，动手看东西的地方」。
- **为什么要多页签而不是单一视图？** 用户常常**同时**要看 diff + 盯终端输出 + 翻一个文件；多页签让这些内容**并存、一键切换**，不必来回开关、丢失现场。
- **为什么打开默认是启动器列表？** 面板刚展开时用户还没决定看什么。一张**竖排入口列表**（审查 / 终端 / 浏览器 / 文件，各带快捷键）让他一眼选，零猜测、零学习成本。
- **为什么审查是核心、固定第一？**「agent 改代码 → 人审查 → Stage / Revert / 评论」是这个产品的**主循环**。审查是最高频、价值最高的面，**固定排第一**让它永远一键可达、不被别的页签挤走。
- **为什么审查 + 文件做全态、终端 + 浏览器只做可见 surface？**（结论先给，详细论证见 §2）审查是主循环、文件是「目录树 + 对话跳转」的**共同落点**（两个兄弟模块都把「富预览的账」记到这个页签），这两个不做全就**断链**；终端 / 浏览器的**可见 surface**（看输出 / 看页面）已交付日常价值，其**深层内部**（多会话管理 / 历史书签 / devtools 等）是可分离的重基建，先不做以免**过早建错、返工**。
- **为什么要放大缩小？** diff / 终端 / 浏览器 / 文件有时需要**更大视野**细看：整面板放大占满中区、单页签放大聚焦一处——都是真实的「看得更清」诉求。
- **为什么要承接对话跳转 + 消费目录树？** 用户在对话里点了某段改动 / 某个文件，期望**立刻在右边看到**；在目录树里选中某文件也一样。右侧边栏是这些跳转的**统一落点**——不承接，跳转就无处可去、目录树的「选中」就没有下文。

## 2. 范围

> 董事长允许「页签框架 + 部分页签内容全态、其余页签占位标后续」的分阶段切法（参照 codepilot-layout 分阶段先例）；下方**做 / 不做逐条写死**，并对四页签的**深度切分**显式论证。

### 做

#### A. 页签框架能力（全做——这是所有页签挂靠的骨架，不能半建）

- **① 打开默认 = 启动器列表**：右侧边栏展开且**无任何已打开页签**时，落地态为**竖排启动器**（审查 / 终端 / 浏览器 / 文件，各带快捷键提示）；此时顶部**仅有 ⤢ 放大 + 收起**，**还没有 tab 页签条、也没有「新选项卡 +」**。点某行 → 打开对应类型页签、tab 条随之出现。
- **② 多页签**：可同时存在多个页签并一键切换；**审查一旦处于打开状态即固定排第一个**（不可被拖到别的位置、不出现在「新选项卡 +」下拉里——因为它是常驻项而非「新增」项）。
- **③ 新选项卡 +**：tab 条上有「新选项卡 +」，点开一个**下拉**（终端 / 浏览器 / 文件三项，各带快捷键），选一个即在 tab 条追加对应类型页签；**快捷键等价触发**（无需先点 +）。
- **④ 悬浮关闭 ✕**：页签**悬浮时**行尾浮出 ✕，点它关闭该页签。终端 / 浏览器 / 文件页签**可关**（关闭 = 仅布局层移除，可重开）；**审查页签默认不可关**（其 ✕ 置灰、不可点）——此项 HS 标为「开放项待董事长定」，本需求**默认取「审查不可关」**并列入 §7 开放问题。
- **⑤ 拖拽调序**：页签可**左右拖拽调序**，拖动时显**放置指示线**；审查固定第一、不参与被拖到后面。
- **⑥ 页签右键菜单（3 项）**：在页签上右键 → **关闭页签 / 关闭其它 / 关闭全部（保留审查）**。
- **⑦ 放大缩小 ⤢**：
  - **整面板放大**：tab 条右侧 ⤢ → 右侧边栏**扩展占满中区（对话区的空间）**、**左栏保留**；**还原 ⤡** 回到停靠态。
  - **单页签放大**：每个页签内容右上角有 ⤢ → **单独放大该页签内容**（审查 diff / 终端 / 浏览器 / 文件各自可放大），再 ⤡ 还原。
- **⑧ 关掉全部页签 → 回启动器默认态**：所有页签关闭后回到 ① 的启动器列表（「新选项卡 +」的类型选择也回到这张列表的语义）。**注**：在「审查不可关」默认下，审查一经打开即常驻，面板至少常驻审查页签，因此「关全部 → 回裸启动器」这条完整出口的**可达性取决于开放问题 #1**（审查是否可关）——见 §3 与 §7。

#### B. 审查页签（全态全做）

- 内容 = **当前工作区 Git diff**：文件标题 + 增删统计；行号 + 增删分色；底部 **Stage / Revert / 行评论**。
- **右键（两处）**：**diff 行右键（2 项）** 复制行 / 添加行评论；**文件标题右键（3 项）** Stage 文件 / Revert 文件 / 在 Finder 中显示。
- **全态**：默认 / hover（行尾浮出行评论入口）/ 运行（代理改动中 diff 增量刷新）/ 禁用（**非 Git 工作区** Stage·Revert 置灰）/ 空（**没有改动**）/ 加载（拉取 diff）/ 错误（**Git 读取失败** + 重试）/ 离线（主机断连冻结 + 重连，见面板级聚合 sRS7）。

#### C. 文件页签（全态全做 · 预览面 · 只读）

- 内容 = **预览面**：**消费目录树输出的「选中文件」**、或**承接对话「点文件」跳转**打开；**富可读预览**——代码高亮预览 / 图片预览 / 未识别·二进制兜底。
- **明确不重画树**：文件页签**不含目录树**（目录树是独立的第 4 区、由 file-tree 模块负责），它只是**消费选中的一个预览面**。
- **本轮只读预览**；**内联编辑（编辑 = 写文件）标后续**。
- **全态**：默认（渲染选中文件预览）/ 空（**未选文件 →「选择一个文件」占位**）/ 加载（读取该文件）/ 错误（**无法读取该文件** + 重试）/ 离线（见 sRS7）。

#### D. 终端页签（可见 surface 全态）

- 内容 = **等宽输出 + 光标 + 流式追加**；**只作右面板页签、不做中区底部停靠**（解决旧版底部停靠的不一致）。
- **右键（3 项）**：复制 / 粘贴 / 清屏。
- **态**：默认 / 运行（流式追加）/ 空（**无历史停在提示符**）/ 加载（连接中）/ 错误（**非 0 退出码红字**）/ 离线（冻结 + 重连，见 sRS7）。

#### E. 浏览器页签（可见 surface 全态）

- 内容 = **地址栏 ← → ⟳ + URL + 前往** + **页面内嵌预览**；空态**「开始浏览」**。
- **右键（3 项）**：后退 / 刷新 / 复制链接。
- **态**：默认 / 运行（加载指示）/ 空（「开始浏览」占位）/ 错误（**页面加载失败** + 重试）/ 离线（见 sRS7）。

#### F. 主题

- 走 **codePilot** 主题（GitHub 浅色默认 + 深色一并适配），与外壳**同一套主题来源**，不自带冲突配色。（主题取值 / 切换机制归 codepilot-layout，本需求不定义。）

#### G. 平台

- **桌面 only**；移动 / 浏览器紧凑态 deferred。

### 四页签深度切分 · 显式论证

> 为什么**审查 + 文件做全态**、**终端 + 浏览器只做可见 surface（深层内部后续）**？从三个角度论证。

**① 用户价值角度**

- **审查（全态）**：这是产品**主循环**的终点——agent 改完代码，人必须在这里审查 diff 并 Stage / Revert / 评论。它是**最高频、最高价值**的面；缺一个态（如「运行中增量刷新」或「非 Git 禁用」）用户的审查动作就会卡住。
- **文件（全态·只读）**：这是「看清一个文件的内容」的落点。目录树只做「定位 + 选中」，对话只做「发起跳转」——两者的**下文都在这里**。缺文件预览全态，用户点了树 / 点了对话里的文件都**没有反应**。而**内联编辑**属于另一类诉求：审查为核心的工作流里，用户改代码是**让 agent 改**，很少在这里手敲；`只读预览` 已覆盖 95% 的「看文件」诉求，编辑是可分离的增量（YAGNI）。
- **终端 / 浏览器（可见 surface）**：用户对这两者的**日常诉求就是「看」**——看 agent 跑测试的输出、看它建的预览页效果，加上最基本的复制 / 粘贴 / 清屏、地址栏前进后退刷新。**可见 surface 已经把日常价值交足**；多并发会话、历史书签、devtools 这些是**少数人偶尔才要**的深水区。

**② 分阶段避免返工角度**

- 审查 diff 与文件只读预览的**契约稳定**（工作区 diff / 读一个文件渲染），做全**不会返工**。
- 终端 / 浏览器的**可见 surface 是稳定外壳**，深层内部（会话模型 / 尺寸重排 / scrollback / 历史 / devtools）是**在同一 surface 下的增量**——现在做全 surface、以后补深层，**不推翻 surface**；反过来，现在就把会话模型 / 历史模型定死，很可能在没摸清真实用法前**建错、返工**。这正是 codepilot-layout「先立形、再填细节」的分阶段铁律。

**③ 与兄弟模块边界角度**

- **文件页签必须做全**，否则 **file-tree 模块的承诺落空**：file-tree §2「不做」明写「文件内容富预览属右侧边栏文件页签」——这笔账记在本页签，本轮兑现，边界才闭合。
- **审查独立于目录树**：审查消费的是工作区 Git 改动，不与目录树（定位 / 选中）重叠。
- **终端不做底部停靠**是一条**明确的边界纠偏**：旧版终端在中区底部停靠造成不一致，本轮统一收进右面板页签。
- 深层内部后续，**不侵占**兄弟模块，也不制造跨模块的半成品。

### 不做（逐条写死 · 防范围蔓延 · 每条后续项不得静默丢弃）

- **不重定义壳行为**：右栏 toggle（顶栏、默认收起）、宽度（默认 480 / min 320 / max 800）、相邻手柄拖拽改宽、按工作区记忆宽度、需 active workspace 才可用——**全部沿用壳子 `2026-06-28-shell` 与 `2026-06-27-codepilot-layout`，本需求一概不改、不重写**。本需求只关心容器内部内容。
- **不做目录树**：定位 / 选中 / 搜索 / 切目录 / 文件图标 / 树内右键 / 内联新建重命名——**属 file-tree 模块**（独立第 4 区）；**文件页签只消费其「选中」，不重画树**。
- **不做终端深层内部**（**后续**）：多并发 shell 会话管理 / 尺寸重排 reflow / scrollback 性能 / 终端活动指示。
- **不做浏览器深层内部**（**后续**）：历史 / 书签 / devtools / 页内多标签。
- **不做文件页签内联编辑**（**后续**）：编辑 = 写文件；本轮只读预览。
- **不做对话侧「发起跳转」的交互**（属 `2026-06-28-conversation-page`）：在对话里哪里点、怎么触发由对话页负责；本需求**只承接「被跳转打开」这一态**。
- **不定义主题取值 / 切换机制 / 入口**（归 codepilot-layout）。
- **不做移动 / 浏览器紧凑态**（**deferred**）。
- **不涉及协议 / RPC / 能力标志**：纯前端设计需求；能力门是架构师 P2 的事，本 WHAT 层只说「依赖某能力」不点名。

## 3. 流程（端到端）

> 每态有入口、有出口，无死胡同。覆盖正常路径 + 分叉（空 / 加载 / 错误 / 离线 / 被对话跳转打开 / 关全部回启动器 / 放大还原）。

### 3.1 页签框架

- **展开右侧边栏 → 落启动器默认态**：用户点顶栏右栏 toggle 展开右侧边栏（壳行为）→ 若**无任何已打开页签**，落**启动器列表**（审查 / 终端 / 浏览器 / 文件，各带快捷键）；顶部仅 ⤢ + 收起。出口 = 点任一行开页签 / ⤢ 放大 / 收起交还壳。
- **从启动器开页签**：点某行（或按其快捷键）→ 打开对应类型页签、tab 条出现（含「新选项卡 +」）；**审查一旦打开即固定排第一**。出口 = 切页签 / 新建 / 关闭 / 调序 / 放大。
- **新选项卡 +**：点 tab 条「新选项卡 +」→ 弹下拉【终端 / 浏览器 / 文件】→ 选一项即追加对应页签并聚焦它；快捷键等价触发。点下拉外 / Esc → 关下拉、不新增。
- **切页签**：点某页签 → 切到其内容；当前页签高亮。
- **悬浮关闭 ✕**：页签悬浮 → 行尾浮出 ✕ → 点它关该页签（终端 / 浏览器 / 文件可关，关 = 仅布局、可重开）。**审查页签 ✕ 置灰、不可点**（默认不可关）。
- **拖拽调序**：拖某页签左右移动 → 显放置指示线 → 松开即在指示位落位；审查固定第一、不被拖到其后。
- **页签右键（3 项）**：右键某页签 → **关闭页签**（关该页签）/ **关闭其它**（关除它外全部可关页签）/ **关闭全部（保留审查）**（关掉除审查外全部）。点项即执行并关菜单；点菜单外 / Esc → 关菜单不执行。
- **关掉全部页签 → 回启动器**：当**所有页签都被关闭**时 → 回启动器默认态。**分叉 · 审查不可关（默认）**：审查一经打开即常驻，「关闭全部（保留审查）」只会留下审查，面板不会自动回到裸启动器；**回裸启动器只在「审查尚未被打开过」或「开放问题 #1 采纳审查可关」时成立**——两解本需求都写清，默认取前者语义。

### 3.2 审查页签

- **打开审查**：从启动器点「审查」/ 从对话点某改动或 diff 跳转 → 打开审查页签（固定第一）并列出当前工作区 diff（文件标题 + 增删统计 + 行号 + 增删分色）。
- **hover 行评论**：悬浮某 diff 行 → 行尾浮出「+ 行评论」入口 → 点它在该行添加评论。
- **Stage / Revert**：点底部 Stage → 暂存改动；点 Revert → 回退改动；改后 diff 相应刷新。
- **文件标题右键 / diff 行右键**：见 §4 sRS3（Stage 文件 / Revert 文件 / 在 Finder 中显示；复制行 / 添加行评论）。
- **分叉 · 运行**：代理改动进行中 → diff **增量刷新**（文件 / 行实时累加），无需手动刷新。
- **分叉 · 非 Git 工作区（禁用）**：当前工作区非 Git → Stage / Revert **置灰**，diff 区给出说明。
- **分叉 · 空**：无改动 → 居中显「没有改动」。出口 = 待 agent 产生改动 / 切页签。
- **分叉 · 加载**：拉取 diff 中 → 行级加载指示。
- **分叉 · 错误**：Git 读取失败 → 面板内提示（红边）+ **重试**。点重试 → 重新拉取。
- **分叉 · 离线**：主机断连 → 内容冻结 + 顶部重连提示（面板级，见 3.6 / sRS7）；主机恢复后重试。

### 3.3 文件页签（只读预览）

- **打开文件 · 消费目录树选中**：目录树选中某文件（file-tree 输出「选中」）→ 文件页签打开并预览该文件（代码高亮 / 图片 / 兜底之一）。
- **打开文件 · 承接对话跳转**：对话里点某文件（对话页发起跳转）→ 文件页签打开并预览**该文件**。
- **从启动器 / 新选项卡开文件页签而未有选中**：显**空态「选择一个文件」**占位。出口 = 去目录树选一个 / 对话点一个 → 回填预览。
- **换选中 → 换预览**：选中另一文件 → 预览切到新文件。
- **分叉 · 代码 / 图片 / 未识别**：代码文件 → 语法高亮只读预览；图片 → 图片预览；未识别 / 二进制 → 兜底占位（说明无法富预览）。
- **分叉 · 加载**：读取文件中 → 加载指示。
- **分叉 · 错误**：无法读取该文件（无权限 / 已删除等）→ 提示 + **重试**。
- **分叉 · 离线**：主机断连 → 见 3.6 / sRS7。
- **明确边界**：文件页签**不重画树**、**只读**（编辑后续）。

### 3.4 终端页签（可见 surface）

- **打开终端**：从启动器 / 新选项卡开终端 → 显等宽输出（有历史则回放、无历史停在提示符）。
- **运行**：命令执行中 → 输出**流式追加**；聚焦时光标闪。
- **右键（3 项）**：复制 / 粘贴 / 清屏。
- **分叉 · 空**：无历史 → 停在提示符。
- **分叉 · 加载**：连接中 → 加载指示。
- **分叉 · 错误**：非 0 退出码 → 红字提示。
- **分叉 · 离线**：主机断连 → 冻结 + 重连（见 3.6 / sRS7）。
- **边界**：终端**只作右面板页签、不做中区底部停靠**；多会话 / 尺寸重排 / scrollback / 活动指示**后续**。

### 3.5 浏览器页签（可见 surface）

- **打开浏览器**：从启动器 / 新选项卡开浏览器 → 显地址栏（← → ⟳ + URL + 前往）+ 空态「开始浏览」。
- **前往**：输入 URL → 点「前往」/ 回车 → 内嵌预览加载该页；加载中地址栏显加载指示。
- **← → ⟳**：后退 / 前进 / 刷新。
- **右键（3 项）**：后退 / 刷新 / 复制链接。
- **分叉 · 空**：未输入 → 「开始浏览」占位。
- **分叉 · 错误**：页面加载失败 → 占位 + **重试**。
- **分叉 · 离线**：主机断连 → 见 3.6 / sRS7。
- **边界**：历史 / 书签 / devtools / 页内多标签**后续**。

### 3.6 放大缩小 & 面板级聚合态

- **整面板放大 / 还原**：停靠态点 tab 条 ⤢ → 右侧边栏**扩展占满中区**（左栏保留）；图标变 ⤡ → 点 ⤡ 还原回停靠列（恢复中区）。旁边的**收起**仍可把整列收起、右栏 toggle 交还壳（位置不变）。
- **单页签放大 / 还原**：点某页签内容右上角 ⤢ → 单独放大该页签内容（审查 / 终端 / 浏览器 / 文件皆可）；再 ⤡ 还原。放大态下内容**照常实时刷新**（diff 增量 / 终端流式）。
- **被对话跳转打开（承接态）**：对话页发起跳转（本需求不画对话侧）→ 右侧边栏**承接**：
  - 点对话里某**改动 / diff** → 打开 / 切到**审查页签**并**聚焦该文件的 diff**（滚动定位到该文件）。
  - 点对话里某**文件** → 打开 / 切到**文件页签**并**预览该文件**。
  - 若右侧边栏当前收起，则跳转**顺带展开**右侧边栏（沿用壳「展开右侧边栏」这一公共壳行为，本需求不新增布局原语）。
- **面板级离线（聚合）**：主机断连 → **整面板所有页签**统一冻结当前内容 + 顶部一条重连提示；主机恢复后各页签按各自能力恢复。出口 = 重连。
- **面板级加载（聚合）**：面板打开 / 页签恢复 / 首次建立工作面板中 → 面板级加载指示；完成落内容，失败转面板级错误。
- **面板级错误（聚合）**：无法建立工作面板（罕见的面板级失败）→ 提示 + 重试。
- **面板级能力门（聚合）**：主机版本过低 / 缺工作面板能力 → 显「更新主机以使用工作面板」+「查看如何更新」引导升级；**不提供降级 / 模拟路径**（呼应 §5 能力门「不写降级版另一套实现」）。出口 = 升级主机后能力就绪即可用。
- **面板级空（聚合）** = **启动器默认态**（无任何已打开页签）——即 sRS1；出口 = 点启动器项开页签。

## 5. 边界与依赖

### 与既有设计的关系（分工边界）

- **建立在壳子之上（壳行为一概不重定义）**：本需求填的是壳子 `2026-06-28-shell` §7.d 第 22–25 条标注的右侧边栏空容器。右栏 toggle（顶栏 · 默认收起）、宽度（默认 480 / min 320 / max 800）、相邻手柄拖拽改宽、按工作区记忆宽度、需 active workspace——**全部是壳行为**（壳子 + `2026-06-27-codepilot-layout`），**本需求沿用不改**。本需求只关心「容器里装什么、怎么用」。
- **与目录树（file-tree 模块）边界**：目录树只做「定位 + 选中 + 搜索 + 切目录 + 图标 + 树内右键 + 内联新建重命名」，是**独立的第 4 区**；**文件内容富预览（代码高亮 / 图片）属本需求的文件页签**。文件页签**不重画树**——它是一个**预览面**，**消费**目录树输出的「选中文件」（file-tree 已把目录树做成「喂目录即展示」的公共能力 + 输出「选中文件」，见 file-tree §2「不做」明写「文件内容富预览属右侧边栏文件页签、不在目录树里做」）。
- **与对话页（conversation-page）联动**：对话页点击代码块 / 文件 / 改动会**发起跳转到右栏**——**对话页只负责「发起跳转这一步」**（见 conversation-page §2「点击代码 / 文件 / 改动等跳到右栏的目标内容不在本需求，只负责发起跳转」）；**右侧边栏负责「被跳转后打开对应页签并聚焦该内容」这一态**：点某文件 → 文件页签预览该文件；点某改动 / diff → 审查页签聚焦该文件的 diff。本需求**不画对话侧交互**。
- **与 codepilot-layout（主题）**：走 **codePilot** 主题（GitHub 浅色默认 + 深色），与外壳同一套主题来源；**主题取值 / 浅深切换机制 / 入口归 codepilot-layout**，本需求不定义、不自带冲突配色。

### 平台与能力门（用 WHAT 描述 · 不点名 RPC / 接口）

- **桌面 only**；移动 / 浏览器紧凑态 deferred。
- **能力门 · 工作区 Git 改动**：依赖「主机能读出当前工作区的 Git diff、并能 Stage / Revert 改动」的能力。不可用 / 主机离线 → 审查页签走加载 / 错误 / 离线 / 禁用（非 Git）态，不崩。
- **能力门 · 读取文件内容**：依赖「主机能读出某文件内容供只读预览」的能力。不可用 → 文件页签走加载 / 错误 / 离线态。
- **能力门 · 终端会话流**：依赖「主机能提供一个终端会话的输出流并接收输入」的能力。不可用 → 终端页签走加载 / 错误 / 离线态。
- **能力门 · 内嵌网页渲染**：依赖「客户端能在页签内内嵌渲染一个网页」的能力。不可用 → 浏览器页签走错误 / 离线态。
- 以上均为**能力门**：能力在则功能可用，能力缺则相应路径给出可恢复的提示态，**不写降级版另一套实现**。能力门的具体形态（协议 / RPC / 能力标志）属架构师 P2，本需求不点名。
- **无老用户 / 迁移**（fork 未上线）：不写存量兼容。

## 6. 验收标准（逐条可判定 · 能 / 否）

**页签框架 · 启动器**

1. 右侧边栏展开且**无任何已打开页签**时，**能**落**启动器列表**（竖排：审查 / 终端 / 浏览器 / 文件，各带快捷键提示），且顶部**仅有 ⤢ 放大 + 收起**、**无 tab 条、无「新选项卡 +」**。
2. 点启动器某行（或按其快捷键）**能**打开对应类型页签，此后 tab 条**能**出现（含「新选项卡 +」）。

**页签框架 · 多页签管理**

3. **能**同时存在多个页签并一键切换；**审查一旦处于打开状态即固定排第一个**，且**不出现**在「新选项卡 +」下拉里。
4. 「新选项卡 +」点开的下拉**恰为**终端 / 浏览器 / 文件三项；选一项**能**追加对应页签；快捷键**能**等价触发。
5. 页签**悬浮时能**浮出 ✕ 关闭该页签（终端 / 浏览器 / 文件可关 = 仅布局、可重开）；**审查页签 ✕ 置灰、不可点**（默认不可关）。
6. 页签**能**左右拖拽调序，拖动时**有**放置指示线；审查固定第一、**不被**拖到其后。
7. 页签右键**能**弹出菜单，且**恰为 3 项**：关闭页签 / 关闭其它 / 关闭全部（保留审查），各项点击效果如 §3.1。
8. **所有页签关闭后能**回到启动器默认态；文档**明确**「审查不可关」默认下「关全部 → 回裸启动器」的可达性**取决于开放问题 #1**（不静默丢弃该出口）。

**放大缩小**

9. tab 条 ⤢ **能**把整面板**放大占满中区（左栏保留）**，⤡ **能**还原回停靠列；其旁「收起」仍**能**把整列收起、交还壳。
10. 每个页签内容右上角 ⤢ **能**单独放大该页签内容（审查 / 终端 / 浏览器 / 文件皆可），⤡ **能**还原；放大态下内容**能**照常实时刷新。

**审查页签（全态）**

11. 审查页签**能**列出当前工作区 Git diff（文件标题 + 增删统计 + 行号 + 增删分色），底部**有** Stage / Revert / 行评论。
12. 悬浮 diff 行**能**在行尾浮出行评论入口并添加行评论；**能** Stage / Revert 改动并相应刷新。
13. diff 行右键**恰为 2 项**（复制行 / 添加行评论）；文件标题右键**恰为 3 项**（Stage 文件 / Revert 文件 / 在 Finder 中显示）。
14. 审查页签**能**覆盖全态：默认 / hover（行评论）/ 运行（**代理改动中 diff 增量刷新**）/ 禁用（**非 Git 工作区 Stage·Revert 置灰**）/ 空（**没有改动**）/ 加载（拉取 diff）/ 错误（**Git 读取失败** + 重试）/ 离线（冻结 + 重连），每个非常规态**有**定义出口。

**文件页签（全态 · 只读预览）**

15. 文件页签**能**消费目录树输出的「选中文件」并预览；**能**承接对话「点文件」跳转打开并预览该文件。
16. 文件页签**能**做代码高亮预览 / 图片预览 / 未识别·二进制兜底；**未选文件时能**显「选择一个文件」空态。
17. 文件页签**能**覆盖：默认 / 空（未选）/ 加载 / 错误（**无法读取该文件** + 重试）/ 离线，每个非常规态**有**定义出口。
18. 文档**明确**：文件页签**不重画树**（只消费选中）、**本轮只读**、**内联编辑标后续**（不静默丢弃）。
    18a. 文件预览**能**弹出右键——代码预览 3 项（复制选中文本 / 复制文件路径 / 在 Finder 中显示）、图片预览 3 项（复制图片 / 复制文件路径 / 在 Finder 中显示）；目录树相关右键归目录树模块、**不在本预览面**。

**终端页签（可见 surface 全态）**

19. 终端页签**能**显等宽输出 + 光标 + 流式追加；**只作右面板页签、不做中区底部停靠**。
20. 终端右键**恰为 3 项**（复制 / 粘贴 / 清屏）；**能**覆盖：默认 / 运行（流式）/ 空（无历史停提示符）/ 加载（连接中）/ 错误（**非 0 退出码红字**）/ 离线（冻结 + 重连）。
21. 文档**明确**：终端**深层内部**（多会话 / 尺寸重排 / scrollback / 活动指示）**后续**（不静默丢弃）。

**浏览器页签（可见 surface 全态）**

22. 浏览器页签**能**显地址栏 ← → ⟳ + URL + 前往 + 页面内嵌预览；未输入时**能**显「开始浏览」空态。
23. 浏览器右键**恰为 3 项**（后退 / 刷新 / 复制链接）；**能**覆盖：默认 / 运行（加载指示）/ 空 / 错误（**页面加载失败** + 重试）/ 离线。
24. 文档**明确**：浏览器**深层内部**（历史 / 书签 / devtools / 页内多标签）**后续**（不静默丢弃）。

**对话跳转承接 & 目录树消费**

25. 对话点某**改动 / diff** 跳转时，右侧边栏**能**打开 / 切到**审查页签**并**聚焦该文件的 diff**；对话点某**文件**跳转时，**能**打开 / 切到**文件页签**并**预览该文件**；右侧边栏若收起，跳转**能**顺带展开它（沿用壳「展开右侧边栏」壳行为，不新增布局原语）。
26. 文档**明确**：对话侧「发起跳转」的交互归 conversation-page，本需求**只承接「被跳转打开」这一态**。

**面板级聚合态**

27. 主机**离线**时**整面板所有页签统一冻结** + 顶部一条重连提示，主机恢复后各页签按各自能力恢复；面板级**空 / 加载 / 错误**分别对应启动器默认态 / 面板恢复中 / 无法建立工作面板（+ 重试）；主机**版本过低 / 缺工作面板能力**时**能**显「更新主机以使用工作面板」+ 查看如何更新、**不提供降级路径**；以上面板级态相互**并列且与各页签内容态可区分**。

**主题**

28. 右侧边栏**能**走 codePilot 主题（GitHub 浅色默认 + 深色一并适配），读**同一套主题来源**、不自带冲突配色；主题取值 / 切换机制**不在本需求定义**（归 codepilot-layout）。

**边界（不做，逐条声明不静默丢弃）**

29. 文档**明确不重定义**壳行为：右栏 toggle / 宽度（480 / 320 / 800）/ 拖拽手柄 / 按工作区记忆 / active workspace 门——均沿用壳子。
30. 文档**明确不做**：目录树（属 file-tree，文件页签只消费选中不重画树）、终端深层内部、浏览器深层内部、文件内联编辑、对话侧发起跳转交互、主题取值 / 切换机制、移动 / 紧凑态；每条后续项均标注「本轮不做 / 后续」。
31. 文档**明确**本需求**不涉及**协议 / RPC / 能力标志（纯前端 WHAT 层，能力门只说依赖不点名）。

**屏对齐**

32. sRS1（启动器默认）/ sRS2（多页签框架）/ sRS3（审查 diff 全态）/ sRS4（文件预览全态 · 不重画树）/ sRS5（终端 & 浏览器内容态）/ sRS6（放大缩小整面板 + 单页签）/ sRS7（面板级空 / 加载 / 错误 / 离线聚合）**七屏**在 ui.html 均**有** `sRS*` 锚点，注解块覆盖本需求全态（含各屏右键菜单与可点元素点击效果），且每状态 ↔ 屏 1:1、无「无对应屏」遗留。

## 7. 开放问题（需董事长在闸 1 拍板）

1. **审查页签是否允许关闭**：本需求**默认取「审查不可关」**（其 ✕ 置灰）。此项 HS 明标「开放项待董事长定」。**注意其耦合**：审查可关与否**直接决定**「关全部 → 回裸启动器」（做 ⑧）这条完整出口是否可达——默认「不可关」下审查一经打开即常驻、回不到裸启动器；若采纳「可关」则关掉含审查在内的全部页签即回启动器。请拍板。
2. **终端 / 浏览器本轮深度切分**：本需求切「**可见 surface 全态 + 深层内部后续**」（终端多会话 / 尺寸重排 / scrollback / 活动指示；浏览器历史 / 书签 / devtools / 页内多标签 —— 均后续）。是否认可此切分？
3. **文件页签本轮「只读预览、内联编辑后续」**：是否认可？（论证见 §2：只读预览覆盖绝大多数「看文件」诉求，编辑为可分离增量、避免过早建写路径而返工。）
4. **对话跳转的映射边界**：确认「点对话里某**改动 / diff** → **审查页签**聚焦该文件 diff」「点对话里某**文件** → **文件页签**预览该文件」这一映射；是否还有第三类对话元素（如点某段**代码块**）需要映射到某页签，请一并指示。
5. **整面板放大的占满范围**：默认取「**仅盖对话区**、左栏与目录树按各自显隐保留」。是否需要放大时连带收起目录树 / 仅保留左栏？请确认。
6. **启动器 / 新选项卡的快捷键取值**：本需求只在 WHAT 层保证「每项有快捷键等价触发」；**具体键位由 UI / 设计定值**（HS 稿中「审查 ⌃⇧G」与「终端 ⌃⇧G」存在**键位冲突**，需一并厘清）。是否同意键位定值 + 解冲突留给设计稿？
