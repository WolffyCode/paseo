## 1. 目标 & 用户价值

**一句话目标**:把主界面左侧边栏的空容器,填成一个可用的**对话树**——按项目分组、可无限嵌套 subagent、可搜索、可新建、可管理、可跨主机切换的会话导航区,让用户在一处看清「本机 + 远程主机上有哪些项目、每个项目下有哪些对话、每条对话内部还派生了哪些 subagent、谁在跑、谁需要我」。

**用户为什么需要**:

- 用户随时随地(含手机盯着本机)监控 / 指挥多个 AI 编码 agent,**左栏是唯一的导航起点**——不点进某条对话,用户无法看到它的内容、无法知道它是否还在跑、是否出错、是否需要输入。没有这块,整个 app 不可用。
- 真实工作中,一条任务经常在内部派生 subagent(Explore 子任务、写测试子任务……),用户需要在**同一棵树**里看清「谁是谁的子任务」,而不是所有对话拍平在一层、丢失父子关系。
- 用户手上不止一台主机(本机 + 公司电脑 + 云服务器等),需要**不切工具、不重连**地在几台主机的对话之间跳转,由树顶部的入口提供。
- 项目一多,列表会变长;**搜索**让用户不用滚动就能定位到想找的那条对话。
- **本轮把这一整块从「壳里的空容器」变成「真实可用」**——`2026-06-28-shell` 需求刻意把所有内容留空以求壳先稳定;本需求正是那份「后续内容里程碑」承诺的兑现者之一。

## 2. 范围

### 做

#### A. 对话树展示(项目 → 对话 → subagent 无限嵌套)

- **分组**:纵向三组——**置顶**(仅当存在置顶项目 / 对话时出现,置顶项目整棵进入、置顶对话从其所属项目里提升出来)→ **项目**(按代码仓库聚合的分组;同一项目下可能同时有主目录与若干工作树,其上的对话都归在同一项目节点下)→ **对话**(未归入任何项目的游离对话)。
- **嵌套**:项目展开出其下对话(根);对话展开出其 subagent;subagent 可以再展开出更深一层 subagent,递归、**不设人为层数上限**。视觉缩进达到一定深度后**停止继续增长**(仅靠图标与展开箭头区分更深层级),但父子关系与展开 / 收起能力不受影响。
- **节点组成**:展开箭头(仅当有可展开内容时出现,前置于图标之前,收起 / 展开态图形不同,如旋转)+ 图标(项目 = 文件夹;对话 / subagent = 机器人,subagent 图标略小)+ 标题(单行、超长省略)+ 状态点 + (非项目节点、且拥有后代时)后代总数角标。
- **空态细节**:项目节点展开但其下没有任何对话时,显示「还没有对话」的缩进提示,而非空白或消失;对话 / subagent 节点只有真的存在子节点时才显示展开箭头,无子节点的行以等宽占位对齐图标(不显示箭头)。

#### B. 状态点语义(重新设计,非现状复用)

- **本条是重新设计,不是「忠实还原现状」**:当前树行**未渲染**任何状态点——此前曾有过近似尝试,因反馈「达不到想要的效果」被整体移除;节点的运行状态数据(五值状态枚举 + 「需关注」标志)本身真实存在,只是没有对应的树内视觉。本轮据此重新设计一套树内可视状态点(见 sCT2 图例),请董事长闸 1 特别过目视觉效果(见 §8)。
- 对话 / subagent 节点的状态点至少区分五态:**运行中**(绿 · 脉冲)/ **待输入或需关注**(醒目色,涵盖「回合结束等待用户」与「完成后需要人复核」两种触发原因,统一为同一个可见信号)/ **空闲**(灰)/ **出错**(红)/ **初始化中**(过渡色)。
- 该套语义与应用内其它活动指示(如终端活动)**同源**——复用既有的「运行 / 待输入 / 空闲 / 出错」活动词汇体系,不为树自造一套新状态名。
- 已归档 / 已关闭的对话及其 subagent **不出现**在树中。

#### C. 树行交互(hover / 选中 / 工作区卡片 / 更多 / 双击重命名)

- **hover**:行底色变浅;项目行行尾浮出「新建对话」图标,对话 / subagent 行行尾浮出「更多」图标(点击打开与右键相同的菜单)。项目行**没有**行尾「更多」快捷入口——项目菜单只能经右键 / 长按打开。
- **hover 与选中为两档灰阶(相对现状单档的有意修正)**:hover = 较浅一档的淡灰,选中 = 较深一档的淡灰(两者均为柔和灰,不使用黑底白字 / 强调色做底),两档可清楚区分;选中态持续显示、不随指针移开而消失。现状 hover 与选中共用同一档灰,本轮改为两档,对齐 codePilot 设计系统下同类控件(目录树行、右栏页签)既有的两档灰阶惯例(见 §8 开放问题)。只有对话 / subagent 可被选中,项目节点不可选中(点击只切换展开 / 收起)。
- **hover 工作区卡片**(仅对话行,桌面网页端,短暂宽限延迟后出现、离开安全区后再延迟收起):浮出该对话的标题、当前分支、工作目录、最近变更时间;若该工作区存在改动统计 / 关联 PR / CI 检查结果,一并显示摘要;卡片内目录与分支可点击复制,检查摘要可点击跳转外部详情。
- **双击重命名**:对已绑定工作目录的对话行,300ms 内双击进入行内重命名(等价于右键菜单的「重命名」);行内变为输入框 + 聚焦态边框,回车提交、Esc 取消。

#### D. 右键菜单(两套,忠实还原现状)

- **项目行菜单(6 项)**:置顶 / 取消置顶 · 在 Finder 中显示(需 Electron 桌面壳 + 已知本地目录,否则不显示)· 创建工作树(需已知本地目录,否则不显示)· 重命名项目 · 归档(禁用占位,语义待定,不在本需求内裁定)· 移除(破坏性,二次确认,确认后仅从侧栏移除该项目分组,不触碰磁盘文件)。
- **对话 / subagent 共用菜单(11 项 + 分隔)**:置顶 / 取消置顶(需已绑定工作目录)· 重命名(需已绑定工作目录)· 归档(禁用占位)· 标记为未读(禁用占位)· —— · 在 Finder 中显示(条件同项目行)· 复制工作目录(禁用占位)· 复制会话 ID(始终可用,与是否绑定工作目录无关)· 复制深度链接(禁用占位)· —— · 派生到本地(禁用占位)· 派生到新工作树(禁用占位)· —— · 在新窗口打开(需 Electron 桌面壳 + 已知本地目录,否则不显示)。
- 对话与 subagent **共用同一套菜单**(不拆分出按「对话根 / subagent」区分的第三套)——这是现状,本需求原样保留;上述「禁用占位」项的具体语义**不在本需求裁定**,维持现状占位。

#### E. 新对话入口(两处)

- **全局入口**:树区域顶部固定一行「新对话」,点击导航进入既有新建对话流程,**不预选**项目。
- **项目内入口**:项目行 hover 时行尾浮出「新建对话」图标,点击进入同一流程,但**预选**该项目工作目录。
- 两处都只负责**导航到已有的新建流程**;该流程内部如何选工作目录 / provider / 模式等属另一能力,本需求不重画(深度切后续)。

#### F. 会话搜索入口

- 树区域顶部固定一行「搜索」(含快捷键提示),点击或按快捷键唤出既有的搜索呈现。
- 本需求要求的最低能力:**至少支持按对话名称过滤并定位候选**。既有搜索呈现若已覆盖更深范围(消息内容、目录等跨维度匹配),那是其自身既有能力,不在本需求重新设计或重新验收的范围内(深度切后续)。

#### G. 点击联动(中区 / 右侧)

- 点击一个**根对话**节点 → 中区切换焦点到该对话(发起侧;承接侧 = `2026-06-28-conversation-page`,目前仍是占位——本需求只保证「点击后中区确实切到了该对话的位置」,中区能否渲染出真实消息流由该需求独立验收)。
- 点击一个 **subagent** 节点 → **发起侧**:树内点击、触发跳转到右侧的动作在现状代码里真实存在、真实可用,不改变中区当前显示的根对话。**承接侧**:右侧最终呈现的具体页签形态,不超出 `2026-07-07-right-sidebar` 既有声明的范围——该需求把「对话」列为其统一页签框架下的一种 **deferred** 类型,尚未按新框架设计实现;本需求只保证「点击后确实在右侧发生了跳转」这一发起侧行为,**不承诺**右侧呈现已经是该需求定义的正式「对话」页签类型。端到端体验待该需求把「对话」页签类型落地后才算完整(见 §5)。
- 树的选中态准确反映「中区当前呈现的是哪个根对话」;选中某 subagent 不会清除其所属根对话行原有的选中标识(两者同时可见选中态)。

#### H. 主机切换器(顶部 · 完整闭环)

- 位于**左栏内容最顶部**(壳的窗口控制 / 统一顶栏归壳所有,这是「内容」自己的顶部,不是壳顶栏的一部分)——从当前(临时落在左栏底部、紧邻设置)的位置**挪到此处**,能力本身**原样复用**,不重新设计(见 §5、§8)。
- 显示当前主机名 + 三态连接点(在线 / 连接中 / 离线);点击展开下拉,列出全部已配置主机(各自连接点 + 名称),当前项有明确标识;末尾「添加主机…」入口(复用既有添加主机流程,不重画其内部)。
- 选中一台**在线**主机 → 整个工作区(树 + 中区 + 右侧面板)进入切换中过场,随后重载为该主机数据。
- 点击一台**离线**主机行 → **不直接切换**,原地对其发起重连尝试(退避重试);成功后该行状态转为在线,此时用户可再次点击真正切换过去(相对现状的一处行为修正,见 §8)。
- 仅有一台主机时,下拉只列出该主机 + 「添加主机…」。

#### I. 全态(空 / 加载 / 错误 / 离线 / 浅深主题)

- **空**:无任何项目和对话时,「项目」分组只显示新增入口,「对话」分组显示「还没有对话」提示;新对话 / 搜索 / 主机切换器三个入口仍正常可用,不是死胡同。
- **加载**:首次进入或切主机期间,树位置显示骨架占位行,完成后换入真实内容。
- **错误**:拉取项目或对话列表失败时,树区域出现错误提示 + 「重试」;点重试重新拉取。
- **离线**:当前主机断连 → 主机切换器状态点转离线、树区域出现「离线 · 重新连接」提示条;树内容冻结为断连前最后已知状态、操作项置灰(只读);点「重新连接」发起退避重试,恢复后按最新数据刷新。
- **浅 / 深主题**:读壳提供的 codePilot 主题来源;选中态与 hover 态均为柔和灰阶(两档,见 §2·C),不使用黑底白字 / 强调色做底。

### 深度切分 · 显式论证

> 为什么「树主体 + 主机切换器 + 两套右键菜单(现状还原)」全做,而「专属 subagent 菜单 / 拖拽排序 / 新建流程与搜索内部」只接入口或 deferred?

**① 树是唯一导航起点**——没有可用的树,用户无法进入任何对话,app 不可用;这是必须做全、不能碎片化交付的部分,没有「分批」的空间。

**② 现状即真实、成本最低、风险最小**——树的展示 / 行交互 / 两套右键菜单 / 主机切换器,在当前左栏里都是**真实上线、跑过用户反馈打磨**的行为。本需求要做的是「把这套已验证的真实行为原样接进新壳的左栏容器」,这是最低风险、立即可验收的路径——不是从零设计一遍,也因此不会返工。**例外**:状态点视觉与 hover / 选中的两档灰阶是本轮**新设计 / 有意修正**的两处,不在「现状照搬」之列,理由与范围见 §2·B、§2·C、§8。

**③ 深链接的内部流程不重复设计**——新建对话流程、搜索呈现,都是本身完整独立、已有明确产品形态的能力;本需求作为「消费方」只需接好入口,重新设计等于重复劳动,还可能与既有形态打架。

**④ 专属 subagent 右键与拖拽排序是锦上添花、非阻塞项**——「剥离为独立对话」这个能力已经在对话页的 subagent 相关区域有出口,不会因为树内暂缺专属菜单而让用户被卡住;拖拽排序从未实现过,也从未被证明是当前的刚需。两者都不影响「看树、选对话、做基本管理」这个核心闭环,归后续、不为它们拖慢本轮交付。

### 不做

- **不重定义壳行为**:左栏开关、默认 240px、拖 180–300px、按工作区记忆宽度、设置入口固定在左栏最下方槽位——**全部沿用**壳子 `2026-06-28-shell` 与 `2026-06-27-codepilot-layout`,本需求一概不改、不重写,只在文档里**引用**设置入口的存在。
- **不做树节点拖拽排序**——沿用 shell §7.b 第 16 条已定的 deferred,现状也未实现,本轮不新增。
- **不做按节点类型细分的第三套「subagent 专属」右键菜单**(跳到父对话 / 剥离为独立对话)——现状对话与 subagent 共用同一套菜单,本轮忠实还原现状,不新增专属菜单;home-shell 曾构想过这套专属菜单,本轮视为后续方向,不静默丢弃(见 §5)。
- **不裁定「归档 / 标记为未读 / 复制工作目录 / 复制深度链接 / 派生到本地 · 新工作树」等菜单项的语义**——现状即为禁用占位、语义待定,是与本需求无关的既有决策,本轮不重新打开这些讨论,维持现状占位。
- **不重画「新建对话」流程内部**(选目录 / 选 provider / 选模式等)——那是已有的独立流程,本需求只接入口。
- **不重画搜索 / 命令面板本身**——已有独立能力,本需求只接入口 + 保证「至少按名称可查到」的最低期望。
- **不做 provider 内部只读 subagent(如 Claude 原生 Task 子任务)的深层可见性**——那是 `2026-06-27-subagent-native-tree` 的范围(仍评审中);本需求的树结构对其保持开放(同一套嵌套 / 展开 / 状态点语义天然适配),但不在本需求内实现或验收其读取能力。
- **不做移动端 / 紧凑态**——桌面 only,紧凑态 deferred,沿用壳既定的「后续由桌面统一适配」安排。
- **不涉及协议 / RPC / 能力标志点名**——纯前端 WHAT 层,能力门只做「依赖某能力」的表述,不点名。

## 3. 流程(端到端)

- **落地默认态**:连上主机后,左栏内容自上而下依次呈现:主机切换器(顶部)→ 新对话 / 搜索(两行入口)→ 置顶组(若有)/ 项目组 / 对话组(按各自展开记忆呈现)。
- **浏览树**:点项目行(或其展开箭头)→ 展开 / 收起其下对话;点对话 / subagent 行的展开箭头 → 展开 / 收起其子代理(不触发联动);点对话 / subagent 行本身(非箭头区域)→ 选中并触发联动(见 §2·G)。
- **新建对话**:点顶部「新对话」→ 进入既有新建流程(不预选项目);或 hover 项目行 → 行尾「新建对话」→ 进入同一流程且预选该项目工作目录。流程完成后,新对话出现在树中对应位置并自动选中。
- **搜索**:点顶部「搜索」或按快捷键 → 唤出既有搜索呈现 → 输入内容按名称(至少)过滤定位候选 → 选中一项 → 关闭搜索、树滚动到该对话并选中、按 §2·G 联动规则呈现内容。
- **管理操作**:右键(或对话 / subagent 行的行尾「更多」)一行 → 按行类型弹出对应菜单 → 选项按现状可用性显隐 / 禁用 → 点击执行(置顶 / 重命名 / 在 Finder 中显示 / 创建工作树 / 移除项目 / 复制会话 ID / 在新窗口打开等);重命名走行内输入(回车提交 / Esc 取消),双击对话行是重命名的快捷方式。
- **切主机**:点主机切换器 → 下拉列出所有主机 → 点一台在线主机 → 整个工作区(树 + 中区 + 右侧面板)进入切换中过场 → 重载为该主机数据;点一台离线主机 → 不切换、原地触发重连(退避重试)→ 成功后该行转在线、可再次点击真正切过去;点「添加主机…」→ 进入既有添加主机流程,完成后新主机出现在列表且可选中。
- **边界分叉**(每态有入口有出口,无死胡同):
  - **空态**(无项目也无对话):树区域只显「项目」分组的新增入口与「对话」分组的「还没有对话」提示,顶部三个入口均可用。
  - **加载**:首次拉取 / 切主机期间,树位置显示骨架占位行,完成后换入真实内容。
  - **错误**:拉取项目或对话列表失败 → 树顶部出现错误提示 + 重试;点重试 → 重新拉取,成功则恢复正常态。
  - **离线**:当前主机断连 → 主机切换器状态点转离线红 + 树区域出现「离线 · 重新连接」提示条;树内容冻结为断连前最后已知状态(只读,操作项置灰);点「重新连接」→ 退避重试;恢复后树内容按最新数据刷新。
  - **管理操作进行中**:对某行发起归档 / 移除等操作后,该行进入处理中态,完成后从树消失(或按操作语义更新);失败则保留原状 + 反馈。

## 5. 边界与依赖

- **与 shell(`2026-06-28-shell`)的关系**:shell 定义左侧边栏这个空容器的**外壳行为**(展开 / 收起 toggle、默认 240px、拖 180–300px、按工作区记忆宽度、设置入口固定在左栏最下方槽位)——本需求**完全不改**这些,只负责往这个已经会开关、会拖宽的容器里填入内容。本需求正是该需求 §7.b 第 7–18 条点名的「后续内容里程碑」的兑现者之一。
- **与 codepilot-layout(`2026-06-27-codepilot-layout`)§5 的关系**:该需求明令「左栏外壳(开关 / 位置 / 240px / 拖 180-300 / 主题)归 CodePilot,内部内容 + 布局归 Helm 现有那套对话树」,并逐项点名了本需求要交付的清单(主机切换器 / 新对话 / 搜索 / 对话树细节 / 设置引用)。本需求就是把该判决落成可验收的 requirement;不采用 CodePilot 左栏的插件 / 素材库内容(该判决已排除)。
- **与 home-shell(`2026-06-25-home-shell`)的关系**:home-shell 是**尚未落地的概念稿**(gate-1 未过、未回写 canonical)。本需求**不是**把 home-shell 搬过来,而是以**当前真实实现**为准,只在一处采纳 home-shell 已验证过的设计意图作为改进(离线主机点击语义,见 §8);home-shell 里尚未实现的部分(拖拽排序、subagent 专属右键的「跳到父对话 / 剥离为独立对话」、目录节点的「移动到目录 / 复制对话」等)本需求视为后续方向,不在本轮实现,不代表被放弃。
- **与 subagent-native-tree(`2026-06-27-subagent-native-tree`,评审中)的关系**:该需求负责让 provider 内部只读 subagent(如 Claude 原生 Task 子任务)在树中任意层可见并可点开只读对话,目前仍在评审、未实现。本需求的树结构(无限嵌套 / 展开收起 / 状态点 / 角标)设计上对其保持开放——同一套语义天然可承载只读节点,不需要本需求预先改动;但本需求的验收范围**不包含**provider 内部子的深层可见性本身,那是该需求自己的验收范围。
- **与 conversation-page(`2026-06-28-conversation-page`)的关系**:本需求点击根对话后「发起」中区切换,但中区**承接**这条对话、渲染出消息流,是 conversation-page 的范围;该需求目前仍是占位(尚未实现消息流内容)。本需求的验收只要求「点击后中区的焦点确实切到了该对话」,不要求中区已经能渲染出真实消息流——那由 conversation-page 自己独立验收。
- **与右侧边栏(`2026-07-07-right-sidebar`)的关系**:subagent 点击 → 右侧打开对话,是**发起侧真实存在、承接侧 deferred** 的一条断链(表述范式同该需求 §2·D 的三条断链)——**发起侧**(树内点击、触发跳转到右侧)在现状代码里真实可用;**承接侧**(右侧以该需求定义的「对话」页签类型正式承接)仍是 deferred,该需求明确「对话(右栏侧边会话 / 子对话,deferred)」尚未按其统一页签框架设计实现。本需求的验收只覆盖发起侧,不对承接侧的最终呈现形态做超出该需求既有声明的承诺;两者何时端到端接通,取决于该需求「对话」页签类型的落地时间,不在本需求内处理。
- **能力门(不点名协议 / RPC)**:依赖「能拿到项目分组」「能拿到对话 / subagent 的父子关系与状态」「能对某主机发起连接 / 重连」「能创建 / 重命名 / 置顶 / 移除项目或对话」「能拿到工作区的分支 / 目录 / 改动 / PR / 检查信息用于 hover 卡片」这类既有能力;本需求只读取、只展示、只发起既有动作,不新增采集或协议机制。旧主机若缺少某项能力,按现有「升级主机」提示处理(不点名具体能力名)。
- **平台**:桌面 only。移动 / 紧凑态不在本轮,沿用壳既定的「deferred、后续由桌面统一适配」安排(左栏在紧凑态本就是不同呈现,不受本需求约束)。
- **术语**(对齐 [glossary.md](../../../glossary.md)):「对话」= 一个根 agent 的会话(Agent session);「项目」= 按代码仓库聚合的分组;「subagent」= 有父对话的会话,可再嵌套自己的 subagent;「主机」= 客户端连接的一个 daemon profile。
- **无老用户 / 迁移**(fork 未上线)。**不改协议 / RPC / `server_info.features.*`**:本需求是纯前端的内容填充。

## 6. 验收标准(逐条可判定 · 能 / 否)

**树结构与嵌套**

1. 左栏内容自上而下依次呈现:主机切换器 → 新对话 / 搜索两行入口 → 置顶组(仅当存在置顶项时出现)→ 项目组 → 对话组(游离对话)。
2. 树呈现项目 → 对话(根)→ subagent → … 的嵌套关系,层数不设人为上限;有可展开内容的节点前置展开箭头,收起态与展开态图形不同。
3. 项目节点展开但其下没有任何对话时,显示「还没有对话」的缩进提示,而不是空白或消失。
4. 对话 / subagent 节点只有真正存在子节点时才显示展开箭头;无子节点的行以等宽占位对齐、不显示箭头。
5. 非项目节点(对话 / subagent)在拥有后代时显示后代总数角标(不止直接子节点数)。
6. 深层嵌套超过一定层数时,视觉缩进停止继续增长,但展开 / 收起与父子关系不受影响、仍可继续操作更深层级。

**状态点**

7. 每个对话 / subagent 节点显示状态点,至少区分运行中 / 待输入或需关注 / 空闲 / 出错 / 初始化中五种,且与应用内其它活动指示使用同一套语义,而非本树自造的新状态词汇。
8. 已归档 / 已关闭的对话及其 subagent 不出现在树中。

**行交互**

9. 行默认态、hover 态(行底色变浅 + 行尾浮出操作)、选中态(与 hover 呈**两档灰阶**——hover 较浅、选中较深一档,均不使用黑底白字 / 强调色做底)均可判定区分,且 hover 与选中两档可清楚分辨(相对现状单档灰的有意修正)。
10. hover 对话行(桌面网页端)时,经短暂宽限延迟浮出工作区卡片,显示标题 / 当前分支 / 工作目录 / 最近变更时间;若该工作区存在改动统计 / 关联 PR / CI 检查结果,一并显示;卡片内目录与分支可点复制。
11. 项目行 hover 时行尾浮出「新建对话」图标;对话 / subagent 行 hover 时行尾浮出「更多」图标,点击打开与右键相同的菜单。

> **【董事长闸 1 · 2026-07-11 认可】**:董事长审阅设计稿后确认「没问题」——六条开放问题**全部按推荐值采纳**:①离线主机行点击=原地重连 ✓;②subagent 专属右键本轮不拆 ✓;③主机切换器完整闭环 ✓;④搜索接既有 ⌘K 能力 ✓;⑤状态点重新设计(五态)获过目认可 ✓;⑥hover/选中两档灰阶 ✓。**P1 闭环,进入 P2 架构。**下方条目保留为决策记录。

1. **离线主机行点击语义修正**:现状(当前左栏)离线主机行点击与在线行一样直接尝试切换;本需求采用 `2026-06-25-home-shell` 已验证过的设计——改为「原地触发重连、不直接切走」(见 sCT5)。这是相对现状的一处行为修正,请董事长确认是否认可。若不认可,退回现状「点击即尝试切换」亦可,不影响其余范围。
