## 1. 目标 & 用户价值

**一句话目标**:把主界面左侧边栏的空容器,填成一个可用的**对话树**——按项目分组、可无限嵌套 subagent、可搜索、可新建、可管理、可跨主机切换的会话导航区,让用户在一处看清「本机 + 远程主机上有哪些项目、每个项目下有哪些对话、每条对话内部还派生了哪些 subagent、谁在跑、谁需要我」。

**用户为什么需要**:

- 用户随时随地(含手机盯着本机)监控 / 指挥多个 AI 编码 agent,**左栏是唯一的导航起点**——不点进某条对话,用户无法看到它的内容、无法知道它是否还在跑、是否出错、是否需要输入。没有这块,整个 app 不可用。
- 真实工作中,一条任务经常在内部派生 subagent(Explore 子任务、写测试子任务……),用户需要在**同一棵树**里看清「谁是谁的子任务」,而不是所有对话拍平在一层、丢失父子关系。
- 用户手上不止一台主机(本机 + 公司电脑 + 云服务器等),需要**不切工具、不重连**地在几台主机的对话之间跳转,由树顶部的入口提供。
- 项目一多,列表会变长;**搜索**让用户不用滚动就能定位到想找的那条对话。
- **本轮把这一整块从「壳里的空容器」变成「真实可用」**——`2026-06-28-shell` 需求刻意把所有内容留空以求壳先稳定;本需求正是那份「后续内容里程碑」承诺的兑现者之一。

## 2. 范围

### 做

#### A. 对话树展示(项目 → 对话 → subagent 无限嵌套)

- **分组**:纵向三组——**置顶**(仅当存在置顶项目 / 对话时出现,置顶项目整棵进入、置顶对话从其所属项目里提升出来)→ **项目**(按代码仓库聚合的分组;同一项目下可能同时有主目录与若干工作树,其上的对话都归在同一项目节点下)→ **对话**(未归入任何项目的游离对话)。
- **嵌套**:项目展开出其下对话(根);对话展开出其 subagent;subagent 可以再展开出更深一层 subagent,递归、**不设人为层数上限**。视觉缩进达到一定深度后**停止继续增长**(深层级仅靠展开箭头与父子关系判断——对话 / subagent 节点已不显示机器人图标,不能再靠图标区分层级,见下方「节点组成」2026-07-23 追加修正),但父子关系与展开 / 收起能力不受影响。
- **节点组成(2026-07-28 最终覆盖)**:三类节点统一为 36px 单行。项目节点 = 展开箭头(仅有子级时)+ 文件夹图标 + 标题；对话(根)与 subagent = 展开箭头(仅有子级时)+ 标题。根对话和 subagent 均不显示机器人图标、provider 图标、状态点或后代数量；所有行都不显示尾部三点、快捷新建或其它动作按钮。分支、diff、时间与 provider 只在 hover 信息卡出现。
- **空态细节**:项目节点展开但其下没有任何对话时,显示「暂无对话」的缩进提示,而非空白或消失;对话 / subagent 节点只有真的存在子节点时才显示展开箭头,无子节点的行以等宽占位对齐标题起始位置,不显示箭头。

#### B. 单行信息结构与状态边界(2026-07-28 最终覆盖)

- 项目、根对话、subagent 均为 36px 单行，标题单行省略；项目保留文件夹图标，根对话与 subagent 不显示任何前置图标或状态点。
- subagent 不显示直接子级或全部后代数量；根对话同样不显示 subagent 数量。层级只由缩进与展开箭头表达。
- 项目、根对话与 subagent 都没有行尾按钮。三点“更多”、项目快捷“新对话”及其它尾部动作全部移入右键菜单。
- 项目信息卡显示标题、文件路径、Git 分支、Git diff；根对话与 subagent 信息卡均显示各自的对话名称、操作目录、最后一次使用时间、提供方。subagent 的名称、时间、提供方取自身数据；没有独立工作区时，操作目录仅为展示而继承父级目录上下文。
- 根对话的审核中、报错、进行中等状态判断与视觉另行设计；底层状态语义可继续保留，但本轮不在根对话或 subagent 行内展示。
- 已归档的对话及其 subagent 不出现；closed 对话保留显示且仍可点击进入。

#### C. 树行交互(hover / 选中 / 信息卡片 / 双击重命名)

- **hover**:项目、根对话与 subagent 行底色变浅，不浮出任何行尾按钮；三类行在桌面网页端经短暂宽限延迟后显示各自的右侧信息卡。
- **hover 与选中为两档灰阶(相对现状单档的有意修正)**:hover = 较浅一档的淡灰,选中 = 较深一档的淡灰(两者均为柔和灰,不使用黑底白字 / 强调色做底),两档可清楚区分;选中态持续显示、不随指针移开而消失。现状 hover 与选中共用同一档灰,本轮改为两档,对齐 codePilot 设计系统下同类控件(目录树行、右栏页签)既有的两档灰阶惯例(见 §8 开放问题)。只有对话 / subagent 可被选中,项目节点不可选中(点击只切换展开 / 收起)。
- **hover 信息卡片**(桌面网页端,短暂宽限延迟后出现、离开安全区后再延迟收起):项目卡片显示标题、文件路径、Git 分支、Git diff；根对话与 subagent 卡片显示各自的对话名称、操作目录、最后一次使用时间、提供方。路径可点击复制；subagent 没有独立工作区时，卡片目录仅继承父级上下文用于展示，不改变管理能力。
- **双击重命名**:对已绑定工作目录的对话行,300ms 内双击进入行内重命名(等价于右键菜单的「重命名」);行内变为输入框 + 聚焦态边框,回车提交、Esc 取消。

#### D. 右键菜单(两套,所有行操作的唯一入口)

- **项目行菜单(7 项)**:新对话(预选该项目工作目录)· 置顶 / 取消置顶 · 在 Finder 中显示(需 Electron 桌面壳 + 已知本地目录,否则不显示)· 创建工作树(需已知本地目录,否则不显示)· 重命名项目 · 归档(禁用占位,语义待定,不在本需求内裁定)· 移除(破坏性,二次确认,确认后仅从侧栏移除该项目分组,不触碰磁盘文件)。
- **对话 / subagent 共用菜单(11 项 + 分隔)**:置顶 / 取消置顶(需已绑定工作目录)· 重命名(需已绑定工作目录)· 归档(禁用占位)· 标记为未读(禁用占位)· —— · 在 Finder 中显示(条件同项目行)· 复制工作目录(禁用占位)· 复制会话 ID(始终可用,与是否绑定工作目录无关)· 复制深度链接(禁用占位)· —— · 派生到本地(禁用占位)· 派生到新工作树(禁用占位)· —— · 在新窗口打开(需 Electron 桌面壳 + 已知本地目录,否则不显示)。
- 对话与 subagent **共用同一套菜单**(不拆分出按「对话根 / subagent」区分的第三套)——这是现状,本需求原样保留;上述「禁用占位」项的具体语义**不在本需求裁定**,维持现状占位。

#### E. 新对话入口(全局 + 项目右键)

- **全局入口**:树区域顶部固定一行「新对话」,点击导航进入既有新建对话流程,**不预选**项目。
- **项目内入口**:右键项目行后选择“新对话”，进入同一流程并**预选**该项目工作目录；行尾不显示快捷按钮。
- 两处都只负责**导航到已有的新建流程**;该流程内部如何选工作目录 / provider / 模式等属另一能力,本需求不重画(深度切后续)。

#### F. 会话搜索入口

- 树区域顶部固定一行「搜索」(含快捷键提示),点击或按快捷键唤出既有的搜索呈现。
- 本需求要求的最低能力:**至少支持按对话名称过滤并定位候选**。既有搜索呈现若已覆盖更深范围(消息内容、目录等跨维度匹配),那是其自身既有能力,不在本需求重新设计或重新验收的范围内(深度切后续)。

#### G. 点击联动(中区 / 右侧)

- 点击一个**根对话**节点 → 中区切换焦点到该对话(发起侧;承接侧 = `2026-06-28-conversation-page`,目前仍是占位——本需求只保证「点击后中区确实切到了该对话的位置」,中区能否渲染出真实消息流由该需求独立验收)。
- 点击一个 **subagent** 节点 → **发起侧**:树内点击、触发跳转到右侧的动作在现状代码里真实存在、真实可用,不改变中区当前显示的根对话。**承接侧**:右侧最终呈现的具体页签形态,不超出 `2026-07-07-right-sidebar` 既有声明的范围——该需求把「对话」列为其统一页签框架下的一种 **deferred** 类型,尚未按新框架设计实现;本需求只保证「点击后确实在右侧发生了跳转」这一发起侧行为,**不承诺**右侧呈现已经是该需求定义的正式「对话」页签类型。端到端体验待该需求把「对话」页签类型落地后才算完整(见 §5)。
- 树的选中态准确反映「中区当前呈现的是哪个根对话」;选中某 subagent 不会清除其所属根对话行原有的选中标识(两者同时可见选中态)。

#### H. 主机切换器(顶部 · 完整闭环)

- 位于**左栏内容最顶部**(壳的窗口控制 / 统一顶栏归壳所有,这是「内容」自己的顶部,不是壳顶栏的一部分)——从当前(临时落在左栏底部、紧邻设置)的位置**挪到此处**,能力本身**原样复用**,不重新设计(见 §5、§8)。
- 显示当前主机名 + 三态连接点(在线 / 连接中 / 离线);点击展开下拉,列出全部已配置主机(各自连接点 + 名称),当前项有明确标识;末尾「添加主机…」入口(复用既有添加主机流程,不重画其内部)。
- 选中一台**在线**主机 → 整个工作区(树 + 中区 + 右侧面板)进入切换中过场,随后重载为该主机数据。
- 点击一台**离线**主机行 → **不直接切换**,原地对其发起重连尝试(退避重试);成功后该行状态转为在线,此时用户可再次点击真正切换过去(相对现状的一处行为修正,见 §8)。
- 仅有一台主机时,下拉只列出该主机 + 「添加主机…」。

#### I. 全态(空 / 加载 / 错误 / 离线 / 浅深主题)

- **空**:无任何项目和对话时,「项目」分组只显示新增入口,「对话」分组显示「暂无对话」提示;新对话 / 搜索 / 主机切换器三个入口仍正常可用,不是死胡同。
- **加载**:首次进入或切主机期间,树位置显示骨架占位行,完成后换入真实内容。
- **错误**:拉取项目或对话列表失败时,树区域出现错误提示 + 「重试」;点重试重新拉取。
- **离线**:当前主机断连 → 主机切换器状态点转离线、树区域出现「离线 · 重新连接」提示条;树内容冻结为断连前最后已知状态、操作项置灰(只读);点「重新连接」发起退避重试,恢复后按最新数据刷新。
- **浅 / 深主题**:读壳提供的 codePilot 主题来源;选中态与 hover 态均为柔和灰阶(两档,见 §2·C),不使用黑底白字 / 强调色做底。

### 深度切分 · 显式论证

> 为什么「树主体 + 主机切换器 + 两套右键菜单(现状还原)」全做,而「专属 subagent 菜单 / 拖拽排序 / 新建流程与搜索内部」只接入口或 deferred?

**① 树是唯一导航起点**——没有可用的树,用户无法进入任何对话,app 不可用;这是必须做全、不能碎片化交付的部分,没有「分批」的空间。

**② 现状即真实、成本最低、风险最小**——树的展示 / 行交互 / 两套右键菜单 / 主机切换器,在当前左栏里都是**真实上线、跑过用户反馈打磨**的行为。本需求要做的是「把这套已验证的真实行为原样接进新壳的左栏容器」,这是最低风险、立即可验收的路径——不是从零设计一遍,也因此不会返工。**例外**:状态点视觉与 hover / 选中的两档灰阶是本轮**新设计 / 有意修正**的两处,不在「现状照搬」之列,理由与范围见 §2·B、§2·C、§8。

**③ 深链接的内部流程不重复设计**——新建对话流程、搜索呈现,都是本身完整独立、已有明确产品形态的能力;本需求作为「消费方」只需接好入口,重新设计等于重复劳动,还可能与既有形态打架。

**④ 专属 subagent 右键与拖拽排序是锦上添花、非阻塞项**——「剥离为独立对话」这个能力已经在对话页的 subagent 相关区域有出口,不会因为树内暂缺专属菜单而让用户被卡住;拖拽排序从未实现过,也从未被证明是当前的刚需。两者都不影响「看树、选对话、做基本管理」这个核心闭环,归后续、不为它们拖慢本轮交付。

### 不做

- **本次(2026-07-23,含视觉修正与信息架构修正两轮)追加修正不无限扩大改动范围**:这两轮修正合计影响的是图标、状态点是否存在及渲染方式、标签行、对话(根)行与项目行是否为两行及两行内容(见 §2·A、§2·B);展开箭头、缩进逻辑、两套右键菜单、hover 尾部动作、内联重命名、closed 语义、拖拽等均不受影响,继续维持 2026-07-11 闸 1 通过时的定义。**项目行结构本身属信息架构修正这一轮的变动范围**(升级为两行),不再沿用视觉修正那一轮「项目行不受影响」的表述——这处衔接特此说明,避免两轮修正的边界描述互相矛盾。
- **不重定义壳行为**:左栏开关、默认 240px、拖 180–300px、按工作区记忆宽度、设置入口固定在左栏最下方槽位——**全部沿用**壳子 `2026-06-28-shell` 与 `2026-06-27-codepilot-layout`,本需求一概不改、不重写,只在文档里**引用**设置入口的存在。
- **不做树节点拖拽排序**——沿用 shell §7.b 第 16 条已定的 deferred,现状也未实现,本轮不新增。
- **不做按节点类型细分的第三套「subagent 专属」右键菜单**(跳到父对话 / 剥离为独立对话)——现状对话与 subagent 共用同一套菜单,本轮忠实还原现状,不新增专属菜单;home-shell 曾构想过这套专属菜单,本轮视为后续方向,不静默丢弃(见 §5)。
- **不裁定「归档 / 标记为未读 / 复制工作目录 / 复制深度链接 / 派生到本地 · 新工作树」等菜单项的语义**——现状即为禁用占位、语义待定,是与本需求无关的既有决策,本轮不重新打开这些讨论,维持现状占位。
- **不重画「新建对话」流程内部**(选目录 / 选 provider / 选模式等)——那是已有的独立流程,本需求只接入口。
- **不重画搜索 / 命令面板本身**——已有独立能力,本需求只接入口 + 保证「至少按名称可查到」的最低期望。
- **不做 provider 内部只读 subagent(如 Claude 原生 Task 子任务)的深层可见性**——那是 `2026-06-27-subagent-native-tree` 的范围(仍评审中);本需求的树结构对其保持开放(同一套嵌套 / 展开语义天然适配),但不在本需求内实现或验收其读取能力。
- **不做移动端 / 紧凑态**——桌面 only,紧凑态 deferred,沿用壳既定的「后续由桌面统一适配」安排。
- **不涉及协议 / RPC / 能力标志点名**——纯前端 WHAT 层,能力门只做「依赖某能力」的表述,不点名。

## 3. 流程(端到端)

- **落地默认态**:连上主机后,左栏内容自上而下依次呈现:主机切换器(顶部)→ 新对话 / 搜索(两行入口)→ 置顶组(若有)/ 项目组 / 对话组(按各自展开记忆呈现)。
- **浏览树**:点项目行(或其展开箭头)→ 展开 / 收起其下对话;点对话 / subagent 行的展开箭头 → 展开 / 收起其子代理(不触发联动);点对话 / subagent 行本身(非箭头区域)→ 选中并触发联动(见 §2·G)。
- **新建对话**:点顶部「新对话」→ 进入既有新建流程(不预选项目);或右键项目行 →「新对话」→ 进入同一流程且预选该项目工作目录。流程完成后,新对话出现在树中对应位置并自动选中。
- **搜索**:点顶部「搜索」或按快捷键 → 唤出既有搜索呈现 → 输入内容按名称(至少)过滤定位候选 → 选中一项 → 关闭搜索、树滚动到该对话并选中、按 §2·G 联动规则呈现内容。
- **管理操作**:右键项目、根对话或 subagent 行 → 按行类型弹出对应菜单 → 选项按现状可用性显隐 / 禁用 → 点击执行(项目内新对话 / 置顶 / 重命名 / 在 Finder 中显示 / 创建工作树 / 移除项目 / 复制会话 ID / 在新窗口打开等);重命名走行内输入(回车提交 / Esc 取消),双击对话行是重命名的快捷方式。行尾没有其它操作入口。
- **切主机**:点主机切换器 → 下拉列出所有主机 → 点一台在线主机 → 整个工作区(树 + 中区 + 右侧面板)进入切换中过场 → 重载为该主机数据;点一台离线主机 → 不切换、原地触发重连(退避重试)→ 成功后该行转在线、可再次点击真正切过去;点「添加主机…」→ 进入既有添加主机流程,完成后新主机出现在列表且可选中。
- **边界分叉**(每态有入口有出口,无死胡同):
  - **空态**(无项目也无对话):树区域只显「项目」分组的新增入口与「对话」分组的「暂无对话」提示,顶部三个入口均可用。
  - **加载**:首次拉取 / 切主机期间,树位置显示骨架占位行,完成后换入真实内容。
  - **错误**:拉取项目或对话列表失败 → 树顶部出现错误提示 + 重试;点重试 → 重新拉取,成功则恢复正常态。
  - **离线**:当前主机断连 → 主机切换器状态点转离线红 + 树区域出现「离线 · 重新连接」提示条;树内容冻结为断连前最后已知状态(只读,操作项置灰);点「重新连接」→ 退避重试;恢复后树内容按最新数据刷新。
  - **管理操作进行中**:对某行发起归档 / 移除等操作后,该行进入处理中态,完成后从树消失(或按操作语义更新);失败则保留原状 + 反馈。

## 5. 边界与依赖

- **与 shell(`2026-06-28-shell`)的关系**:shell 定义左侧边栏这个空容器的**外壳行为**(展开 / 收起 toggle、默认 240px、拖 180–300px、按工作区记忆宽度、设置入口固定在左栏最下方槽位)——本需求**完全不改**这些,只负责往这个已经会开关、会拖宽的容器里填入内容。本需求正是该需求 §7.b 第 7–18 条点名的「后续内容里程碑」的兑现者之一。
- **与 codepilot-layout(`2026-06-27-codepilot-layout`)§5 的关系**:该需求明令「左栏外壳(开关 / 位置 / 240px / 拖 180-300 / 主题)归 CodePilot,内部内容 + 布局归 Helm 现有那套对话树」,并逐项点名了本需求要交付的清单(主机切换器 / 新对话 / 搜索 / 对话树细节 / 设置引用)。本需求就是把该判决落成可验收的 requirement;不采用 CodePilot 左栏的插件 / 素材库内容(该判决已排除)。
- **与 home-shell(`2026-06-25-home-shell`)的关系**:home-shell 是**尚未落地的概念稿**(gate-1 未过、未回写 canonical)。本需求**不是**把 home-shell 搬过来,而是以**当前真实实现**为准,只在一处采纳 home-shell 已验证过的设计意图作为改进(离线主机点击语义,见 §8);home-shell 里尚未实现的部分(拖拽排序、subagent 专属右键的「跳到父对话 / 剥离为独立对话」、目录节点的「移动到目录 / 复制对话」等)本需求视为后续方向,不在本轮实现,不代表被放弃。
- **与 subagent-native-tree(`2026-06-27-subagent-native-tree`,评审中)的关系**:该需求负责让 provider 内部只读 subagent(如 Claude 原生 Task 子任务)在树中任意层可见并可点开只读对话,目前仍在评审、未实现。本需求的树结构(无限嵌套 / 展开收起 / 状态呈现 / 角标)设计上对其保持开放——同一套语义天然可承载只读节点,不需要本需求预先改动;但本需求的验收范围**不包含**provider 内部子的深层可见性本身,那是该需求自己的验收范围。
- **与 conversation-page(`2026-06-28-conversation-page`)的关系**:本需求点击根对话后「发起」中区切换,但中区**承接**这条对话、渲染出消息流,是 conversation-page 的范围;该需求目前仍是占位(尚未实现消息流内容)。本需求的验收只要求「点击后中区的焦点确实切到了该对话」,不要求中区已经能渲染出真实消息流——那由 conversation-page 自己独立验收。
- **与右侧边栏(`2026-07-07-right-sidebar`)的关系**:subagent 点击 → 右侧打开对话,是**发起侧真实存在、承接侧 deferred** 的一条断链(表述范式同该需求 §2·D 的三条断链)——**发起侧**(树内点击、触发跳转到右侧)在现状代码里真实可用;**承接侧**(右侧以该需求定义的「对话」页签类型正式承接)仍是 deferred,该需求明确「对话(右栏侧边会话 / 子对话,deferred)」尚未按其统一页签框架设计实现。本需求的验收只覆盖发起侧,不对承接侧的最终呈现形态做超出该需求既有声明的承诺;两者何时端到端接通,取决于该需求「对话」页签类型的落地时间,不在本需求内处理。
- **能力门(不点名协议 / RPC)**:依赖「能拿到项目分组」「能拿到对话 / subagent 的父子关系与状态」「能对某主机发起连接 / 重连」「能创建 / 重命名 / 置顶 / 移除项目或对话」「能拿到工作区的分支 / 目录 / 改动 / PR / 检查信息,用于 hover 卡片、以及本轮项目行第二行的常显分支 / diff」这类既有能力;本轮新增两类能力依赖——「能拿到对话所属的 agent provider 归属」「能拿到对话最近一次消息往来的时间」——两者是否已可用、能否本轮接入均待架构确认(见 §8 开放问题 8、7),不预先假定已具备。本需求只读取、只展示、只发起既有动作,不新增采集或协议机制。旧主机若缺少某项能力,按现有「升级主机」提示处理(不点名具体能力名)。
- **平台**:桌面 only。移动 / 紧凑态不在本轮,沿用壳既定的「deferred、后续由桌面统一适配」安排(左栏在紧凑态本就是不同呈现,不受本需求约束)。
- **术语**(对齐 [glossary.md](../../../glossary.md)):「对话」= 一个根 agent 的会话(Agent session);「项目」= 按代码仓库聚合的分组;「subagent」= 有父对话的会话,可再嵌套自己的 subagent;「主机」= 客户端连接的一个 daemon profile。
- **无老用户 / 迁移**(fork 未上线)。**不改协议 / RPC / `server_info.features.*`**:本需求是纯前端的内容填充。

## 6. 验收标准(逐条可判定 · 能 / 否)

**树结构与嵌套**

1. 左栏内容自上而下依次呈现:主机切换器 → 新对话 / 搜索两行入口 → 置顶组(仅当存在置顶项时出现)→ 项目组 → 对话组(游离对话)。
2. 树呈现项目 → 对话(根)→ subagent → … 的嵌套关系,层数不设人为上限;有可展开内容的节点前置展开箭头,收起态与展开态图形不同。
3. 项目节点展开但其下没有任何对话时,显示「暂无对话」的缩进提示,而不是空白或消失。
4. 对话 / subagent 节点只有真正存在子节点时才显示展开箭头;无子节点的行以等宽占位对齐、不显示箭头。
5. 根对话与 subagent 均不显示子级或后代总数，行内只保留标题。
6. 深层嵌套超过一定层数时,视觉缩进停止继续增长,但展开 / 收起与父子关系不受影响、仍可继续操作更深层级。

**状态点、标签行与对话 / 项目行结构**

7. 根对话与 subagent 均不显示运行状态点；审核中、报错、进行中等状态判断与视觉另行设计，本轮不在行内展示。
8. 对话 / subagent 节点均不再显示机器人图标;项目节点的文件夹图标不受影响。
9. 对话(根)节点不显示状态点、provider 标签或状态标签，前置图形位置只保留展开箭头(如有子代)。
10. subagent 节点前不显示状态点、机器人、provider 或其它图标。
11. 对话(根)节点使用 36px 单行，只显示标题(单行、超长省略)，标题前不增加机器人、provider 或其它图标；hover / 选中 / 双击重命名覆盖整行。
12. 根对话的 provider 与最后一次使用时间移入 hover 卡片，不在行内常显。
13. 根对话行内不展示运行状态文案；审核中、报错、进行中等状态判断与视觉待下一轮单独确认。
14. hover 根对话时，提供方显示正确的 provider 名称；内置 provider 使用标准名称，自定义 provider 以原始 id 兜底。
15. hover 根对话时，“最后一次使用时间”使用该对话自身的最近更新时间，以相对时间展示。
16. 对话(根)行不再显示子对话(subagent)总数角标——按字面直接去除,不移到别处;此信息去留的可用性顾虑已独立列为开放问题(见 §8 开放问题 9),不在本条验收范围内擅自恢复或裁定。
17. subagent 节点使用 36px 单行纯标题结构，不显示前置图标、状态点或后代数量。
18. 项目节点使用 36px 单行，依次显示展开箭头(如有子代)、文件夹图标与标题；分支和 diff 不在行内展示。
19. 项目、根对话、subagent、分组标题和空提示统一为 36px，保持稳定的单行扫描节奏。
20. 已归档的对话及其 subagent 不出现在树中；已关闭(closed)的对话保留显示，根对话行仍只显示标题。

**行交互**

21. 行默认态、hover 态(行底色变浅)、选中态(与 hover 呈**两档灰阶**——hover 较浅、选中较深一档,均不使用黑底白字 / 强调色做底)均可判定区分；hover 不浮出任何行尾操作。
22. 桌面网页端 hover 项目行时，经短暂宽限延迟在行右侧浮出卡片，显示标题 / 文件路径 / Git 分支 / Git diff；hover 根对话或 subagent 行时显示目标自身的对话名称 / 操作目录 / 最后一次使用时间 / 提供方。路径可点复制；subagent 没有独立工作区时，操作目录继承父级目录上下文且只用于展示。
23. 项目、根对话与 subagent 行结尾均无三点、新建或其它动作按钮；所有管理动作仅从右键菜单进入。
24. 双击已绑定工作目录的对话行,300ms 内触发行内重命名(等价于菜单里的「重命名」);行内重命名态为输入框 + 聚焦态边框,回车提交、Esc 取消。
25. 树节点拖拽排序**不在本轮范围**,文档明确标注为 deferred(不静默丢弃)。

**右键菜单**

26. 项目行右键菜单固定 7 项:新对话、置顶 / 取消置顶、在 Finder 中显示(条件显隐)、创建工作树(条件显隐)、重命名项目、归档(禁用占位)、移除(破坏性、二次确认、确认后仅从侧栏移除、不动磁盘文件)。
27. 对话与 subagent 行共用同一套右键菜单(不拆分出第三套专属 subagent 菜单),含:置顶 / 取消置顶、重命名(以上两项需已绑定工作目录)、归档(禁用占位)、标记为未读(禁用占位)、在 Finder 中显示(条件显隐)、复制工作目录(禁用占位)、复制会话 ID(始终可用)、复制深度链接(禁用占位)、派生到本地(禁用占位)、派生到新工作树(禁用占位)、在新窗口打开(条件显隐,需 Electron 桌面壳)。
28. 上述禁用占位项的具体语义**不在本需求裁定**,文档明确其为既有的、独立于本需求的待定项,维持现状占位、不新增也不删除。
29. 「跳到父对话」「剥离为独立对话」等 home-shell 构想过的 subagent 专属菜单项,本轮**不实现**,文档明确标注为后续方向、给出指针,不静默丢弃。

**新对话与搜索**

30. 左栏内容顶部存在一个不预选项目的全局「新对话」入口,点击后导航进入既有新建对话流程。
31. 每个项目行可通过右键菜单“新对话”发起该项目下的新对话，效果等同全局入口但预选该项目工作目录。
32. 左栏内容顶部存在一个「搜索」入口(含快捷键提示),点击或按快捷键唤出既有搜索呈现;搜索至少支持按对话名称过滤并定位候选。
33. 从搜索选中一个候选对话后,搜索关闭、树滚动到该对话并选中、内容按 §2·G 联动规则呈现。

**点击联动**

34. 点击一个根对话节点后,中区切换焦点到该对话(发起侧完整;中区自身能否渲染出真实消息流由 conversation-page 独立验收,不在本需求验收范围)。
35. 点击一个 subagent 节点后,**发起侧**——树内触发跳转到右侧、且中区当前显示的根对话不受影响、不切换——完整可验;**承接侧**(右侧最终呈现的具体页签形态)不超出 `2026-07-07-right-sidebar` 既有 deferred 声明范围,不在本需求验收范围内。
36. 树的选中态准确反映「中区当前呈现的是哪个根对话」;选中 subagent 不清除其所属根对话行的选中标识。

**主机切换器**

37. 左栏内容最顶部存在主机切换胶囊,显示当前主机名与三态连接点(在线 / 连接中 / 离线)。
38. 点击胶囊展开下拉,列出全部已配置主机(各自连接点 + 名称),当前项有明确标识;末尾有「添加主机…」入口。
39. 点击下拉内一台在线主机后,整个工作区(树 + 中区 + 右侧面板)经过切换中过场后重载为该主机数据。
40. 点击下拉内一台离线主机,**不直接切换**,而是原地对该主机发起重连尝试;重连成功后该行状态转为在线,此时可再次点击真正切换过去。
41. 仅有一台主机时,下拉只列出该主机与「添加主机…」。
42. 点击「添加主机…」进入既有添加主机流程,完成后新主机出现在列表中并可选中。

**全态**

43. 无任何项目和对话时,「项目」分组只显示新增入口、「对话」分组显示「暂无对话」提示;新对话 / 搜索 / 主机切换器三个入口在此空态下仍可正常操作,不是死胡同。
44. 首次进入或切主机期间,树位置显示骨架占位行,完成后换入真实内容。
45. 拉取项目或对话列表失败时,树区域出现错误提示与「重试」操作;点重试重新拉取。
46. 当前主机断连时,主机切换器状态点转为离线、树区域出现离线提示条;树内容冻结为断连前最后已知状态且操作项置灰(只读);点「重新连接」发起退避重试,恢复后树按最新数据刷新。
47. 浅色与深色两套主题均正确呈现,选中态与 hover 态均为柔和灰阶(两档,读壳的 codePilot 主题来源),不使用黑底白字 / 强调色做底。

**边界与范围声明**

48. 文档明确本需求**桌面 only**,移动 / 紧凑态标注 deferred、沿用壳既定安排。
49. 文档明确不重定义壳的展开 / 收起 / 宽度 / 拖拽 / 记忆 / 设置入口位置——这些行为完全沿用 `2026-06-28-shell` 与 `2026-06-27-codepilot-layout`。
50. 文档明确不重画「新建对话」流程内部与「搜索 / 命令面板」本身——两者均为既有独立能力,本需求只接入口。
51. 文档明确 provider 内部 subagent 的深层可见性属 `2026-06-27-subagent-native-tree` 独立范围,不在本需求验收内;本需求的树结构对其保持开放、不需预先改动。
52. 文档明确本需求不改协议 / RPC / `server_info.features.*`,能力门只做「依赖某能力」的 WHAT 级表述、不点名。
53. 文档明确 2026-07-28 两次修正覆盖此前项目 / 根对话两行、subagent 状态点 / 后代角标及 hover 行尾动作定义；保留展开箭头、缩进、内联重命名、closed 语义与拖拽边界，根对话状态判断与视觉另行设计。

**屏对齐**

54. sCT1–sCT7 共 7 屏在 ui.html 均有对应锚点,requirement 每状态 ↔ 屏 1:1,注解块覆盖布局 / 状态 / 右键菜单 / 点击效果四维度。

1. **离线主机行点击语义修正**:现状(当前左栏)离线主机行点击与在线行一样直接尝试切换;本需求采用 `2026-06-25-home-shell` 已验证过的设计——改为「原地触发重连、不直接切走」(见 sCT5)。这是相对现状的一处行为修正,请董事长确认是否认可。若不认可,退回现状「点击即尝试切换」亦可,不影响其余范围。
2. **subagent 专属右键菜单(跳到父对话 / 剥离为独立对话)是否本轮纳入**:现状对话与 subagent 行共用同一套右键菜单,没有专属项;「剥离」能力已在对话页的相关区域有出口,不会因树内暂缺而阻塞用户。推荐:**本轮不纳入**,归后续(见 §5)。请董事长确认,或要求提前纳入。
3. **主机切换器采用完整闭环 vs 占位**:本需求选择复用现状已真实工作的主机切换能力(胶囊 + 下拉 + 切换 + 添加主机),仅将其从当前的「左栏底部(临时位置)」挪到「左栏内容顶部」。推荐:**采用完整闭环**(成本低、无需重新设计,只是挪位置)。请董事长确认是否认可挪动位置,或希望暂缓挪动、维持现状位置直到统一顶栏未来长出专属槽位为止。
4. **搜索入口的落点**:搜索点击后唤出的是现有的、跨主机 / 跨内容(标题 + 消息内容 + 目录)的搜索呈现,并非本需求新造一个只按名称过滤的轻量搜索框。推荐:**维持现状搜索呈现,不新造**,本需求只保证「至少按名称能查到」这个最低期望被满足(现状已满足)。请董事长确认这个「接入口、不重造」的处理是否符合预期,或希望本轮就单独做一个更轻量的名称过滤框(与现状搜索呈现二选一并存)。
5. **状态点视觉为重新设计,非现状复用(请特别过目视觉效果)**:现有代码曾经尝试过树内状态图标,但因反馈「达不到想要的效果」被整体移除;节点的运行状态数据(五值状态枚举 + 「需关注」标志)本身真实存在,只是当前没有对应的树内视觉。本轮据此重新设计一套五态状态点(运行中绿脉冲 / 待输入或需关注醒目色 / 空闲灰 / 出错红 / 初始化中过渡色,见 sCT2 图例)。请董事长闸 1 **特别过目视觉效果**(而非仅审 WHAT 文字描述),确认这版重新设计是否解决了此前「达不到想要的效果」的问题;若仍不理想,请指出具体不满意点以便下一轮调整。
6. **hover 与选中改两档灰阶**:现状 hover 与选中共用同一档淡灰,本轮改为两档——hover 较浅、选中较深一档(见 §2·C / sCT3)。这是相对现状的**有意修正**,理由是对齐 codePilot 设计系统下同类行 / 页签控件(目录树行、右侧栏页签)的既有两档灰阶惯例,让全产品在「悬浮」与「选中」的视觉区分上保持一致。推荐:**采纳**。请董事长确认。
7. **「最近说话相对时间」的数据依赖(2026-07-23 二次修正,地位由「可选后缀」升级为「阻塞性」)**:上一轮(视觉修正)此项还只是空闲态的一个可选后缀,不阻塞验收;本轮(信息架构修正)把它挪到对话(根)行**第一行行尾、每一行都要展示**,取代原有的子对话计数角标——地位从「锦上添花」变成「核心信息」,不显示等于这一行的信息架构缺了一块。数据现状不变:对话树自己的节点数据模型目前只带「创建时间」,不带「最近一次活跃 / 更新」时间;应用内其它地方(如工作区详情)确实已经在用类似「最近变更时间」的概念,理论上可能有可复用的数据来源,但本对话树模块尚未接入,能否接入、接入成本多高,requirement 层无法断定。**与上一轮不同,本轮要求架构给出的结论必须在本轮就明确**(不能像上一轮那样延后为不确定的「后续待办」)——若架构确认这项数据本轮拿不到,意味着对话(根)行第一行行尾这个位置暂时留白或需要产品重新决定放什么,请架构给出明确结论以便决策,不要默认「反正上一轮已经这么写过」就沿用旧结论。
8. **CLI 类型标签(provider)的数据依赖(2026-07-23 新增,待架构确认)**:董事长初步判断对话树自己的节点数据模型目前没有 provider 字段,认为这跟「最近说话时间」是同一类缺口——协议层的原始数据大概率带着 provider 信息,只是没有被这一层模块接住,但这只是初步判断,不是确认过的结论。**我独立重新核实过一遍(读了该模块的数据模型与解码逻辑,不是照抄这一判断)**:确认属实——协议层的原始快照数据确实带 provider 信息,但对话树自己的节点数据模型目前没有解出这个字段,不能直接拿来用。能否把它接进来、接入成本多高,需架构阶段确认。**本需求的强制要求只是标签行本身必须存在、且至少含 CLI 类型标签的位置**(见 §6 验收标准第 12 条);若架构确认本轮无法接入 provider 数据,请给出明确结论——是先只显示当前状态标签、CLI 类型标签延后,还是有其它更低成本的替代方案,由总监 / 董事长依据架构结论再定,不在此处预先假设。
9. **子对话(subagent)计数信息去留的可用性顾虑(2026-07-23 新增 · 董事长已确认收口)**:董事长原话是「不显示子对话的个数」,没有提到挪到别处;本次修正按字面理解执行为**直接去掉**,不做「移到别的位置」处理,行内不再有任何位置显示这个数字(见 §2·A、§2·B、§6)。这条信息此前是用户判断「这个对话底下挂了几个 subagent」的**唯一**途径,完全去掉是否构成可用性倒退,曾如实标为顾虑、未替董事长做取舍。**【已收口】董事长确认:维持「彻底去掉,不做任何补偿」**——理由:运行中的 subagent 本来就会把状态贡献给父对话的聚合状态,「有 subagent 需要关注」这个信号不会因为去掉计数而消失,只是丢了「具体几个」这个数字,该数字本身价值不大。§2·A、§2·B、§6 当前的正式内容(彻底去掉、不挪位置)即为最终定义,不再是待验证的基线。
10. **历史问题：根对话与 subagent 状态视觉不统一(2026-07-23，已被 2026-07-28 覆盖)**:最新决定是根对话与 subagent 均不显示状态点或状态标签，统一为纯标题；状态判断与视觉整体延后，因此该问题不再存在于当前 UI。
11. **项目行分支 / diff 常显于行内的渲染 / 滚动性能代价(2026-07-23 新增,待架构确认)**:项目行第二行(当前分支 + diff 统计)所需的数据本身不是新缺口——工作区详情模型已有对应字段(可空的分支、可空的增删统计),现有的 hover 工作区卡片已经在用这两个字段、也已经处理了「无分支」的情况;这轮的性质更像是「把已经存在、原本只在 hover 时才计算 / 展示的信息,改成每个项目行常驻显示」。但常驻显示是否会给长列表的渲染或滚动带来额外性能代价(尤其项目数量多、diff 统计需要实时或准实时更新时),不归产品判断,需要架构阶段评估并给出结论;若代价过高,可能需要退让(比如降低刷新频率、或只在可视区域内计算),具体如何取舍由架构提出方案,本需求只要求「有分支时显示分支 + diff 统计、无分支时显示"暂无分支"」这个用户可见效果,不预设实现路径。
12. **项目行第二行"当前分支"对应哪个目录(2026-07-23 UI 定稿阶段发现,待产品 / 架构确认)**:§2·A「分组」已经写明「同一项目下可能同时有主目录与若干工作树,其上的对话都归在同一项目节点下」——项目节点本身就是多个目录的聚合。但项目行第二行只有一处位置显示「当前分支」(见 §2·A、§2·B),主目录和各工作树完全可能处在不同分支上,本文档此前没有显式定义这一处「当前分支」具体取哪个目录的分支。UI 设计师画稿时按**项目主目录自身的分支**处理(各工作树自己的分支仍由其对应对话行的 hover 工作区卡片单独展示,见 §2·C),但这只是绘稿时为了能往下画而做的假设,不是本需求已经拍板的定义,**不应由 UI 自行悄悄定案**。**这不是我能替产品 / 架构做的取舍,如实标出**:是否就按「项目主目录分支」这个假设定稿?主目录本身不存在或未绑定本地目录时这一行怎么处理?多个工作树分支不一致时,是否需要在项目行给出「多分支」一类的提示而不是默默只显示主目录一个?请产品(可能是我下一轮据此定稿)与架构(数据是否已能区分「项目下具体是哪个目录」)共同确认口径,本条目前不裁定。
